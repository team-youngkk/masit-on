# 맛잇온 프로젝트 범위

## 1. 문서 목적

이 문서는 맛잇온의 MVP 기능 범위와 단계별 배포 경계를 정의하는 기준 문서다. 이후 작성하는 기능 요구사항, PRD, Role, API 명세, ADR은 이 문서의 포함 범위와 제외 범위를 따라야 하며, 별도의 범위 변경 절차 없이 기능을 추가하거나 확장해서는 안 된다.

맛잇온은 유튜버가 실제로 방문한 맛집 정보를 지역, 음식 카테고리, 유튜버 기준으로 정리하여 사용자가 원하는 맛집을 쉽게 탐색할 수 있도록 제공하는 웹 서비스다. MVP의 목표는 계정이나 개인화 기능 없이 핵심 맛집 탐색 흐름과 관리자의 검증 데이터 등록 흐름을 검증하는 것이다.

## 2. 범위 결정 원칙

- MVP는 맛집 목록 탐색, 맛집 상세 확인, 방문 유튜버 및 근거 영상 확인, 관리자 데이터 등록에 집중한다.
- 일반 사용자는 계정 없이 서비스를 이용하며, 서비스는 사용자별 데이터를 저장하지 않는다.
- 일반 사용자는 맛집, 유튜버, 영상 및 방문 관계를 직접 등록하거나 수정하지 않는다.
- 서비스에 노출하는 데이터는 관리자가 검증하여 등록한다.
- MVP의 서비스 지역은 서울특별시로 한정한다.
- 맛집과 유튜버의 방문 관계는 실제 방문을 확인할 수 있는 YouTube 영상을 근거로 등록한다.
- 영상 연결 정보가 없는 맛집도 목록과 상세에서 기본 정보를 조회할 수 있어야 한다.
- YouTube 영상 원본은 저장하거나 재배포하지 않고, 원본 링크와 서비스 제공에 필요한 메타데이터만 저장한다.
- 카카오 장소 정보는 맛집 위치와 기본 연락 정보를 확인하는 용도로 사용하되, 지도 기반 탐색으로 확장하지 않는다.
- 서비스는 웹으로 제공하며 모바일 브라우저에서도 핵심 탐색 흐름을 사용할 수 있도록 고려한다.
- MVP 구현은 로컬 Docker 환경에서 전체 사용자 흐름을 통합 검증하는 단계다.
- 초기 운영 배포(M2)는 다음 확장 단계 착수 전에 최초 운영 환경으로 수행하고, 이후 확장에서는 필요한 인프라 변경을 각 단계에 함께 반영한다. ALB·Blue-Green 무중단 배포는 3차 확장 이후 배포 고도화 단계에서 도입을 검토한다. 착수 시점은 합의했으나 7절 3·4항 영향 검토가 남아 있어 확정 범위가 아니다([ADR-DEPLOY-002](../07-adr/platform/deploy-002-validation-deployment-before-expansion.md) 3.1절).
- 구현 방식, 데이터 구조 또는 화면 구성이 본 문서에 명시되지 않은 경우 이를 새로운 기능의 근거로 해석하지 않는다.
- 이후 확장 기능 중 범위 변경 절차를 완료하지 않은 후보는 현재 설계 및 구현 범위에 포함하지 않는다. 승인된 확장은 해당 단계 절의 포함·제외 경계를 따른다.

## 3. MVP 포함 범위

### 3.1 맛집 탐색

#### 맛집 목록 조회

- 목적: 사용자가 서비스에 등록된 맛집을 탐색할 수 있는 시작점을 제공한다.
- 사용 주체: 일반 사용자
- 포함 범위:
  - 관리자가 등록한 맛집을 목록으로 조회한다.
  - 목록에 맛집 이름, 자치구, 대표 음식 카테고리와 방문이 확인된 YouTube 채널명을 표시한다.
  - 영상 연결 정보가 없는 맛집도 목록에서 기본 정보를 조회할 수 있다.
  - 목록은 페이지 단위로 조회하며, 사용자는 이전·다음 또는 특정 페이지로 이동할 수 있다.
  - 기본 페이지 크기는 20개이며, 10개·20개·50개 중 하나를 선택할 수 있다.
  - 검색 또는 필터 조건이 변경되면 첫 페이지부터 결과를 제공한다.
  - 웹과 모바일 브라우저에서 목록 탐색 흐름을 사용할 수 있다.
- 제외 범위:
  - 인기순, 추천순 등 통계 또는 추천에 기반한 정렬
  - 지도 형태의 목록 표시
  - 사용자별 목록 구성이나 개인화
  - 무한 스크롤과 자동 추가 로딩
  - Internet Explorer, 오래된 브라우저와 앱 내부 브라우저에 대한 공식 지원

#### 맛집 이름 검색

- 목적: 사용자가 알고 있는 맛집을 이름으로 찾을 수 있도록 한다.
- 사용 주체: 일반 사용자
- 포함 범위:
  - 관리자가 등록한 맛집 이름만을 검색 대상으로 한다.
  - 맛집 이름에 검색어가 포함되면 결과에 표시한다.
  - 검색어 앞뒤 공백을 무시하고 영문 대소문자를 구분하지 않는다.
  - 검색어가 비어 있으면 이름 조건 없이 목록을 조회한다.
  - 검색 결과를 맛집 목록으로 제공한다.
- 제외 범위:
  - 자연어 검색
  - 오타 자동 교정
  - 검색어 자동 완성 또는 추천
  - 검색 기록 저장
  - 메뉴명, 지역명, YouTube 채널명, 영상 제목을 대상으로 하는 통합 검색
  - 초성, 유사어 또는 별칭 검색

#### 지역별 필터

- 목적: 사용자가 원하는 지역에 속한 맛집으로 탐색 범위를 좁힐 수 있도록 한다.
- 사용 주체: 일반 사용자
- 포함 범위:
  - 서비스 지역은 서울특별시로 한정한다.
  - 서울특별시 자치구를 기준으로 목록을 필터링한다.
  - 필터 결과를 맛집 목록으로 제공한다.
- 제외 범위:
  - 서울특별시 외 지역의 맛집 탐색
  - 동·읍·면 단위 필터
  - 현재 위치 기반 필터링
  - 거리 계산 및 반경 검색
  - 지도 이동 영역 기반 검색

#### 유튜버별 필터

- 목적: 사용자가 특정 유튜버의 실제 방문이 확인된 맛집을 찾을 수 있도록 한다.
- 사용 주체: 일반 사용자
- 포함 범위:
  - 일반 사용자가 필터 값을 선택할 수 있도록 공개 유튜버의 식별자와 현재 YouTube 채널명으로 구성된 최소 선택 목록을 제공한다.
  - 등록된 방문 관계를 기준으로 특정 유튜버가 방문한 맛집을 필터링한다.
  - 필터 결과를 맛집 목록으로 제공한다.
- 제외 범위:
  - 유튜버 상세 페이지
  - 유튜버 선택 목록의 검색·페이지네이션·프로필·구독자 정보
  - 구독자 수, 인기도 또는 성향에 따른 필터링과 정렬
  - 방문 영상이 확인되지 않은 추정 관계의 노출

#### 음식 카테고리별 필터

- 목적: 사용자가 원하는 음식 종류에 속한 맛집으로 탐색 범위를 좁힐 수 있도록 한다.
- 사용 주체: 일반 사용자
- 포함 범위:
  - 관리자가 맛집에 등록한 음식 카테고리를 기준으로 목록을 필터링한다.
  - 각 맛집에는 관리자가 대표 음식 카테고리 1개를 반드시 지정한다.
  - 대표 음식 카테고리는 한식, 중식, 일식, 양식, 동남아 음식, 인도·남아시아 음식, 분식, 카페·디저트, 술집·주점, 기타 중 하나를 사용한다.
  - 기타는 기존 카테고리에 명확히 해당하지 않을 때만 사용하며, 관리자는 실제 음식 종류를 확인할 수 있도록 기록한다.
  - 기타를 선택하면 별도 구체 음식 종류를 저장하지 않고 대표 카테고리 `기타`만 기록한다.
  - 새로운 카테고리는 팀 합의와 범위 변경 절차를 거친 뒤 추가한다.
  - 향후 다중 카테고리를 지원하더라도 대표 카테고리는 유지한다.
  - 필터 결과를 맛집 목록으로 제공한다.
- 제외 범위:
  - 맛집별 복수 카테고리 지정
  - 관리자의 임의 카테고리 생성
  - AI를 이용한 카테고리 자동 분류
  - 사용자별 선호 카테고리 추천
  - 테마, 분위기, 가격대 등 확정되지 않은 추가 분류 기준

#### 검색 및 필터 조합

- 목적: 사용자가 여러 탐색 조건을 함께 적용하여 원하는 맛집을 찾을 수 있도록 한다.
- 사용 주체: 일반 사용자
- 포함 범위:
  - 맛집 이름 검색과 지역, 유튜버, 음식 카테고리 필터를 동시에 사용할 수 있다.
  - 서로 다른 검색·필터 조건은 모두 만족해야 하는 방식으로 적용한다.
  - 각 필터에서는 한 번에 하나의 값만 선택할 수 있다.
  - 조건에 맞는 맛집이 없으면 빈 결과를 표시한다.
- 제외 범위:
  - 같은 종류의 필터에서 여러 값 동시 선택
  - 일부 조건만 만족하는 결과의 혼합 제공

### 3.2 맛집 상세 조회

#### 맛집 상세 조회

- 목적: 사용자가 선택한 맛집의 기본 정보와 방문 근거 정보를 한곳에서 확인할 수 있도록 한다.
- 사용 주체: 일반 사용자
- 포함 범위:
  - 목록 또는 검색·필터 결과에서 선택한 맛집의 이름, 대표 음식 카테고리, 전체 도로명주소와 전화번호를 조회한다.
  - 도로명주소에는 필요한 경우 건물명, 층 또는 호수 등 상세 위치를 함께 표시한다.
  - 카카오 장소 페이지로 이동할 수 있는 링크를 제공한다.
  - 해당 맛집과 연결된 방문 유튜버 및 관련 영상 정보를 함께 확인할 수 있다.
  - 영상 연결 정보가 없어도 맛집 기본 정보는 조회할 수 있다.
- 제외 범위:
  - 지도 표시, 길찾기, 현재 위치로부터의 거리 계산
  - 지번주소 표시와 주소 검색·자동 완성·좌표 변환
  - 예약 및 결제
  - 찜하기, 최근 본 맛집, 방문 기록 등 사용자별 기능
  - 사용자 리뷰, 평점, 제보 및 신고

### 3.3 유튜버 및 영상 정보 확인

#### 맛집을 방문한 유튜버 정보 확인

- 목적: 사용자가 해당 맛집을 실제로 방문한 유튜버를 확인할 수 있도록 한다.
- 사용 주체: 일반 사용자
- 포함 범위:
  - 관리자 검증을 거쳐 등록된 방문 관계에 포함된 YouTube 채널명을 맛집 목록과 상세에서 확인한다.
  - 맛집 상세에서 해당 유튜버의 YouTube 채널 링크를 확인한다.
  - 유튜버와 맛집의 관계는 실제 방문을 확인할 수 있는 영상이 있는 경우에만 등록한다.
- 제외 범위:
  - 별도의 유튜버 상세 페이지
  - 프로필 이미지, 채널 소개, 구독자 수와 전체 영상 목록
  - 유튜버 구독, 팔로우 또는 알림
  - 방문 여부의 자동 판정

#### 관련 YouTube 영상 링크 확인

- 목적: 사용자가 맛집 방문 관계의 근거가 되는 원본 영상을 확인할 수 있도록 한다.
- 사용 주체: 일반 사용자
- 포함 범위:
  - 맛집 상세에서 방문 관계에 연결된 영상 제목, 썸네일, YouTube 채널명과 원본 링크를 확인한다.
  - 원본 링크를 통해 YouTube 영상으로 이동할 수 있다.
- 제외 범위:
  - 영상 원본 저장 또는 재배포
  - 영상 내용 자동 요약·분석·추출
  - 업로드 날짜, 조회 수, 좋아요 수, 영상 설명과 맛집 등장 시점
  - 별도의 영상 상세 페이지나 영상 탐색 기능

### 3.4 관리자 데이터 등록

#### 관리자 접근

- 목적: 검증된 관리자만 데이터 등록 기능을 사용할 수 있도록 한다.
- 사용 주체: 관리자
- 포함 범위:
  - 관리자 전용 로그인을 제공한다.
  - 관리자 계정은 서비스에서 가입하지 않고 사전에 발급한다.
  - 모든 관리자는 동일한 데이터 등록 권한을 가진다.
  - 인증되지 않은 사용자는 관리자 등록 기능에 접근할 수 없다.
- 제외 범위:
  - 관리자 회원가입
  - 관리자 등급 및 기능별 권한 세분화
  - 관리자 계정 관리 화면
  - 일반 사용자 로그인

#### 맛집 정보 등록

- 목적: 검증된 맛집 기본 정보를 사용자 탐색 대상으로 제공한다.
- 사용 주체: 관리자
- 포함 범위:
  - 관리자가 검증한 맛집 정보를 등록한다.
  - 맛집은 카카오에서 동일한 장소와 연결하고, 관리자가 장소 일치 여부를 확인한다.
  - 맛집마다 사전 정의된 대표 음식 카테고리 1개를 지정한다.
  - 대표 음식 카테고리는 맛집의 주된 메뉴와 영업 정체성을 가장 잘 나타내는 값으로 지정한다.
  - 등록된 맛집은 사용자 목록, 검색, 필터 및 상세 조회에 반영된다.
  - 영상 연결 정보가 없는 맛집도 등록할 수 있다.
- 제외 범위:
  - 일반 사용자의 등록 또는 수정
  - AI 또는 외부 데이터 수집을 통한 자동 등록
  - 맛집 정보 수정·삭제·승인 상태 관리 등 등록 외 관리 기능

#### 유튜버 정보 등록

- 목적: 맛집 방문 관계를 구성하는 검증된 유튜버 정보를 관리한다.
- 사용 주체: 관리자
- 포함 범위:
  - YouTube 채널을 유튜버 정보의 고유한 관리 단위로 사용한다.
  - 관리자가 채널 링크를 입력하면 YouTube API로 채널 존재와 현재 채널명을 조회하고, 관리자가 확인한 결과를 등록한다.
  - 등록된 유튜버는 방문 관계 및 사용자 조회 기능에서 사용할 수 있다.
- 제외 범위:
  - 일반 사용자의 등록 또는 수정
  - MVP 관리자 확인 없는 자동 등록 또는 자동 주기 동기화
  - 유튜버 정보 수정·삭제·승인 상태 관리 등 등록 외 관리 기능

#### 영상 정보 등록

- 목적: 맛집 방문 관계를 입증하는 YouTube 영상 정보를 관리한다.
- 사용 주체: 관리자
- 포함 범위:
  - 관리자가 원본 링크를 입력하면 YouTube API로 영상 존재, 제목, 썸네일과 게시 채널을 조회하고, 관리자가 실제 방문 근거와 결과를 확인해 등록한다.
  - 등록된 영상은 방문 관계를 통해 사용자 조회 기능에 반영된다.
- 제외 범위:
  - 영상 원본 업로드, 저장 또는 재배포
  - 관리자 확인 없는 영상 메타데이터 자동 등록과 자동 주기 동기화
  - AI를 이용한 영상 분석 및 정보 추출
  - 영상 정보 수정·삭제·승인 상태 관리 등 등록 외 관리 기능

#### 맛집·유튜버·영상 방문 관계 등록

- 목적: 실제 방문 근거를 바탕으로 맛집, 유튜버, 영상을 연결한다.
- 사용 주체: 관리자
- 포함 범위:
  - 관리자가 특정 영상에서 유튜버의 실제 맛집 방문을 확인한 뒤 방문 관계를 등록한다.
  - 방문 관계는 맛집, 유튜버 및 근거 영상과 연결한다.
  - 등록된 관계는 유튜버별 필터와 맛집 상세의 유튜버·영상 정보에 반영된다.
- 제외 범위:
  - 영상이 없는 방문 관계 등록
  - AI에 의한 방문 관계 자동 생성
  - 일반 사용자의 관계 등록, 수정 또는 검증 참여
  - 방문 관계 수정·삭제·승인 상태 관리 등 등록 외 관리 기능

#### 중복 등록 방지

- 목적: 같은 맛집, 유튜버, 영상 또는 방문 관계가 중복 등록되는 것을 방지한다.
- 사용 주체: 관리자
- 포함 범위:
  - 카카오에서 동일한 장소로 확인되는 맛집은 중복으로 판단한다.
  - 동일한 YouTube 채널은 중복 유튜버로 판단한다.
  - 동일한 YouTube 영상은 중복 영상으로 판단한다.
  - 동일한 맛집·유튜버·영상 조합은 중복 방문 관계로 판단한다.
  - 상호명이 같더라도 카카오에서 서로 다른 지점이면 별도 맛집으로 등록할 수 있다.
  - 중복으로 확인되면 새로 등록하지 않고 기존 정보를 사용한다.
  - 동일 여부를 판단할 수 없으면 등록을 보류하고 관리자가 확인한다.
- 제외 범위:
  - 이름만을 기준으로 한 자동 병합
  - AI를 이용한 중복 판단

## 4. MVP 제외 범위

### 4.1 사용자 및 개인화 기능

- 제외되는 기능: 회원가입 및 로그인, 찜하기, 최근 본 맛집, 그 밖의 사용자별 데이터 저장 기능
- 상태: MVP 제외
- 제외 이유: 계정과 개인화 데이터 없이도 핵심 맛집 탐색 가치를 검증할 수 있으며, 해당 기능은 별도의 사용자 식별과 데이터 관리 범위를 추가한다.
- 향후 포함 가능 시점: 회원가입 및 로그인, 찜하기, 최근 본 맛집은 1차 확장에서 검토한다.
- 현재 설계 영향:
  - 일반 사용자 계정과 사용자별 데이터는 현재 설계 범위에 포함하지 않는다.
  - 일반 사용자에게 인증을 요구하는 기능은 작성하지 않는다.
  - 개인화 기능을 위한 선행 구조를 현재 MVP에 미리 구현하지 않는다.
  - 관리자 전용 인증은 일반 사용자 계정 기능에 포함되는 것으로 보지 않는다.

### 4.2 지도 및 위치 기반 기능

- 제외되는 기능: 서비스 내부 지도 표시, 지도 기반 탐색, 현재 위치 사용, 거리·반경 검색, 길찾기, 지도 SDK를 이용한 표시
- 상태: MVP 제외
- 제외 이유: 목록·검색·필터로 핵심 탐색 흐름을 검증할 수 있고, 지도 및 위치 처리는 별도의 외부 연동과 위치 기반 설계를 요구한다.
- 향후 포함 가능 시점: 지도 기반 탐색은 1차 확장에서 검토한다.
- 현재 설계 영향:
  - 지도 SDK 또는 위치 권한 처리를 현재 설계 범위에 포함하지 않는다.
  - 거리 계산, 좌표 기반 검색 및 경로 탐색을 위한 기능을 작성하지 않는다.
  - 도로명주소, 전화번호 및 카카오 장소 링크 제공은 지도 기반 탐색에 포함되는 것으로 보지 않는다.

### 4.3 추천 및 큐레이션 기능

- 제외되는 기능: 컬렉션, 인기 맛집, 큐레이션, 개인화 추천, 추천 알고리즘, 동선 및 코스 추천
- 상태: MVP 제외
- 제외 이유: 핵심 탐색에 필수적이지 않고, 사용자 행동 데이터·통계 집계·편집 운영 또는 경로 계산 등 별도 범위를 요구한다.
- 향후 포함 가능 시점: 컬렉션, 인기 맛집, 큐레이션은 2차 확장에서, 동선 및 코스 추천은 3차 확장에서 검토한다.
- 현재 단계: 컬렉션·인기 맛집·관리자 큐레이션의 2차 확장 초기 범위는 2026-08-03 승인했으며 [5.2절](#52-2차-확장)을 따른다. 개인화 추천·추천 알고리즘·동선 및 코스 추천은 승인 범위가 아니다.
- 현재 설계 영향:
  - 추천 점수, 인기 집계, 컬렉션 및 코스용 데이터 모델을 현재 설계 범위에 포함하지 않는다.
  - 일반 목록이나 필터 결과를 추천 또는 인기 콘텐츠로 표현하지 않는다.

### 4.4 사용자 참여 기능

- 제외되는 기능: 사용자의 맛집·유튜버·영상 등록 및 수정, 사용자 제보 및 신고, 알림
- 상태: MVP 제외
- 제외 이유: MVP는 관리자가 검증한 데이터만 제공하며, 사용자 참여 기능은 계정, 검수, 처리 상태 및 운영 절차를 추가로 요구한다.
- 향후 포함 가능 시점: 사용자 제보 및 신고, 알림은 2차 확장에서 검토한다.
- 현재 단계: 사용자 제보·신고와 서비스 내 사용자 알림의 2차 확장 초기 범위는 2026-08-03 승인했으며 [5.2절](#52-2차-확장)을 따른다. 사용자의 직접 등록·수정과 외부 푸시 알림은 승인 범위가 아니다.
- 현재 설계 영향:
  - 일반 사용자의 데이터 생성·수정 권한을 설계하지 않는다.
  - 제보·신고 처리 흐름과 실시간 알림 또는 복잡한 비동기 처리를 현재 설계 범위에 포함하지 않는다.

### 4.5 AI 및 자동화 기능

- 제외되는 기능: 자연어 검색, AI 기반 영상 정보 추출, AI를 이용한 자동 데이터 수집·분석·분류
- 상태: MVP 제외
- 제외 이유: 관리자의 수동 등록과 검증으로 MVP 운영이 가능하며, AI 기능은 별도의 모델, 처리 흐름, 품질 검증 및 운영 기준을 요구한다.
- 향후 포함 가능 시점: 자연어 검색과 AI 기반 영상 정보 추출은 3차 확장에서 검토한다.
- 현재 설계 영향:
  - AI 처리 결과, 검수 상태 및 자동 추출 작업을 위한 데이터 모델이나 인프라를 현재 설계 범위에 포함하지 않는다.
  - MVP 관리자 등록 흐름은 YouTube API 조회 결과를 관리자가 확인해 저장하며, MVP에서는 관리자 확인 없는 자동 등록과 자동 주기 동기화를 전제로 설계하지 않는다. 3차 AI 등록은 별도 자동 검증 계약을 따른다.

### 4.6 예약·결제 및 외부 연동 기능

- 제외되는 기능: 예약, 결제, 상업적 거래, 지도·위치·AI·자동 데이터 수집을 위한 복잡한 외부 서비스 연동
- 상태: MVP 제외
- 제외 이유: 핵심 맛집 탐색 가치 검증에 필요하지 않으며, 거래·정산·보안·실패 처리 또는 외부 서비스 종속성을 크게 추가한다.
- 향후 포함 가능 시점: 예약과 결제는 현재 확장 단계에도 포함되지 않은 미정 범위이며, 별도 제안과 범위 변경 절차를 거쳐야 한다. 나머지 외부 연동은 해당 확장 기능의 검토 시점에 함께 판단한다.
- 현재 설계 영향:
  - 예약, 주문, 결제 및 거래 상태를 현재 설계 범위에 포함하지 않는다.
  - MVP에 포함된 YouTube 원본·채널 링크와 카카오 장소 정보·링크 제공 외에 외부 서비스와의 복잡한 연동을 전제로 설계하지 않는다.

## 5. MVP 이후 확장 범위

이 절은 MVP 이후 기능의 단계와 현재 승인 상태를 분류한다. 1차 확장은 구현됐고, 2차 확장은 2026-08-03 초기 범위를 승인했으며, 3차 확장은 2026-08-10 초기 범위를 승인했다. 승인된 범위도 요구사항·PRD·API·데이터·ADR 계약과 구현 Task를 순서대로 작성해야 하며 범위 승인만으로 구현 완료를 뜻하지 않는다.

### 5.1 1차 확장

- 회원가입 및 로그인
- 찜하기
- 최근 본 맛집
- 지도 기반 탐색
- 유튜버 상세 페이지

### 5.2 2차 확장

2026-08-03 범위 변경 절차에 따라 다음 기능의 초기 범위를 승인했다. 이 절은 2차 확장의 최상위 범위 계약이며, 세부 요구사항·PRD·API·데이터·ADR은 이 경계를 좁힐 수 있지만 별도 범위 변경 승인 없이 넓힐 수 없다. 구현 Task의 사전 문서화·담당자 배정은 가능하지만 실제 구현 착수는 [2차 확장 선행 상태 검토](../08-planning/second-expansion-baseline-review.md)의 착수 게이트와 각 기능의 선행 조건을 모두 충족한 뒤 진행한다.

#### 5.2.1 개인 컬렉션

| 승인 항목 | 결정 |
|---|---|
| 목적과 사용자 가치 | 회원이 다시 방문하려는 공개 맛집을 목적별 비공개 폴더로 나누어 재탐색할 수 있게 한다. 1차 확장의 단일 찜 관계와 달리 이름을 가진 여러 목록을 제공한다. |
| 포함 범위 | 회원 본인의 생성·이름 변경·삭제·조회, 공개·활성 맛집 추가·제거, 같은 맛집의 여러 컬렉션 포함, 컬렉션 최근 수정순·항목 추가 최신순, 회원당 20개·컬렉션당 맛집 100개 상한을 포함한다. 같은 컬렉션 안의 같은 맛집은 한 번만 존재한다. |
| 제외 범위 | 공개·링크 공유, 검색 노출, 공동 편집, 팔로우, 메모·태그·대표 이미지, 직접 순서 편집, 관리자 큐레이션 전환을 제외한다. |
| 선행 기능 | 1차 확장의 회원 인증, 맛집 공개·생명주기 판정과 회원 탈퇴 정리가 선행한다. 비공개·삭제 맛집은 개인 목록에서 숨긴다. |
| 개인정보 영향 | 회원 식별자와 컬렉션·맛집 포함 관계를 사용자별 데이터로 저장한다. 본인만 접근하며 회원 탈퇴 시 컬렉션과 포함 관계를 삭제한다. 공개 공유를 제공하지 않아 다른 회원에게 소유자나 목록을 노출하지 않는다. |
| 운영자 작업량 | 일상적인 콘텐츠 검수는 없다. 상한 초과, 소유권 침범, 탈퇴 정리 실패를 관측하고 장애 시 복구하는 작업만 추가된다. |
| 외부 연동 | 추가 외부 연동이 없다. 기존 PostgreSQL과 회원 인증 경계만 사용한다. |

| 외부 연동 | 추가 외부 연동이 없다. PostgreSQL 저장과 일반 HTTP 조회만 사용하며 FCM은 활성화하지 않는다. CloudWatch→Slack 운영 알림은 기존 운영 경계로 유지한다. |
| 비용과 일정 | 신규 유료 인프라 비용은 예상하지 않는다. 알림 저장·조회·읽음·보존 cleanup과 화면을 구현하는 중간 규모 작업이며 제보·신고 상태 계약 이후 착수한다. |
| 완료 조건 | 각 승인된 상태 전환과 알림이 원자적으로 한 번만 저장되고 본인만 조회·읽음 처리한다. 90일·200개 보존, 정확한 미읽음 수, `99+` 표시, 탈퇴 삭제와 외부 채널 미사용을 검증한다. |

#### 5.2.7 공통 승인 조건

- 제보와 신고는 별도 기능·모델·API로 유지하지만 회원별 하루 5건 제한과 상태 의미, 감사 필드, 사용자 알림 연결에서 공통 규칙을 사용한다.
- 개인 컬렉션과 관리자 큐레이션은 소유자·공개 범위·생명주기가 다르므로 데이터 모델·API·권한을 공유하지 않는다.
- 인기 맛집은 현재 찜 수 집계이며 큐레이션이나 추천의 동의어로 사용하지 않는다.
- 2차 확장은 신규 외부 유료 서비스 없이 시작한다. FCM, 파일 저장소, 메시지 브로커, 실시간 연결 또는 집계 전용 인프라가 필요해지면 비용·개인정보·운영 영향을 다시 검토하고 별도 범위 변경 및 ADR 승인을 거친다.
- 상대 작업량은 범위 비교를 위한 초기 평가다. 담당자, 병렬화, 정확한 일정과 완료 Task는 요구사항·PRD·API·데이터·ADR 추적성을 완성한 뒤 구현 계획에서 확정한다.

### 5.3 3차 확장

2026-08-10 범위 변경 절차에 따라 [3차 확장 범위와 용어 결정](../08-planning/third-expansion-scope-and-terminology.md)의 초기 범위를 승인했다. 이 절은 3차 확장의 최상위 범위 계약이며, 세부 요구사항·PRD·API·데이터·ADR은 이 경계를 좁힐 수 있지만 별도 범위 변경 승인 없이 넓힐 수 없다. 아래 표의 `승인`은 기능 범위와 주요 외부 연동·비용 상한을 승인한 상태를 뜻한다. 실제 API 자격 증명·quota 연결 확인과 운영 부하 측정은 구현·검증 게이트로 남긴다.

#### 5.3.1 자연어 검색

| 제외 범위 | 임베딩 의미 검색, RAG 답변, 자유 형식 챗봇, 관리자 미확정 AI 후보·원문 메뉴·분위기 정보의 자유 검색, 오타 자동 교정, 예약·결제 연결을 제외한다. |

| 비용 상한 | P1 신규 외부 호출 비용은 0원이다. 향후 LLM 도입은 별도 월 비용 상한·호출 제한·차단 동작 승인 후에만 가능하다. |
| 운영자 작업량 | 콘텐츠 검수는 없다. 해석 실패율·미지원 조건·응답 지연을 관측하고 조건 사전 변경이 필요할 때만 운영자가 갱신한다. |

| 품질 기준 | 지원 조건은 기존 필터와 같은 의미로 적용하고, 같은 조건 종류가 충돌하면 직접 지정 필터를 우선한다. 미지원 조건을 조용히 추정하지 않으며 AI가 새로운 사실이나 선정 이유를 생성하지 않는다. |
| 완료 조건 | 이름·지역·카테고리·유튜버의 단일·복합 조건, 직접 필터 충돌, 빈 결과, 미지원 조건, 해석 실패를 계약 테스트로 검증하고 원문·검색 이력이 저장되지 않음을 확인한다. |
| 결과 경계 | AI가 새로운 사실이나 선정 이유를 생성하지 않는다. 검색 결과는 기존 목록 의미를 따르며, 해석 불가·미지원 조건은 후속 API 계약의 실패 상태로 처리한다. |

#### 5.3.2 AI 기반 영상 정보 추출

| 승인 항목 | 결정 |
|---|---|
| 목적과 사용자 가치 | 관리자가 확인할 영상에서 맛집·메뉴·주소·방문·탐색용 태그 후보를 추출해 수동 등록 검수를 돕는다. |
| 포함 범위 | 관리자 화면의 신규 영상 추가와 관리자가 활성화한 YouTube 채널의 Webhook 신규 영상 감지, 두 경로의 비동기 추출, 자동 정규화·중복·근거·Kakao·YouTube·Visit 검증, 자동 정식 등록·공개와 필드·태그별 출처·감사 이력을 포함한다. |
| 제외 범위 | 영상·전체 자막 원본 자동 수집·저장·재배포, 자동 검증 없는 공개, 전체 채널 무차별 감시, 무제한 재처리와 공개 AI 요약을 제외한다. 자동 검증을 통과한 AI 기반 Restaurant·Creator·Video·Visit 생성·공개는 포함한다. |
| 선행 기능 | 관리자 인증, 기존 등록 명령의 원자성·중복 규칙, Kakao 장소 검증, YouTube 메타데이터 검증과 Visit 등록 규칙이 선행한다. Webhook은 명시적으로 활성화한 채널만 대상으로 하며, 공개 YouTube URL은 Google Gemini API의 영상 입력으로 사용하고 관리자 보완 텍스트를 fallback으로 둔다. |
| 개인정보 영향 | 원본 영상·자동 수집 전체 자막·전체 모델 응답을 애플리케이션에 저장하거나 공개하지 않는다. 관리자가 직접 입력한 보완 텍스트는 암호화된 임시 입력으로 작업 종료 후 24시간 이내 삭제하며, 후보와 근거 위치·해시만 장기 보존한다. Google Gemini Free Tier의 데이터 사용·보존 경계를 확인한 뒤에만 호출을 활성화한다. |
| 외부 API와 AI 모델 | 기존 Kakao·YouTube 검증과 Google Gemini API Free Tier의 `gemini-3.5-flash-lite`를 사용한다. Gemini Developer API의 global endpoint를 사용하고 자동 failover·File API·context caching은 사용하지 않는다. 모델 ID를 자동 교체하지 않으며 현재 운영 계약은 Prompt `P2`, 결과 Schema `S1`로 고정한다. 모델이 Free Tier에서 제공되지 않거나 결제 연결을 요구하면 호출하지 않는다. |
| 비용 상한 | AI와 Mobility의 유료 호출은 모두 금지한다. 공급자 Free Tier quota와 애플리케이션 자체 호출 상한 중 더 낮은 기준을 적용하고, quota 확인 실패·소진·결제 연결 요구 시 즉시 hard stop한다. |
| 운영자 작업량 | 정상 조건에서는 건별 승인을 하지 않는다. 운영자는 채널 활성화·중지, 실패·보류 작업, 자동 등록 롤백과 태그 중복 정책을 관리하며, 자동 처리 Worker는 인스턴스당 1개로 제한한다. |
| 실패 대체 동작 | AI 실패·시간 초과·quota 초과·장소 모호·근거 부족은 제한 재시도 후 자동 보류·실패로 남긴다. 자동 등록하지 않고 기존 수동 등록 흐름으로 복구할 수 있다. |
| 품질 기준 | 자동 검증을 통과한 경우에만 정식 Entity·`VisitTag`를 생성·공개한다. 태그는 자막 근거·정규화·중복 검사를 통과한 경우에만 `ACTIVE`로 등록하며, 동일 URL·입력 hash·모델 버전은 멱등 처리한다. |
| 완료 조건 | 관리자 신규 추가·Webhook 감지·작업 중복 수렴·자동 추출·태그 자동 생성·외부 검증·자동 등록·자동 공개·보류·실패·롤백·모델 버전 시나리오를 검증하고, 자동 검증 실패 시 정식 저장 0건과 Free Tier 차단을 확인한다. |
| 공개 경계 | 관리자 승인 없이도 자동 검증을 모두 통과한 결과는 정식 Entity·`VisitTag`로 생성·공개한다. 검증 실패·불확실·중복·근거 부족 결과는 자동 보류하고 공개하지 않는다. |

#### 5.3.3 동선 및 코스 추천

| 승인 항목 | 결정 |
|---|---|
| 목적과 사용자 가치 | 사용자가 고른 맛집을 방문할 현실적인 순서로 정리하고 각 이동 구간의 경로 요약을 제공한다. |
| 포함 범위 | 공개·활성·좌표 보유 맛집 2~5개 선택, 첫 선택 맛집을 출발지로 고정한 자동차 이동 순서 제안, 마지막 맛집까지의 구간 거리·예상 소요 시간, 전체 30km 이하 상한을 포함한다. |
| 제외 범위 | 자동 맛집 선정, 현재 위치·별도 출발·도착지, 도보·대중교통·자전거, 실시간 교통 판단, 영업 가능 여부, 예약·결제, 코스 저장·공유를 제외한다. |
| 선행 기능 | 공개·활성 맛집 조회, 유효한 위도·경도 보강, 2~5개 선택 UI/API와 Kakao Mobility 제휴·인증·호출 계약이 선행한다. |
| 개인정보 영향 | 현재 위치·위치 권한·이동 이력을 수집하지 않는다. 선택한 맛집 ID와 요청 결과는 초기에는 저장·공유하지 않으며, 공개 사업장 좌표만 경로 계산에 사용한다. |
| 외부 API와 AI 모델 | 자동차 경로 계산에 Kakao Mobility 자동차 길찾기 `/v1/directions`를 사용하고, 첫 장소를 출발지로 고정한 최근접 이웃 순서로 좌표를 구성한다. AI 모델은 사용하지 않는다. |
| 비용 상한 | Mobility 유료 호출은 금지하고 Free Tier quota 안에서만 동작한다. 앱 자체 호출 상한은 월 1,000건, 코스 1건당 외부 호출은 최대 1회로 둔다. 공식 quota·계약을 확인할 수 없거나 무료 quota를 초과하면 호출하지 않는다. |
| 운영자 작업량 | 코스별 수동 편집은 없다. 좌표 누락률·외부 호출량·quota·지연·실패율을 관측하고 장애·계약 변경 때만 설정을 조정한다. |
| 실패 대체 동작 | 좌표 부족·입력 범위 위반·외부 429·시간 초과·경로 실패 시 거리·시간을 추정해 만들지 않고 실패 상태와 재선택 안내를 반환한다. 기존 맛집 탐색은 계속 사용할 수 있다. |
| 품질 기준 | 공개·활성·좌표 보유 맛집 2~5개만 허용하고 첫 선택을 출발지로 고정한다. 실제 경로 거리·예상 시간만 반환하며 총 이동 거리 30km 초과 코스는 제공하지 않는다. |
| 완료 조건 | 2~5개 선택, 순서 제안, 구간 거리·시간, 30km 상한, 좌표 누락, 외부 실패·quota 초과·중복 요청을 검증하고, 현재 위치·저장·공유·자동 맛집 선정이 발생하지 않음을 확인한다. 외부 호출 상한과 비용 차단도 검증한다. |
| 추천의 의미 | `추천`은 맛집을 고르는 개인화 추천이 아니라 사용자가 고른 맛집의 이동 순서를 제안하는 의미로만 사용한다. |

#### 5.3.4 공통 승인 조건

- 세 기능은 기존 공개·활성 맛집과 현재 공개·생명주기 판정을 재사용한다. 좌표 없는 맛집은 기존 목록·상세에는 남지만 코스 후보에서는 제외한다.
- 자연어 검색은 기존 조건 해석으로 제한하고, AI 영상 정보 추출은 자동 검증 통과 결과의 자동 등록·공개와 예외 보정으로 확장한다.
- AI가 만든 후보나 문장을 자동 검증 없이 사실로 확정하지 않으며, 정식 데이터 등록에는 기존 등록 명령의 원자성·중복 규칙과 Kakao·YouTube·Visit 자동 검증을 적용한다. 관리자의 사전 승인은 요구하지 않는다.
- 코스 결과는 초기에는 저장·공유하지 않고 현재 위치·회원 행동·개인 컬렉션을 사용하지 않는다.
- 2차 확장의 정상 부하 50명·20 RPS와 최대 부하 200명·80 RPS 측정은 3차 확장 최종 완료 게이트로 승계한다([3차 확장 선행 상태 검토](../08-planning/third-expansion-baseline-review.md) 참조).

### 5.4 MVP 검증 배포와 이후 운영

- 선행 조건: MVP 구현 및 로컬 통합 검증 완료
- 포함 범위: EC2, ECR, RDS, CloudWatch, 운영 비밀정보, 운영 배포·상태 확인·백업·복구 검증
- 적용 원칙: M2 초기 운영 배포에서 최초 운영 환경을 검증 참여자 전용 쿠키 세션으로 제한 공개하고 같은 환경을 계속 운영한다. 제한 공개 인증은 회원·관리자 인증과 분리하며 정식 공개 시 전체 제거한다. 이후 확장에서는 필요한 인프라 변경을 기능 변경과 같은 단계에서 반영한다.

## 6. 범위 경계 규칙

새로운 요구사항이 MVP에 포함되는지는 다음 질문에 따라 판단한다.

1. 맛집 목록 탐색부터 상세의 방문 유튜버와 근거 영상 확인까지 이어지는 핵심 탐색 흐름에 필수적인가?
2. 사용자 계정 없이 제공 가능한가?
3. 사용자별 데이터를 저장하지 않고 제공 가능한가?
4. 관리자가 검증 후 수동 등록하는 방식으로 운영 가능한가?
5. 외부 서비스의 복잡한 연동 없이 구현 가능한가?
6. 4명의 백엔드 개발자가 MVP 기간 내 서로 독립적으로 개발 가능한 크기와 의존성을 가지는가?
7. 새로운 데이터 모델이나 인프라를 크게 추가하지 않고 구현 가능한가?
8. 해당 기능이 없어도 핵심 서비스 가치가 유지되는가?

핵심 탐색 흐름에 필수적이고 2번부터 7번까지의 제약을 충족하며, 기능 부재 시 핵심 서비스 가치가 훼손되는 경우에만 MVP 포함 후보로 판단한다. 단, 후보로 판단되더라도 자동으로 범위에 포함되지 않으며 제7장의 범위 변경 절차를 완료해야 한다.

다음 중 하나에 해당하면 원칙적으로 MVP에서 제외한다.

- 사용자 계정이 필요한 기능
- 개인화 데이터를 저장하는 기능
- 지도 SDK 또는 위치 기반 처리가 필요한 기능
- 추천 모델이나 통계 집계가 필요한 기능
- AI 분석이나 자동 데이터 추출이 필요한 기능
- 예약, 결제 또는 상업적 거래가 필요한 기능
- 실시간 알림이나 복잡한 비동기 처리가 필요한 기능

판단이 애매하거나 위 기준이 충돌하면 구현을 시작하지 않고 제9장에 검토 필요 항목으로 기록한다. 이후 팀 합의와 범위 변경 절차가 완료되기 전까지는 제외 범위로 취급한다.

## 7. 범위 변경 절차

기능 범위가 변경되면 다른 요구사항·설계 문서보다 이 문서를 먼저 수정해야 한다. 변경 절차는 다음 순서를 따른다.

1. 새로운 기능을 제안하고 목적과 필요성을 기록한다.
2. 기존 MVP 목표 및 핵심 탐색 흐름과의 연관성을 확인한다.
3. 개발 비용, 데이터, 외부 연동 및 운영을 포함한 영향 범위를 확인한다.
4. 기존 일정 또는 다른 MVP 기능에 미치는 영향을 확인한다.
5. 포함 여부와 조정 범위에 대해 팀이 합의한다.
6. 합의 결과를 반영하여 [scope.md](scope.md)를 먼저 수정한다.
7. 관련 기능 요구사항, PRD, Role, API 명세를 수정한다.
8. 중요한 설계 선택이나 장기적인 영향이 있으면 ADR을 작성한다.

팀 합의만 있고 [scope.md](scope.md)가 수정되지 않은 기능은 확정 범위로 보지 않는다. 하위 문서가 이 문서와 충돌하면 이 문서를 기준으로 하며, 충돌 내용을 해결하기 전에는 구현 범위를 확대하지 않는다.

## 8. MVP 완료 기준

다음 항목을 모두 실제로 검증할 수 있을 때 MVP의 기능 범위가 완료된 것으로 판단한다.

- 로컬 Docker 환경에서 Next.js, Spring Boot, PostgreSQL과 Redis를 함께 실행할 수 있다.
- 사용자가 계정 없이 맛집 목록을 조회할 수 있다.
- 사용자가 페이지 단위로 맛집 목록을 이동할 수 있고, 무한 스크롤은 제공되지 않는다.
- 사용자가 맛집 목록에서 이름, 자치구, 대표 음식 카테고리와 방문 유튜버를 확인할 수 있다.
- 사용자가 맛집 이름으로 검색하여 일치하는 맛집을 찾을 수 있다.
- 사용자가 서울특별시 자치구, 유튜버, 음식 카테고리로 각각 맛집을 필터링할 수 있다.
- 사용자가 이름 검색과 각 필터를 함께 적용할 수 있고, 모든 조건을 만족하는 결과만 조회할 수 있다.
- 사용자가 목록, 검색 또는 필터 결과에서 맛집을 선택해 상세 정보를 조회할 수 있다.
- 사용자가 맛집 상세에서 도로명주소, 전화번호를 확인하고 카카오 장소 페이지로 이동할 수 있다.
- 사용자가 맛집 상세에서 관리자가 등록한 방문 유튜버와 관련 YouTube 영상 링크를 확인할 수 있다.
- 사용자가 관련 YouTube 영상 링크를 통해 원본 영상으로 이동할 수 있다.
- 영상 연결 정보가 없는 맛집도 목록과 상세에서 기본 정보를 조회할 수 있다.
- 관리자가 맛집, 유튜버, 영상 및 방문 관계를 각각 등록할 수 있다.
- 사전 발급된 관리자 계정으로 인증한 사용자만 관리자 등록 기능에 접근할 수 있다.
- 관리자가 카카오 장소와 맛집의 일치 여부를 확인하고 대표 음식 카테고리 1개를 지정할 수 있다.
- 관리자가 중복되는 맛집, 유튜버, 영상 또는 방문 관계를 새로 등록하지 않고 기존 정보를 사용할 수 있다.
- 방문 관계는 실제 방문을 확인할 수 있는 영상을 근거로 등록된다.
- 관리자가 등록한 맛집 정보가 사용자 목록, 검색, 필터 및 상세 조회에 정상적으로 반영된다.
- 관리자가 등록한 방문 관계가 유튜버별 필터와 맛집 상세의 유튜버·영상 정보에 정상적으로 반영된다.
- YouTube 영상 원본을 저장하거나 재배포하지 않고 원본 링크와 필요한 메타데이터만 제공한다.
- 핵심 사용자 흐름이 PC Chrome·Edge, Android Chrome의 최신 안정 버전에서 처음부터 끝까지 동작한다. iPhone Safari는 2026-08-06 [ADR-WEB-004](../07-adr/platform/web-004-supported-browser-matrix.md)로 이 기준에서 제외했다. MVP 완료 선언 시점에도 실단말이 없어 검증하지 못한 항목으로 남아 있었고([로컬 실행·회귀 검증 결과](../08-planning/mvp-local-verification.md) 10절), 그 사실을 계약에 반영한 것이다. 의도적으로 차단하지 않으며 실단말 또는 원격 실단말 환경이 확보되면 매트릭스로 되돌린다.
- 회원, 찜, 최근 본 맛집, 지도 기반 탐색, 추천·큐레이션, 사용자 참여, AI, 예약·결제 등 MVP 제외 기능이 일반 사용자 화면이나 API에 포함되지 않는다.
- EC2, ECR, RDS, CloudWatch와 AWS 운영 배포는 MVP 구현 완료 조건과 분리된 M2 초기 운영 배포 완료 조건으로 관리한다.

## 9. 후속 상세 정책

다음 항목은 2026-07-27 승인안으로 확정한다.

- 카카오·YouTube 정보는 등록 시 확인 Token의 10분 후보 Snapshot에만 임시 저장하고, 등록 뒤 자동 갱신하거나 표시 메타데이터 변경 이력을 별도로 저장하지 않는다. 외부 API 장애 시 부분 저장 없이 실패시키고 관리자가 수동 재시도한다.
- 관리자 계정은 별도 운영 명령으로 발급·비활성화·비밀번호 재설정하며, 서비스 계정 관리·복구 API는 MVP에 포함하지 않는다.
- PC Chrome·Edge, Android Chrome의 테스트 시점 최신 및 직전 안정 버전을 지원하고 360px, 390px, 768px, 1280px, 1440px 화면 폭을 검증한다. iPhone Safari는 2026-08-06 [ADR-WEB-004](../07-adr/platform/web-004-supported-browser-matrix.md)에 따라 검증 수단이 없어 지원 대상으로 표방하지 않는다. 의도적으로 차단하지 않으며 실단말 또는 원격 실단말 환경이 확보되면 매트릭스로 되돌린다.
