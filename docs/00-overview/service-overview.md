# 맛잇온 서비스 개요

## 1. 서비스 한 줄 정의

맛잇온은 유튜버가 실제로 방문한 맛집을 지역, 음식 카테고리, 유튜버 기준으로 탐색하고 관련 영상까지 확인할 수 있는 웹 서비스다.

## 2. 서비스 배경 및 문제

유튜브에는 다양한 맛집 콘텐츠가 있지만, 맛집 정보가 개별 영상과 채널에 흩어져 있다. 사용자는 여러 영상을 직접 찾아보며 식당명, 위치, 음식 종류를 다시 정리해야 한다.

특정 지역이나 음식 종류를 기준으로 맛집을 비교하기도 어렵다. 특정 유튜버가 방문한 맛집만 모아서 확인하려면 채널의 영상을 하나씩 살펴봐야 한다.

맛잇온은 영상에 흩어진 방문 정보를 맛집 중심으로 정리한다. 사용자가 원하는 기준으로 맛집을 찾고, 방문 근거가 되는 원본 영상까지 이어서 확인할 수 있도록 한다.

## 3. 서비스 목표

- 유튜버가 방문한 맛집 정보를 한곳에서 탐색할 수 있게 한다.
- 지역, 음식 카테고리, 유튜버 기준으로 탐색 범위를 좁힐 수 있게 한다.
- 맛집의 기본 정보와 방문 유튜버, 관련 영상을 연결해 제공한다.
- 관리자가 검증한 정보만 MVP 데이터로 제공한다.
- PC와 모바일 브라우저에서 핵심 탐색 흐름을 사용할 수 있게 한다.

## 4. 핵심 사용자

### 일반 사용자

- 유튜브 맛집 콘텐츠를 보고 실제 방문할 장소를 찾는 사용자
- 특정 유튜버가 방문한 맛집을 모아서 보고 싶은 사용자
- 지역이나 음식 종류를 기준으로 맛집을 찾는 사용자

MVP의 일반 사용자는 계정 없이 맛집을 탐색한다.

### 관리자

- 맛집, 유튜버, 영상 정보를 검증하고 등록하는 운영자
- 영상에 근거해 맛집, 유튜버, 영상의 방문 관계를 등록하는 운영자

## 5. 핵심 사용자 가치

- 여러 영상과 채널에 흩어진 맛집 정보를 한곳에서 확인할 수 있다.
- 지역, 음식 카테고리, 유튜버 기준으로 원하는 맛집을 빠르게 좁힐 수 있다.
- 맛집별로 어떤 유튜버가 방문했는지 확인할 수 있다.
- 관련 원본 영상을 통해 실제 방문 장면과 콘텐츠를 직접 확인할 수 있다.
- 관리자가 검증한 데이터를 기준으로 탐색할 수 있다.

## 6. 핵심 사용자 흐름

### 일반 사용자 흐름

1. 사용자는 맛집 목록에 접근한다.
2. 맛집 이름을 검색하거나 지역, 음식 카테고리, 유튜버 필터를 선택한다.
3. 검색 또는 필터 결과에서 맛집을 선택한다.
4. 맛집 상세에서 기본 정보와 방문 유튜버 정보를 확인한다.
5. 연결된 영상이 있으면 관련 영상 링크를 선택해 YouTube 원본 영상을 확인한다.

영상이 연결되지 않은 맛집도 기본 정보는 조회할 수 있다.

### 관리자 흐름

1. 관리자는 검증한 맛집, 유튜버, 영상 정보를 등록한다.
2. 영상에서 유튜버의 실제 맛집 방문 여부를 확인한다.
3. 확인된 영상을 근거로 맛집, 유튜버, 영상의 방문 관계를 등록한다.
4. 등록된 정보와 관계가 사용자 탐색 결과와 맛집 상세에 반영되는지 확인한다.

## 7. MVP 범위

### 7.1 맛집 탐색

- 맛집 목록을 조회한다.
- 맛집 이름으로 검색한다.
- 지역별로 맛집을 필터링한다.
- 음식 카테고리별로 맛집을 필터링한다.
- 유튜버별로 맛집을 필터링한다.
- 공개 유튜버의 최소 선택 목록에서 필터 대상을 선택한다.

### 7.2 맛집 상세 정보

- 선택한 맛집의 기본 정보를 조회한다.
- 영상 연결 여부와 관계없이 등록된 맛집의 기본 정보를 조회할 수 있다.
- 상세 정보의 구체적인 표시 항목은 기능 요구사항에서 정의한다.

### 7.3 유튜버 및 영상 정보 확인

- 맛집을 실제로 방문한 유튜버 정보를 확인한다.
- 방문 근거로 등록된 관련 YouTube 영상 링크를 확인한다.
- 영상은 서비스에 직접 저장하거나 재배포하지 않는다.
- 서비스는 원본 영상 링크와 탐색에 필요한 메타데이터만 관리한다.
- MVP에서는 별도의 유튜버 상세 페이지를 제공하지 않는다.

### 7.4 관리자 데이터 등록

- 관리자가 맛집 정보를 등록한다.
- 관리자가 유튜버 정보를 등록한다.
- 관리자가 영상 정보를 등록한다.
- 유튜버와 영상 등록 시 YouTube API로 채널·영상 정보를 조회하고 관리자가 확인한 결과를 저장한다.
- 관리자가 맛집, 유튜버, 영상의 방문 관계를 등록한다.
- 방문 관계는 실제 방문을 확인할 수 있는 영상을 근거로 등록한다.
- MVP 데이터는 관리자가 검증한 후 등록한다.
- 일반 사용자는 맛집, 유튜버, 영상 정보를 직접 등록하지 않는다.

## 8. MVP 제외 범위

다음 기능은 MVP에 포함하지 않는다.

- 회원가입, 로그인 및 사용자 계정
- 찜하기와 최근 본 맛집
- 사용자별 저장 정보와 개인화 기능
- 지도 기반 탐색, 현재 위치, 길 찾기
- 유튜버 상세 페이지
- 컬렉션
- 인기 맛집과 큐레이션
- 사용자 제보 및 신고
- 알림
- 자연어 검색
- AI 기반 영상 정보 추출
- 동선 및 코스 추천
- 예약과 결제
- 추천 알고리즘

## 9. MVP 이후 확장 방향

### 1차 확장

- 회원가입 및 로그인
- 찜하기
- 최근 본 맛집
- 지도 기반 탐색
- 유튜버 상세 페이지

### 2차 확장

- 컬렉션
- 인기 맛집
- 큐레이션
- 사용자 제보 및 신고
- 알림

### 3차 확장

- 자연어 검색
- AI 기반 영상 정보 추출
- 동선 및 코스 추천

### MVP 검증 배포와 이후 운영

- 초기 운영 배포(M2)는 다음 확장 단계 착수 전에 최초 AWS 운영 환경으로 수행한다.
- 초기 운영 배포는 단일 EC2, ECR, RDS와 CloudWatch를 사용하는 기술 결정을 적용하고 M2에서 검증 참여자에게 제한 공개했다. 이 제한 공개는 완료된 역사적 단계이며 현재 정식 공개는 검증 참여자 gate 없이 수행한다([ADR-DEPLOY-006](../07-adr/platform/deploy-006-public-release-without-validation-gate.md)).
- 회원·관리자 인증, Webhook 자체 인증·rate limit, Host 검증, `/internal/**` 외부 `404`와 loopback 애플리케이션 포트 경계는 정식 공개에서도 유지한다.
- 이후 배포 고도화는 영향·비용 검토를 마친 [ADR-DEPLOY-005](../07-adr/platform/deploy-005-asg-blue-green-rollout.md) Accepted 기준(ALB·ASG·CodeDeploy replacement·사설 subnet 전용 Redis)을 따르며, 실제 전환과 `v1.0.0` tag는 별도 운영 승인·확인을 거친다.

확장 기능의 세부 범위와 우선순위는 각 단계의 PRD에서 검토한다. 초기 운영 배포 절차는 후속 문서에서 구체화하되, 이 문서와 비기능 요구사항·ADR의 검증 기준을 충족해야 한다.

## 10. 핵심 운영 원칙

- 맛집과 유튜버의 방문 관계는 실제 방문을 확인할 수 있는 영상을 근거로 한다.
- 방문 근거 영상은 관리자가 확인한다.
- 영상 연결 정보가 없는 맛집도 기본 정보 조회 대상으로 관리할 수 있다.
- MVP의 맛집, 유튜버, 영상 및 방문 관계 데이터는 관리자가 등록한다.
- 일반 사용자는 서비스 데이터를 직접 등록하지 않는다.
- YouTube 영상은 직접 저장하거나 재배포하지 않는다.
- 원본 영상 링크와 서비스 제공에 필요한 메타데이터만 관리한다.
- 일반 사용자 조회는 앱 서버에 저장된 정보를 사용하며 YouTube API를 실시간 호출하지 않는다.
- MVP에서는 사용자 계정과 개인화 데이터를 다루지 않는다.
- MVP의 범위를 벗어나는 기능은 후속 단계와 혼합하지 않는다.

## 11. MVP 완료 기준

- MVP는 로컬 Docker 환경에서 프론트엔드, 백엔드, PostgreSQL과 Redis를 함께 실행해 검증한다.
- 사용자가 웹 서비스에서 등록된 맛집 목록을 조회할 수 있다.
- 사용자가 맛집 이름으로 검색해 일치하는 맛집을 찾을 수 있다.
- 사용자가 지역, 음식 카테고리, 유튜버 필터를 각각 이용해 맛집을 찾을 수 있다.
- 사용자가 목록에서 맛집을 선택해 상세 정보를 조회할 수 있다.
- 사용자가 맛집 상세에서 방문 유튜버와 연결된 영상 링크를 확인할 수 있다.
- 연결된 영상 링크를 통해 YouTube 원본 영상으로 이동할 수 있다.
- 영상이 연결되지 않은 맛집도 목록과 상세에서 기본 정보를 조회할 수 있다.
- 관리자가 맛집, 유튜버, 영상 정보를 등록할 수 있다.
- 관리자가 영상을 근거로 맛집, 유튜버, 영상의 방문 관계를 등록할 수 있다.
- 관리자가 등록한 정보와 방문 관계가 사용자 화면에 반영된다.
- YouTube 영상을 직접 저장하거나 재배포하지 않고 원본 링크로 제공한다.
- 핵심 탐색 흐름을 PC와 모바일 브라우저에서 사용할 수 있다.
- 회원, 찜, 지도, AI, 예약, 결제 및 추천 알고리즘이 MVP 사용자 흐름에 포함되지 않는다.
- EC2, ECR, RDS, CloudWatch와 AWS 운영 배포는 MVP 구현 완료 조건과 분리된 M2 초기 운영 배포 완료 조건으로 관리한다.

## 12. 주요 용어

| 용어 | 정의 |
| --- | --- |
| 맛잇온 | 유튜버 방문 정보를 기준으로 맛집을 탐색하는 웹 서비스 |
| 맛집 | 서비스에서 탐색할 수 있도록 관리자가 등록한 식당 |
| 유튜버 | 맛집 방문 영상이 게시되는, 서비스에 등록된 YouTube 채널 |
| 영상 | 유튜버의 맛집 방문을 확인할 수 있는 YouTube 원본 콘텐츠 |
| 방문 관계 | 특정 영상에서 유튜버가 특정 맛집을 실제로 방문했음을 나타내는 연결 정보 |
| 방문 근거 | 맛집과 유튜버의 방문 관계를 확인할 수 있는 영상 정보 |
| 영상 연결 정보 | 맛집, 유튜버, 원본 영상을 함께 연결한 정보 |
| 관리자 | 맛집, 유튜버, 영상과 방문 관계를 검증하고 등록하는 운영자 |
| 일반 사용자 | 계정 없이 맛집을 검색하고 조회하는 MVP 이용자 |
| MVP | 핵심 탐색 가치와 관리자 데이터 등록 흐름을 검증하기 위한 최초 제공 범위 |
