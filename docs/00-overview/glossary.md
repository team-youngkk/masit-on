# 맛잇온 용어집

## 1. 문서 목적

이 문서는 맛잇온의 요구사항, 설계, 구현 및 운영에서 사용하는 주요 용어의 기준을 정의한다. 팀원과 AI 에이전트는 이 문서를 기준으로 같은 개념을 같은 의미로 해석하고, 유사한 표현의 혼용으로 인한 범위 오해를 방지한다.

이 문서는 [service-overview.md](service-overview.md)와 [scope.md](scope.md)에 확정된 MVP 범위를 따른다. 이 문서의 영문명은 코드와 API 설계를 위한 참고 표현이며, 데이터베이스 테이블명, 클래스명 또는 API 경로를 확정하지 않는다.

## 2. 작성 원칙

- 용어는 사전적 의미보다 맛잇온에서 사용하는 의미를 기준으로 정의한다.
- 하나의 개념에는 하나의 표준 용어를 사용한다.
- 각 용어의 포함 범위와 제외 범위를 함께 명시한다.
- 실제 행위, 서비스에 저장된 정보 및 사용자 화면의 기능을 구분한다.
- MVP의 확정 범위와 이후 확장 가능성을 구분한다.
- 구현 기술, 데이터베이스 구조 및 구체적인 API 형식은 정의하지 않는다.
- 기준 문서에 없는 서비스 개념이나 정책을 새로 추가하지 않는다.
- 확정되지 않은 의미와 영문명은 임의로 결정하지 않고 `검토 필요`로 표시한다.
- 용어 정의가 변경되면 [service-overview.md](service-overview.md), [scope.md](scope.md) 및 관련 요구사항·설계 문서를 함께 검토한다.

## 3. 사용자 및 역할 용어

### 일반 사용자

- 영문명: General User
- 정의: 계정 없이 맛집을 검색하고 조회하는 MVP의 서비스 이용자다.
- 포함:
  - 맛집 목록 조회
  - 맛집 이름 검색
  - 지역·유튜버·음식 카테고리 필터 사용
  - 맛집 상세, 방문 유튜버 및 관련 영상 확인
- 제외:
  - 회원 계정과 로그인
  - 사용자별 데이터 저장과 개인화
  - 맛집·유튜버·영상·방문 관계의 등록 또는 수정
- 관련 용어:
  - 회원
  - 관리자
  - 맛집 탐색
- 사용 규칙:
  - 문서에서 조회 기능을 사용하는 주체는 `일반 사용자`로 표현한다.
  - 로그인 여부와 관계없이 서비스 이용 주체를 `회원`으로 표현하지 않는다.

### 관리자

- 영문명: Administrator
- 정의: 맛집, 유튜버, 영상 및 방문 관계를 검증하고 등록하는 운영자다.
- 포함:
  - 맛집·유튜버·영상 정보의 확인과 등록
  - 영상을 근거로 한 실제 방문 여부 확인
  - 방문 관계 등록
- 제외:
  - 일반 사용자의 조회 역할
  - AI 또는 외부 수집을 통한 자동 등록
  - MVP에서 확정되지 않은 수정·삭제·승인 상태 관리
- 관련 용어:
  - 관리자 등록
  - 검증된 데이터
  - 방문 관계
- 사용 규칙:
  - 문서에서 운영 및 데이터 등록 주체는 `관리자`로 표현한다.
  - 구체적인 인증 방식이나 권한 구조는 이 용어만으로 확정하지 않는다.

## 4. 핵심 도메인 용어

### 맛집

- 영문명: Restaurant
- 정의: 서비스에 등록되어 일반 사용자가 조회할 수 있는 음식점이다.
- 포함:
  - 맛집 이름
  - 지역 정보
  - 음식 카테고리
  - 서비스에 등록된 기본 정보
- 제외:
  - 예약 가능 여부
  - 실시간 영업 상태
  - 결제 정보
  - 등록되지 않은 음식점
- 관련 용어:
  - 지역
  - 음식 카테고리
  - 방문 관계
- 사용 규칙:
  - 요구사항과 설계 문서에서 `맛집` 또는 참고 영문명 `Restaurant`으로 표현한다.
  - 같은 의미로 `음식점`, `식당`, `가게`, `매장`을 혼용하지 않는다.
  - 영상 연결 정보가 없어도 맛집으로 등록하고 기본 정보를 조회할 수 있다.

### 유튜버

- 영문명: YouTuber
- 정의: 맛집 관련 영상이 게시되는 YouTube 채널을 서비스에서 지칭하는 용어다.
- 포함:
  - 관리자가 검증하고 등록한 YouTube 채널 정보
  - 방문 관계에 연결되는 주체
- 제외:
  - YouTube 채널 자체의 모든 플랫폼 데이터
  - 구독자 수·인기도·성향에 따른 분류
  - 별도의 유튜버 상세 페이지
- 관련 용어:
  - 채널
  - 영상
  - 방문 관계
- 사용 규칙:
  - 서비스 문서의 표준 용어는 `유튜버`다.
  - 현재 MVP에서는 YouTube 채널을 유튜버 정보의 고유한 관리 단위로 사용한다. 관리자 등록 시 YouTube API로 정보를 조회할 수 있지만 자동 주기 동기화는 수행하지 않는다.
  - 한 사람이 여러 채널을 운영하면 채널별로 구분하고, 여러 사람이 하나의 채널을 운영하면 하나의 유튜버 정보로 취급한다.

### 영상

- 영문명: Video
- 정의: 유튜버가 맛집을 실제로 방문했다는 근거로 사용하는 YouTube 원본 콘텐츠다.
- 포함:
  - YouTube 원본 링크
  - 서비스 제공에 필요한 영상 메타데이터
  - 하나 이상의 맛집이 등장하는 콘텐츠
- 제외:
  - 영상 원본 파일의 저장 또는 재배포
  - 영상 자동 요약·분석·정보 추출
  - 별도의 영상 상세 페이지나 영상 탐색 기능
- 관련 용어:
  - 유튜버
  - 관련 영상
  - 영상 메타데이터
  - 방문 관계
- 사용 규칙:
  - 문서에서 원본 YouTube 콘텐츠 자체를 가리킬 때 `영상`을 사용한다.
  - 한 영상에는 하나 이상의 맛집이 등장할 수 있다.

### 방문

- 영문명: Visit
- 정의: 유튜버가 특정 맛집에 실제로 간 행위 또는 사실이다.
- 포함:
  - 영상에서 실제로 확인할 수 있는 맛집 방문
- 제외:
  - 방문 여부를 추정한 정보
  - 서비스에 저장된 연결 정보 자체
  - 영상으로 확인할 수 없는 방문 주장
- 관련 용어:
  - 방문 관계
  - 영상
  - 검증된 데이터
- 사용 규칙:
  - 실제 행위나 사실을 설명할 때만 `방문`을 사용한다.
  - 서비스에 등록된 데이터 관계를 뜻할 때는 `방문 관계`를 사용한다.

### 방문 관계

- 영문명: Visit Relationship
- 정의: 특정 유튜버가 특정 맛집을 실제로 방문했다는 사실을 특정 영상을 근거로 연결한 서비스 정보다.
- 포함:
  - 하나의 맛집
  - 하나의 유튜버
  - 방문 근거가 되는 하나의 영상
  - 관리자의 실제 방문 확인 결과
- 제외:
  - 근거 영상이 없는 관계
  - AI가 자동 생성한 추정 관계
  - 실제 방문 행위 자체
- 관련 용어:
  - 방문
  - 영상
  - 연결 정보
  - 검증된 데이터
- 사용 규칙:
  - 맛집·유튜버·근거 영상을 연결한 저장 정보를 `방문 관계`로 표현한다.
  - 하나의 맛집에는 여러 유튜버가 연결될 수 있고, 하나의 유튜버는 여러 맛집과 연결될 수 있다.
  - 한 영상에 여러 맛집이 등장하면 각 맛집에 대한 방문 관계를 구분해 해석한다.

### 지역

- 영문명: Region
- 정의: 관리자가 맛집에 등록하고 일반 사용자가 탐색 범위를 좁히는 데 사용하는 위치 분류 정보다.
- 포함:
  - 맛집에 등록된 지역 정보
  - 지역별 필터의 기준
- 제외:
  - 현재 위치
  - 거리 또는 반경
  - 지도 이동 영역
  - 길찾기와 경로 정보
- 관련 용어:
  - 맛집
  - 필터
  - 맛집 탐색
- 사용 규칙:
  - 등록된 분류 정보를 `지역`으로 표현한다.
  - MVP의 지역은 서울특별시 자치구 1개를 기준으로 하며 동·읍·면, 현재 위치, 거리 또는 반경으로 세분화하지 않는다.

### 음식 카테고리

- 영문명: Food Category
- 정의: 관리자가 맛집에 등록하고 일반 사용자가 음식 종류를 기준으로 탐색 범위를 좁히는 데 사용하는 분류 정보다.
- 포함:
  - 맛집에 등록된 음식 종류 분류
  - 음식 카테고리별 필터의 기준
- 제외:
  - AI 자동 분류
  - 사용자별 선호 추천
  - 테마·분위기·가격대 등 확정되지 않은 분류
- 관련 용어:
  - 맛집
  - 필터
  - 맛집 탐색
- 사용 규칙:
  - 표준 용어는 `음식 카테고리`로 사용한다.
  - 한 맛집에는 주된 메뉴와 영업 정체성을 가장 잘 나타내는 사전 정의된 대표 음식 카테고리 1개만 지정한다.
  - 대표 음식 카테고리는 한식, 중식, 일식, 양식, 동남아 음식, 인도·남아시아 음식, 분식, 카페·디저트, 술집·주점, 기타를 사용한다.

## 5. 탐색 및 조회 용어

### 맛집 탐색

- 영문명: Restaurant Discovery
- 정의: 일반 사용자가 목록, 이름 검색 또는 필터를 이용해 원하는 맛집을 찾고 상세 정보와 방문 근거까지 확인하는 전체 흐름이다.
- 포함:
  - 맛집 목록 조회
  - 맛집 이름 검색
  - 지역·유튜버·음식 카테고리 필터
  - 맛집 상세와 관련 영상 확인
- 제외:
  - 추천 및 개인화
  - 지도·위치 기반 탐색
  - 자연어 검색
- 관련 용어:
  - 맛집 목록
  - 맛집 검색
  - 필터
  - 맛집 상세
- 사용 규칙:
  - 개별 검색 기능이 아니라 사용자의 전체 찾기 흐름을 가리킬 때 `맛집 탐색`을 사용한다.

### 맛집 목록

- 영문명: Restaurant List
- 정의: 서비스에 등록된 맛집을 여러 건 조회하고 탐색을 시작할 수 있도록 제공하는 결과다.
- 포함:
  - 등록된 맛집의 목록용 기본 정보
  - 검색 또는 필터 결과
  - 영상 연결 정보가 없는 맛집
- 제외:
  - 맛집의 모든 상세 정보
  - 관련 영상의 전체 정보
  - 인기순·추천순 정렬
  - 지도 형태의 표시
- 관련 용어:
  - 맛집 검색
  - 필터
  - 맛집 상세
- 사용 규칙:
  - 여러 맛집을 결과로 제공하는 조회를 `맛집 목록`으로 표현한다.
  - 목록에는 맛집 이름, 서울특별시 자치구, 대표 음식 카테고리와 방문이 확인된 YouTube 채널명을 제공한다.
  - 목록은 기본 20개 단위로 제공하며 10개, 20개 또는 50개 중 하나를 선택할 수 있다.

### 맛집 검색

- 영문명: Restaurant Search
- 정의: 일반 사용자가 맛집 이름을 입력해 일치하는 맛집을 찾는 기능이다.
- 포함:
  - 맛집 이름 기준 검색
  - 검색 결과의 맛집 목록 제공
- 제외:
  - 메뉴명·지역명·YouTube 채널명·영상 제목 통합 검색
  - 자연어 검색
  - 오타 자동 교정
  - 자동 완성·추천과 검색 기록 저장
- 관련 용어:
  - 맛집 목록
  - 필터
  - 맛집 탐색
- 사용 규칙:
  - MVP에서 `검색`은 맛집 이름 검색을 의미한다.
  - 지역·유튜버·음식 카테고리 조건 적용은 `필터`로 표현한다.

### 필터

- 영문명: Filter
- 정의: 등록된 분류 또는 방문 관계를 기준으로 맛집 목록의 범위를 좁히는 기능이다.
- 포함:
  - 지역별 필터
  - 유튜버별 필터
  - 음식 카테고리별 필터
- 제외:
  - 맛집 이름 입력 검색
  - 현재 위치·거리·반경 조건
  - 인기도·추천·성향 조건
- 관련 용어:
  - 맛집 검색
  - 지역
  - 음식 카테고리
  - 유튜버별 탐색
- 사용 규칙:
  - 조건 선택으로 결과 범위를 좁힐 때 `필터`를 사용한다.
  - 맛집 이름 검색과 서로 다른 종류의 필터는 함께 사용할 수 있으며 지정한 모든 조건을 만족하는 맛집만 제공한다.
  - 지역, 유튜버와 음식 카테고리 필터는 종류별로 한 번에 하나의 값만 선택한다.

### 맛집 상세

- 영문명: Restaurant Detail
- 정의: 일반 사용자가 선택한 한 맛집의 기본 정보와 연결된 방문 유튜버 및 관련 영상 정보를 확인하는 조회 영역이다.
- 포함:
  - 선택한 맛집의 기본 정보
  - 연결된 방문 유튜버 정보
  - 연결된 관련 영상 정보와 원본 링크
  - 영상 연결 정보가 없는 맛집의 기본 정보
- 제외:
  - 지도·길찾기·거리 계산
  - 예약 및 결제
  - 찜·최근 본 맛집·방문 기록
  - 리뷰·평점·제보·신고
- 관련 용어:
  - 맛집 목록
  - 관련 영상
  - 방문 관계
- 사용 규칙:
  - 한 맛집을 선택한 뒤 제공하는 조회 범위를 `맛집 상세`로 표현한다.
  - 맛집 상세에는 맛집 이름, 대표 음식 카테고리, 전체 도로명주소, 등록된 상세 위치, 전화번호와 카카오 장소 링크를 제공한다.

### 유튜버별 탐색

- 영문명: Browse by YouTuber
- 정의: 등록된 방문 관계를 기준으로 특정 유튜버가 실제 방문한 맛집을 찾아보는 탐색 방식이다.
- 포함:
  - 유튜버별 필터 사용
  - 필터 결과의 맛집 목록 제공
- 제외:
  - 유튜버 상세 페이지
  - 구독자 수·인기도·성향 기반 정렬 또는 추천
  - 근거 영상이 없는 추정 방문 관계
- 관련 용어:
  - 유튜버
  - 방문 관계
  - 필터
- 사용 규칙:
  - MVP의 `유튜버별 탐색`은 유튜버별 필터를 통한 맛집 탐색을 의미한다.
  - 유튜버 자체를 탐색하는 별도 기능으로 해석하지 않는다.

### 관련 영상

- 영문명: Related Video
- 정의: 특정 맛집의 방문 관계에 근거 영상으로 연결되어 맛집 상세에서 확인할 수 있는 영상이다.
- 포함:
  - 해당 맛집의 방문 관계에 연결된 영상 정보
  - YouTube 원본 링크
  - 서비스 제공에 필요한 메타데이터
- 제외:
  - 해당 맛집과 방문 관계로 연결되지 않은 영상
  - 서비스가 저장하거나 재배포하는 원본 영상 파일
  - 별도의 영상 추천 또는 탐색 결과
- 관련 용어:
  - 영상
  - 방문 관계
  - 맛집 상세
- 사용 규칙:
  - 원본 콘텐츠 일반을 말할 때는 `영상`, 특정 맛집에 연결된 맥락에서는 `관련 영상`을 사용한다.

## 6. 데이터 및 관계 용어

### 검증된 데이터

- 영문명: Verified Data
- 정의: 관리자가 출처와 사실 관계를 확인한 뒤 서비스에 등록한 맛집, 유튜버, 영상 또는 방문 관계 정보다.
- 포함:
  - 관리자가 확인한 맛집 기본 정보
  - 관리자가 확인한 유튜버와 영상 정보
  - 영상으로 실제 방문을 확인한 방문 관계
- 제외:
  - 일반 사용자가 직접 입력한 정보
  - AI 또는 외부 수집 결과를 검토 없이 등록한 정보
  - 근거 영상이 없는 방문 관계
- 관련 용어:
  - 관리자
  - 관리자 등록
  - 방문 관계
- 사용 규칙:
  - `검증된 데이터`는 관리자의 확인을 거쳤다는 의미로 사용한다.
  - 검증과 등록은 서로 다른 행위지만, MVP에는 관리자가 검증을 완료한 데이터만 등록한다.

### 관리자 등록

- 영문명: Administrator Registration
- 정의: 관리자가 검증한 정보를 서비스에 저장하여 조회 또는 관계 구성에 사용할 수 있게 하는 행위다.
- 포함:
  - 맛집 정보 등록
  - 유튜버 정보 등록
  - 영상 정보 등록
  - 방문 관계 등록
- 제외:
  - 일반 사용자의 등록
  - 관리자 확인 없는 자동 등록 또는 자동 주기 동기화
  - MVP에서 확정되지 않은 수정·삭제·승인 상태 관리
- 관련 용어:
  - 관리자
  - 검증된 데이터
  - 방문 관계
- 사용 규칙:
  - 시스템에 정보를 저장하는 행위는 `등록`, 사실 여부를 확인하는 행위는 `검증`으로 구분한다.
  - 검증과 등록은 연속될 수 있으나 같은 행위로 표현하지 않는다.

### 영상 메타데이터

- 영문명: Video Metadata
- 정의: 영상 원본을 저장하지 않고 서비스에서 관련 영상을 식별하고 표시하는 데 필요한 부가 정보다.
- 포함:
  - 서비스 제공과 탐색에 필요한 영상 정보
  - 원본 링크와 함께 관리되는 표시용 정보
- 제외:
  - 영상 원본 파일
  - 영상 전체 내용
  - AI가 추출한 분석·요약 정보
- 관련 용어:
  - 영상
  - 관련 영상
  - 외부 링크
- 사용 규칙:
  - MVP의 영상 메타데이터는 영상 제목, 썸네일, YouTube 채널명과 원본 링크다.
  - 영상 원본과 영상 메타데이터를 같은 의미로 사용하지 않는다.

### 외부 링크

- 영문명: External Link
- 정의: 맛잇온 외부 서비스의 원본 콘텐츠로 이동하기 위해 제공하는 주소다.
- 포함:
  - 관련 YouTube 원본 영상 링크
- 제외:
  - 영상 원본 저장 또는 재배포
  - 예약·결제·지도 등 MVP에서 제외된 외부 서비스 연동
  - 외부 콘텐츠의 소유 또는 관리
- 관련 용어:
  - 영상
  - 관련 영상
  - 영상 메타데이터
- 사용 규칙:
  - MVP에서 외부 링크는 관련 YouTube 원본 영상으로 이동하는 링크를 중심으로 사용한다.
  - 링크 제공을 외부 서비스와의 복잡한 기능 연동으로 해석하지 않는다.

### 연결 정보

- 영문명: 검토 필요 (Linkage Information 후보)
- 정의: 맛집, 유튜버 또는 영상 사이에 등록된 관계가 있음을 나타내는 일반 표현이다.
- 포함:
  - 맛집에 방문 유튜버 또는 관련 영상이 연결되어 있는지에 관한 정보
  - 방문 관계를 통해 조회되는 연관 정보
- 제외:
  - 실제 방문 행위
  - 근거 없이 추정한 연관성
  - 방문 관계와 별개인 새로운 데이터 관계
- 관련 용어:
  - 방문 관계
  - 관련 영상
  - 맛집 상세
- 사용 규칙:
  - 맛집·유튜버·근거 영상을 연결한 구체적인 도메인 정보는 `방문 관계`로 표현한다.
  - `연결 정보`는 연결 여부나 연관 정보 전반을 설명할 때만 사용하며 독립된 새 도메인 개념으로 확장하지 않는다.
  - 연결 정보가 없는 맛집도 목록과 상세에서 기본 정보를 조회할 수 있다.

## 7. 프로젝트 범위 용어

### MVP

- 영문명: First MVP
- 정의: 계정이나 개인화 없이 핵심 맛집 탐색 가치와 관리자의 검증 데이터 등록 흐름을 검증하기 위한 최초 제공 범위다.
- 포함:
  - 맛집 목록·이름 검색·필터
  - 맛집 상세와 방문 유튜버·관련 영상 확인
  - 맛집·유튜버·영상·방문 관계의 관리자 등록
  - PC와 모바일 브라우저의 핵심 탐색 흐름
- 제외:
  - 회원 계정과 사용자별 데이터
  - 지도·추천·사용자 참여·AI 기능
  - 예약·결제와 확정되지 않은 외부 연동
- 관련 용어:
  - 완료 기준
  - 확장 기능
  - 제외 범위
- 사용 규칙:
  - `MVP`만 단독으로 써서 다른 단계와 혼동될 수 있으면 `MVP`로 표현한다.
  - 확장 가능성만 기록된 기능을 MVP의 선행 설계 또는 구현 대상으로 해석하지 않는다.

### 확장 기능

- 영문명: Extended Feature
- 정의: MVP 이후 단계에서 검토할 수 있으나 현재 구현 또는 선행 설계 범위에는 포함되지 않은 기능이다.
- 포함:
  - 1차 확장 후보인 회원가입·로그인, 찜하기, 최근 본 맛집, 지도 기반 탐색, 유튜버 상세 페이지
  - 2차 확장 후보인 컬렉션, 인기 맛집, 큐레이션, 사용자 제보·신고, 알림
  - 3차 확장 후보인 자연어 검색, AI 기반 영상 정보 추출, 동선·코스 추천
- 제외:
  - 범위 변경 절차 없이 현재 범위로 확정된 기능
  - 확정된 우선순위 또는 구현 일정
- 관련 용어:
  - MVP
  - 제외 범위
  - 범위 변경
- 사용 규칙:
  - 확장 단계에 기록되었다는 사실은 구현 확정을 의미하지 않는다.
  - 각 단계 착수 전에 범위 변경 절차와 해당 단계의 요구사항 검토가 필요하다.

### 제외 범위

- 영문명: Out of Scope
- 정의: 현재 MVP에서 제공하거나 설계·구현하지 않기로 정한 기능 또는 데이터 범위다.
- 포함:
  - 회원·개인화 기능
  - 지도·위치 기반 기능
  - 추천·큐레이션 기능
  - 사용자 참여 기능
  - AI·자동화 기능
  - 예약·결제 및 확정되지 않은 외부 연동
- 제외:
  - 단순히 세부 기준이 미확정된 MVP 포함 기능
  - 범위 변경 절차를 거쳐 새로 포함된 기능
- 관련 용어:
  - MVP
  - 확장 기능
  - 범위 변경
- 사용 규칙:
  - 제외 범위는 구현하지 않는 현재 기준이며, 미래에도 영구히 금지된다는 의미가 아니다.
  - 판단이 애매하거나 기준이 충돌하는 기능은 합의 전까지 제외 범위로 취급한다.

### 완료 기준

- 영문명: Completion Criteria
- 정의: MVP의 포함 기능과 제외 원칙이 실제로 충족되었는지 판단하기 위한 검증 가능한 조건이다.
- 포함:
  - 계정 없는 맛집 탐색 흐름의 동작 확인
  - 관리자 등록 정보와 방문 관계의 사용자 조회 반영 확인
  - 영상 원본 미저장 및 원본 링크 제공 확인
  - PC와 모바일 브라우저의 핵심 흐름 확인
  - 제외 기능이 사용자 화면이나 API에 포함되지 않았는지 확인
- 제외:
  - 구현 방법의 지정
  - 확장 기능의 완료 여부
  - 검증되지 않은 완료 선언
- 관련 용어:
  - MVP
  - 제외 범위
  - 검증된 데이터
- 사용 규칙:
  - `완료 기준`은 관찰하거나 검증할 수 있는 결과로 표현한다.
  - 세부 완료 판단은 [scope.md](scope.md)의 최신 MVP 완료 기준을 따른다.

### 범위 변경

- 영문명: Scope Change
- 정의: 현재 확정된 MVP의 포함·제외 범위를 추가, 제거 또는 조정하는 공식 변경이다.
- 포함:
  - 제안 목적과 필요성 기록
  - MVP 목표, 비용, 데이터, 외부 연동, 운영 및 일정 영향 검토
  - 팀 합의
  - [scope.md](scope.md) 우선 수정
  - 관련 요구사항·설계 문서 후속 수정
- 제외:
  - 구두 합의만으로 범위를 확정하는 것
  - 하위 문서만 수정해 구현 범위를 확대하는 것
  - 확장 후보를 자동으로 현재 범위에 포함하는 것
- 관련 용어:
  - MVP
  - 확장 기능
  - 제외 범위
- 사용 규칙:
  - 범위 변경 시 [scope.md](scope.md)를 다른 요구사항·설계 문서보다 먼저 수정한다.
  - 팀 합의가 있어도 [scope.md](scope.md)에 반영되지 않았다면 확정 범위로 보지 않는다.

## 8. 유사 용어 구분

### 맛집과 음식점

- `음식점`은 일반적인 대상의 종류를 설명하는 말이고, `맛집`은 그중 맛잇온에 등록되어 조회 가능한 대상을 뜻하는 표준 도메인 용어다.
- 요구사항, 설계 문서 및 도메인 설명에서는 `맛집`을 사용한다.
- 사용자 화면에서는 문맥상 자연스러운 한국어가 필요하면 `음식점` 또는 `식당`을 사용할 수 있으나, 그 표현이 별도의 도메인 개념을 뜻하지 않도록 한다.
- `가게`, `매장`, `식당`을 요구사항과 설계 문서에서 `맛집`과 같은 의미로 혼용하지 않는다.

### 유튜버와 채널

- `유튜버`는 맛집 관련 콘텐츠가 게시되는 YouTube 채널을 가리키는 서비스 용어다.
- `채널`은 YouTube에서 콘텐츠가 게시되는 플랫폼상의 공간 또는 계정 단위다.
- 현재 MVP의 유튜버 관리 단위는 YouTube 채널이다. 관리자 등록 시 API 조회 결과를 확인해 저장하며 자동 주기 동기화는 후속 범위다.
- 한 사람이 여러 채널을 운영하면 채널별로 구분하고, 여러 사람이 하나의 채널을 운영하면 하나의 유튜버 정보로 취급한다.

### 영상과 관련 영상

- `영상`은 맛집 방문 근거로 사용할 수 있는 YouTube 원본 콘텐츠 자체다.
- `관련 영상`은 특정 맛집의 방문 관계에 연결되어 해당 맛집 상세에서 제공되는 영상이다.
- 같은 영상도 특정 맛집과의 연결 맥락이 없으면 단순히 `영상`이며, 연결된 맛집의 관점에서는 `관련 영상`이다.

### 방문과 방문 관계

- `방문`은 유튜버가 맛집에 실제로 간 행위 또는 사실이다.
- `방문 관계`는 그 방문 사실을 특정 영상으로 확인하여 맛집·유튜버·영상을 연결한 서비스 정보다.
- 실제 방문이 있었더라도 확인 가능한 영상과 관리자 검증이 없으면 MVP의 방문 관계로 등록하지 않는다.

### 검색과 필터

- `검색`은 입력한 맛집 이름을 기준으로 일치하는 맛집을 찾는 기능이다.
- `필터`는 지역, 유튜버 또는 음식 카테고리 조건으로 맛집 목록의 범위를 좁히는 기능이다.
- 메뉴명·지역명·YouTube 채널명·영상 제목을 한 번에 찾는 통합 검색은 MVP 검색에 포함하지 않는다.

### 목록과 상세

- `맛집 목록`은 여러 맛집의 탐색용 기본 정보를 제공하며 검색과 필터의 결과도 목록으로 표현한다.
- `맛집 상세`는 선택한 한 맛집의 기본 정보와 연결된 방문 유튜버 및 관련 영상 정보를 제공한다.
- 목록은 맛집 이름, 자치구, 대표 음식 카테고리와 방문이 확인된 YouTube 채널명을 제공한다. 채널명은 오름차순 최대 3명과 `외 N명`으로 축약하며 전체 방문 유튜버는 상세에서 제공한다. 상세는 전체 도로명주소, 등록된 상세 위치, 전화번호와 카카오 장소 링크를 추가로 제공한다.
- 영상 연결 정보가 없는 맛집도 목록과 상세에서 기본 정보를 조회할 수 있다.

### 등록과 검증

- `등록`은 정보를 시스템에 저장하여 서비스에서 사용할 수 있게 하는 행위다.
- `검증`은 등록할 정보의 출처, 내용 또는 실제 방문 사실을 관리자가 확인하는 행위다.
- MVP 데이터는 관리자가 검증한 후 등록하지만, 두 행위를 같은 의미로 사용하지 않는다.

### 사용자와 회원

- `일반 사용자`는 로그인 여부와 관계없이 서비스를 조회하는 이용 주체이며, MVP에서는 계정 없이 이용한다.
- `회원`은 회원가입과 로그인을 통해 식별되는 별도 개념으로, MVP에는 존재하지 않는다.
- 회원은 1차 확장에서 도입을 검토할 수 있으나 범위 변경 전까지 일반 사용자와 같은 의미로 사용하지 않는다.

## 9. 표준 표현 규칙

- 하나의 개념에는 하나의 표준 용어를 사용한다.
- 같은 의미로 `맛집`, `음식점`, `가게`, `매장`, `식당`을 혼용하지 않는다. 요구사항과 설계 문서의 표준 용어는 `맛집`이다.
- 사용자 화면에서는 자연스러운 한국어를 사용할 수 있지만, 요구사항과 설계 문서에서는 이 문서의 표준 용어를 사용한다.
- 영문명은 코드와 API 설계에서 참고할 수 있도록 함께 작성하되 구현 식별자를 확정하는 것으로 해석하지 않는다.
- 아직 확정되지 않은 영문명은 임의로 결정하지 않고 `검토 필요`로 표시한다.
- 데이터베이스 테이블명, 클래스명, 필드명 및 API 경로는 이 문서에서 확정하지 않는다.
- 실제 행위는 `방문`, 서비스에 저장된 연결 정보는 `방문 관계`로 구분한다.
- 원본 콘텐츠 일반은 `영상`, 특정 맛집에 연결된 맥락은 `관련 영상`으로 구분한다.
- 맛집 이름을 입력하는 기능은 `맛집 검색`, 지역·유튜버·음식 카테고리 조건을 적용하는 기능은 `필터`로 구분한다.
- 시스템 저장 행위는 `등록`, 정보의 사실 여부 확인은 `검증`으로 구분한다.
- MVP의 조회 주체는 `일반 사용자`이며 `회원`으로 표현하지 않는다.
- 확장 가능성만 있는 기능은 `확장 기능`으로 표현하고 현재 범위처럼 서술하지 않는다.
- 용어의 정의가 변경되면 관련 요구사항, 범위 및 설계 문서를 함께 검토한다.

## 10. 검토 필요 용어

`방문 관계`의 API·코드 표준 영문명은 `Visit Relationship`으로 확정한다. `연결 정보`는 독립 도메인 자원이 아니므로 별도 API·코드 영문명을 만들지 않고 설명 용어로만 사용한다.
