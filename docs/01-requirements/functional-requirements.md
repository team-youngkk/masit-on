# 맛잇온 기능 요구사항

## 1. 문서 목적

이 문서는 맛잇온 MVP와 승인된 확장 단계에서 일반 사용자·회원·관리자가 사용할 수 있어야 하는 기능, 기능별 정상 결과, 예외 및 경계 조건을 정의한다. 이후 PRD, Role, API 명세, 테스트 시나리오와 구현 작업 분배는 이 문서의 요구사항 ID를 추적 기준으로 사용한다.

맛잇온은 유튜버가 실제로 방문한 맛집 정보를 서울특별시 자치구, 음식 카테고리, 유튜버 기준으로 제공하여 일반 사용자가 원하는 맛집과 방문 근거 영상을 탐색할 수 있게 하는 웹 서비스다.

이 문서는 기능의 결과와 판단 기준만 정의하며 구현 방식, 데이터 구조, API 경로와 품질 속성은 정의하지 않는다. 확정되지 않은 동작은 검토 필요 항목에 기록한다.

## 2. 요구사항 작성 규칙

- 요구사항 ID는 `FR-{DOMAIN}-{NUMBER}` 형식을 사용한다.
- 도메인 식별자는 [요구사항 README 4절](README.md#4-기능-요구사항-id)의 단계별 표준 목록을 사용한다.
- 하나의 요구사항에는 하나의 주요 기능만 정의한다.
- 각 요구사항은 설명, 사용자, 선행 조건, 입력 조건, 처리 규칙, 결과, 예외 및 경계 조건, 인수 조건을 포함한다.
- 인수 조건은 사용자의 행동 또는 시스템의 결과로 검증할 수 있게 작성한다.
- 여러 기능에 공통으로 적용되는 인증, 공개 상태, 오류 및 중복 표시 규칙은 제5장을 따른다.
- `맛집`, `유튜버`, `영상`, `방문 관계`, `개인 컬렉션`, `인기 맛집`, `관리자 큐레이션`, `사용자 제보`, `사용자 신고`, `사용자 알림`, `자연어 검색`, `AI 추출 후보`, `동선`, `코스`는 [용어집](../00-overview/glossary.md)의 의미로 사용한다.
- 요구사항 사이에 충돌이 있으면 단계별 범위의 기준 문서인 [scope.md](../00-overview/scope.md)를 우선한다.

## 3. 일반 사용자 기능

### 3.1 맛집 목록 및 탐색

#### FR-RESTAURANT-001 맛집 목록 조회

##### 설명

일반 사용자는 서비스에 공개된 맛집 목록을 조회할 수 있어야 한다.

##### 사용자

- 일반 사용자

##### 선행 조건

- 별도의 로그인은 필요하지 않다.

##### 입력 조건

- 페이지 번호
- 페이지 크기: 10, 20 또는 50 중 하나(선택, 기본값 20)

##### 처리 규칙

- 관리자가 등록하고 일반 사용자에게 공개된 맛집만 조회한다.
- 영상 연결 정보가 없는 맛집도 목록에 포함한다.
- 목록은 페이지 단위로 제공한다.
- 기본 정렬을 적용한다.

##### 결과

- 맛집 식별자
- 맛집 이름
- 서울특별시 자치구
- 대표 음식 카테고리
- 방문이 확인된 YouTube 채널명

##### 예외 및 경계 조건

- 조회 결과가 없으면 빈 목록을 정상 결과로 제공한다.
- 유효하지 않은 페이지 번호 또는 페이지 크기는 잘못된 요청으로 처리한다.
- 요청한 페이지에 결과가 없으면 빈 목록을 제공한다.

##### 인수 조건

- 공개된 맛집이 있으면 목록에서 확인할 수 있다.
- 영상 연결 정보가 없는 공개 맛집도 목록에서 확인할 수 있다.
- 공개되지 않았거나 삭제된 맛집은 목록에 포함되지 않는다.
- 결과가 없어도 서버 오류로 처리되지 않는다.

#### FR-RESTAURANT-002 맛집 이름 검색

##### 설명

일반 사용자는 맛집 이름에 검색어가 포함된 맛집을 조회할 수 있어야 한다.

##### 사용자

- 일반 사용자

##### 선행 조건

- 별도의 로그인은 필요하지 않다.

##### 입력 조건

- 맛집 이름 검색어

##### 처리 규칙

- 관리자가 등록한 맛집 이름만 검색 대상으로 사용한다.
- 검색어 앞뒤 공백은 제거한 뒤 검색한다.
- 영문 대소문자는 구분하지 않는다.
- 검색어가 맛집 이름의 일부와 일치하면 결과에 포함한다.
- 검색어 앞뒤 공백을 제거한 결과가 비어 있으면 맛집 이름 조건을 적용하지 않는다.

##### 결과

- 검색 조건에 일치하는 맛집 목록

##### 예외 및 경계 조건

- 일치하는 맛집이 없으면 빈 목록을 제공한다.
- 메뉴명, 지역명, YouTube 채널명과 영상 제목은 검색 대상에 포함하지 않는다.
- 초성, 유사어, 별칭과 오타 보정 검색은 제공하지 않는다.

##### 인수 조건

- 등록된 맛집 이름의 일부를 입력하면 해당 맛집을 결과에서 확인할 수 있다.
- 검색어 앞뒤에 공백을 추가해도 같은 검색 결과를 확인할 수 있다.
- 영문 검색어의 대소문자만 달라진 경우 같은 결과를 확인할 수 있다.

#### FR-RESTAURANT-003 지역별 필터

##### 설명

일반 사용자는 서울특별시 자치구를 기준으로 맛집 목록을 필터링할 수 있어야 한다.

##### 사용자

- 일반 사용자

##### 선행 조건

- 맛집에 서울특별시 자치구 정보가 등록되어 있어야 한다.

##### 입력 조건

- 서울특별시 자치구 1개

##### 처리 규칙

- 선택한 자치구에 속한 맛집만 조회한다.
- 필터를 지정하지 않으면 지역 조건을 적용하지 않는다.
- 동·읍·면, 현재 위치, 거리와 반경은 필터 기준으로 사용하지 않는다.

##### 결과

- 선택한 자치구에 속한 맛집 목록

##### 예외 및 경계 조건

- 선택한 자치구에 맛집이 없으면 빈 목록을 제공한다.
- 서울특별시 자치구가 아닌 값은 잘못된 요청으로 처리한다.

##### 인수 조건

- 자치구를 선택하면 해당 자치구의 맛집만 결과에 포함된다.
- 지역 필터를 해제하면 지역 조건이 적용되지 않는다.
- 해당 자치구에 맛집이 없어도 서버 오류로 처리되지 않는다.

#### FR-RESTAURANT-004 음식 카테고리별 필터

##### 설명

일반 사용자는 대표 음식 카테고리를 기준으로 맛집 목록을 필터링할 수 있어야 한다.

##### 사용자

- 일반 사용자

##### 선행 조건

- 맛집에 대표 음식 카테고리 1개가 등록되어 있어야 한다.

##### 입력 조건

- 한식, 중식, 일식, 양식, 동남아 음식, 인도·남아시아 음식, 분식, 카페·디저트, 술집·주점, 기타 중 1개

##### 처리 규칙

- 선택한 대표 음식 카테고리와 일치하는 맛집만 조회한다.
- 필터를 지정하지 않으면 음식 카테고리 조건을 적용하지 않는다.
- 한 번에 여러 음식 카테고리를 선택하는 기능은 제공하지 않는다.

##### 결과

- 선택한 대표 음식 카테고리에 속한 맛집 목록

##### 예외 및 경계 조건

- 선택한 카테고리에 맛집이 없으면 빈 목록을 제공한다.
- 사전 정의되지 않은 카테고리는 잘못된 요청으로 처리한다.

##### 인수 조건

- 음식 카테고리를 선택하면 해당 카테고리가 대표 카테고리인 맛집만 결과에 포함된다.
- 음식 카테고리 필터를 해제하면 해당 조건이 적용되지 않는다.
- 선택한 카테고리에 맛집이 없어도 서버 오류로 처리되지 않는다.

#### FR-CREATOR-001 유튜버 기준 방문 맛집 조회

##### 설명

일반 사용자는 특정 유튜버의 실제 방문이 확인된 맛집을 조회할 수 있어야 한다.

##### 사용자

- 일반 사용자

##### 선행 조건

- 유튜버 정보가 등록되어 있어야 한다.
- 맛집, 유튜버와 근거 영상을 연결한 유효한 방문 관계가 있어야 한다.

##### 입력 조건

- 유튜버 1명

##### 처리 규칙

- 선택한 유튜버가 포함된 유효한 방문 관계를 기준으로 맛집을 조회한다.
- 영상으로 확인되지 않은 추정 방문 정보는 사용하지 않는다.
- 필터를 지정하지 않으면 유튜버 조건을 적용하지 않는다.
- 한 번에 여러 유튜버를 선택하는 기능은 제공하지 않는다.

##### 결과

- 선택한 유튜버의 방문이 확인된 맛집 목록

##### 예외 및 경계 조건

- 유효한 방문 관계가 없으면 빈 목록을 제공한다.
- 존재하지 않거나 공개되지 않은 유튜버를 지정하면 잘못된 요청으로 처리한다.

##### 인수 조건

- 유효한 방문 관계가 있는 유튜버를 선택하면 연결된 맛집을 확인할 수 있다.
- 근거 영상이 없는 관계는 결과에 사용되지 않는다.
- 같은 유튜버가 여러 맛집을 방문한 경우 각 맛집을 결과에서 확인할 수 있다.
- 같은 맛집이 여러 유효한 관계로 연결되어도 결과에는 한 번만 표시된다.

#### FR-CREATOR-003 유튜버 필터 선택 목록 조회

##### 설명

일반 사용자는 유튜버 필터에 사용할 공개 유튜버의 최소 선택 목록을 조회할 수 있어야 한다.

##### 사용자

- 일반 사용자

##### 선행 조건

- 일반 사용자에게 공개된 유튜버 정보가 등록되어 있어야 한다.

##### 입력 조건

- 없음

##### 처리 규칙

- 공개 상태인 유튜버만 제공한다.
- 선택에 필요한 유튜버 식별자와 현재 YouTube 채널명만 제공한다.
- 채널명 오름차순으로 일관되게 제공한다.
- 유튜버 검색, 페이지네이션, 프로필, 구독자 정보와 상세 정보는 제공하지 않는다.

##### 결과

- 유튜버 식별자
- 현재 YouTube 채널명

##### 예외 및 경계 조건

- 공개 유튜버가 없으면 빈 목록을 정상 결과로 제공한다.
- 비공개 또는 삭제된 유튜버는 제공하지 않는다.

##### 인수 조건

- 공개 유튜버가 있으면 필터 선택 목록에서 식별자와 채널명을 확인할 수 있다.
- 비공개 또는 삭제된 유튜버가 목록에 포함되지 않는다.
- 공개 유튜버가 없어도 서버 오류로 처리되지 않는다.

#### FR-RESTAURANT-005 검색 및 필터 조건 조합

##### 설명

일반 사용자는 맛집 이름 검색과 지역, 음식 카테고리, 유튜버 필터를 함께 적용할 수 있어야 한다.

##### 사용자

- 일반 사용자

##### 선행 조건

- 각 검색 및 필터 기능을 사용할 수 있어야 한다.

##### 입력 조건

- 맛집 이름 검색어(선택)
- 서울특별시 자치구 1개(선택)
- 대표 음식 카테고리 1개(선택)
- 유튜버 1명(선택)

##### 처리 규칙

- 지정된 모든 검색 및 필터 조건을 동시에 만족하는 맛집만 조회한다.
- 지정하지 않은 조건은 결과 제한에 사용하지 않는다.
- 같은 종류의 필터에서 여러 값을 동시에 선택하는 기능은 제공하지 않는다.
- 검색 또는 필터 조건이 변경되면 첫 페이지부터 결과를 제공한다.

##### 결과

- 지정된 모든 조건을 만족하는 맛집 목록

##### 예외 및 경계 조건

- 모든 조건을 만족하는 맛집이 없으면 빈 목록을 제공한다.
- 조건 중 하나라도 유효하지 않으면 잘못된 요청으로 처리한다.

##### 인수 조건

- 검색어와 여러 필터를 함께 지정하면 모든 조건을 만족하는 맛집만 표시된다.
- 일부 조건을 지정하지 않으면 해당 조건 때문에 결과가 제한되지 않는다.
- 조건을 변경하면 변경된 조건의 첫 페이지 결과가 표시된다.
- 조건을 만족하는 맛집이 없어도 서버 오류로 처리되지 않는다.

#### FR-RESTAURANT-006 페이지 단위 조회

##### 설명

일반 사용자는 맛집 목록의 이전·다음 페이지 또는 특정 페이지로 이동할 수 있어야 한다.

##### 사용자

- 일반 사용자

##### 선행 조건

- 맛집 목록 조회 결과가 제공되어야 한다.

##### 입력 조건

- 페이지 번호
- 페이지 크기: 10, 20 또는 50 중 하나(선택)
- 현재 적용 중인 검색 및 필터 조건

##### 처리 규칙

- 같은 검색·필터·정렬 조건에서는 페이지마다 서로 구분되는 결과 범위를 제공한다.
- 페이지를 이동해도 현재 검색 및 필터 조건을 유지한다.
- 페이지 크기를 지정하지 않으면 20개를 적용한다.
- 무한 스크롤과 자동 추가 로딩은 제공하지 않는다.

##### 결과

- 요청한 페이지의 맛집 목록
- 페이지 이동에 필요한 정보

##### 예외 및 경계 조건

- 결과 범위를 벗어난 페이지는 빈 목록으로 제공한다.
- 유효하지 않은 페이지 번호 또는 페이지 크기는 잘못된 요청으로 처리한다.

##### 인수 조건

- 결과가 여러 페이지이면 이전·다음 또는 특정 페이지로 이동할 수 있다.
- 페이지를 이동해도 적용 중인 검색 및 필터 조건이 유지된다.
- 결과 범위를 벗어난 페이지 요청이 서버 오류로 처리되지 않는다.

#### FR-RESTAURANT-007 기본 정렬 적용

##### 설명

일반 사용자가 별도의 정렬 조건을 지정하지 않아도 맛집 목록은 서비스가 정한 기본 순서로 제공되어야 한다.

##### 사용자

- 일반 사용자

##### 선행 조건

- 맛집 목록을 조회할 수 있어야 한다.

##### 입력 조건

- 검색 및 필터 조건(선택)

##### 처리 규칙

- 모든 맛집 목록에 하나의 기본 정렬 기준을 일관되게 적용한다.
- 맛집 이름 오름차순으로 정렬하고, 이름이 같으면 전체 도로명주소 오름차순으로 정렬한다.
- 인기순, 추천순과 개인화 정렬은 사용하지 않는다.

##### 결과

- 기본 정렬이 적용된 맛집 목록

##### 예외 및 경계 조건

- 정렬 기준의 값이 같은 맛집도 페이지 이동 중 누락되거나 중복 표시되지 않아야 한다.

##### 인수 조건

- 동일한 데이터와 조회 조건으로 요청하면 같은 기본 정렬 기준이 적용된다.
- 페이지를 순서대로 조회할 때 같은 맛집이 정렬 문제로 중복 표시되지 않는다.
- 인기 또는 추천 정보가 기본 정렬의 근거로 노출되지 않는다.

### 3.3 유튜버 정보 확인

#### FR-CREATOR-002 방문 유튜버 정보 확인

##### 설명

일반 사용자는 맛집 목록과 상세에서 해당 맛집의 방문이 확인된 유튜버 정보를 확인할 수 있어야 한다.

##### 사용자

- 일반 사용자

##### 선행 조건

- 맛집, 유튜버와 근거 영상을 연결한 유효한 방문 관계가 있어야 한다.

##### 입력 조건

- 맛집 식별자

##### 처리 규칙

- 관리자가 영상으로 실제 방문을 검증한 유튜버만 제공한다.
- 맛집 목록에는 YouTube 채널명을 제공한다.
- 맛집 목록에는 중복을 제거한 채널명을 채널명 오름차순으로 최대 3명까지 제공하고, 4명 이상이면 나머지 인원수를 `외 N명`으로 표시할 수 있게 한다.
- 맛집 상세에는 YouTube 채널명과 채널 링크를 제공한다.
- 하나의 맛집에 여러 유튜버가 연결될 수 있다.
- 하나의 유튜버는 여러 맛집과 연결될 수 있다.
- 같은 유튜버가 같은 맛집에 여러 영상으로 연결되어도 유튜버 목록에는 한 번만 표시한다.

##### 결과

- 유튜버 식별자
- YouTube 채널명
- 맛집 상세에서 확인할 수 있는 YouTube 채널 링크

##### 예외 및 경계 조건

- 유효한 방문 관계가 없으면 빈 유튜버 목록을 제공한다.
- 공개되지 않거나 삭제된 유튜버와 방문 관계는 제공하지 않는다.
- 채널 링크가 유효하지 않아도 맛집 기본 정보와 YouTube 채널명은 제공한다.
- 방문 관계·유튜버·영상 정보 제공 과정이 실패하면 정상적인 빈 목록과 구분되는 일시적 콘텐츠 조회 실패로 처리하고 맛집 기본 정보는 제공한다.

##### 인수 조건

- 유효한 방문 관계가 있으면 맛집에서 연결된 유튜버를 확인할 수 있다.
- 한 맛집에 여러 유튜버가 방문했으면 각 유튜버를 확인할 수 있다.
- 같은 유튜버가 여러 관계로 연결되어도 중복 표시되지 않는다.
- 방문 관계가 없으면 빈 목록이 표시되고 서버 오류로 처리되지 않는다.

## 4. 관리자 기능

### 4.1 맛집 정보 등록

#### FR-ADMIN-001 관리자 등록 기능 접근

##### 설명

사전에 발급된 관리자 계정으로 인증한 관리자만 데이터 등록 기능에 접근할 수 있어야 한다.

- 관리자

##### 선행 조건

- 관리자 계정이 사전에 발급되어 있어야 한다.

##### 입력 조건

- 관리자 인증 정보

##### 처리 규칙

- 인증된 관리자에게만 맛집, 유튜버, 영상과 방문 관계 등록 기능을 제공한다.
- 모든 관리자는 같은 데이터 등록 권한을 가진다.
- 서비스 내 관리자 회원가입, 관리자 등급과 기능별 권한 세분화는 제공하지 않는다.

##### 예외 및 경계 조건

- 인증되지 않았거나 유효한 관리자 권한이 없는 요청은 접근을 거부한다.
- 일반 사용자는 관리자 등록 기능을 사용할 수 없다.

##### 인수 조건

- 사전 발급된 유효한 관리자 계정으로 인증하면 등록 기능에 접근할 수 있다.
- 인증하지 않은 사용자는 등록 기능에 접근할 수 없다.
- 일반 사용자 조회 기능은 관리자 인증 없이 사용할 수 있다.

#### FR-ADMIN-002 맛집 정보 등록

##### 설명

관리자는 검증한 맛집 기본 정보를 등록하여 일반 사용자 탐색 대상으로 제공할 수 있어야 한다.

##### 사용자

- 관리자

##### 선행 조건

- 관리자가 인증되어 있어야 한다.
- 관리자가 카카오에서 동일한 장소를 확인하고 장소 일치 여부를 검증해야 한다.

##### 입력 조건

- 맛집 이름
- 카카오에서 확인한 동일 장소 정보와 카카오 장소 링크
- 서울특별시 내 전체 도로명주소
- 전화번호
- 사전 정의된 대표 음식 카테고리 1개
- 필요한 경우 건물명, 층 또는 호수 등 상세 위치
- `기타` 카테고리인 경우 실제 음식 종류를 확인할 수 있는 기록

##### 처리 규칙

- 관리자가 검증한 정보만 등록한다.
- 카카오에서 같은 장소로 확인되는 기존 맛집이 있으면 새로 등록하지 않고 기존 정보를 사용한다.
- 상호명이 같아도 카카오에서 다른 지점으로 확인되면 별도 맛집으로 등록할 수 있다.
- 대표 음식 카테고리는 사전 정의된 값 중 정확히 1개를 지정한다.
- 맛집의 주된 메뉴와 영업 정체성을 가장 잘 나타내는 카테고리를 지정하며, 판단 근거가 부족하면 등록을 보류한다.
- `기타`를 지정하면 별도 구체 음식 종류를 저장하지 않고 대표 카테고리 `기타`만 기록한다.
- 영상 또는 방문 관계가 없어도 맛집을 등록할 수 있다.
- 등록 외 수정, 삭제와 승인 상태 관리는 제공하지 않는다.

##### 결과

- 등록된 맛집 정보
- 사용자 목록, 검색, 필터와 상세 조회에 반영된 맛집

##### 예외 및 경계 조건

- 필수 정보가 누락되거나 유효하지 않으면 등록하지 않고 오류를 제공한다.
- 카카오 장소와의 동일 여부를 판단할 수 없으면 등록을 보류하고 관리자 확인이 필요함을 알린다.
- 동일 장소가 이미 등록되어 있으면 중복 등록하지 않고 기존 맛집 정보를 안내한다.
- 서울특별시 밖의 장소는 등록하지 않는다.

##### 인수 조건

- 필수 정보를 모두 갖춘 검증된 맛집을 등록할 수 있다.
- 등록된 공개 맛집은 일반 사용자 목록, 이름 검색, 필터와 상세 조회에 반영된다.
- 영상 정보가 없어도 맛집을 등록하고 일반 사용자에게 기본 정보를 제공할 수 있다.
- 같은 카카오 장소를 다시 등록해도 맛집이 중복 생성되지 않는다.
- 대표 음식 카테고리가 없으면 등록되지 않는다.

관리자는 검증한 YouTube 채널을 유튜버 정보로 등록하여 방문 관계와 사용자 조회에서 사용할 수 있어야 한다.

##### 사용자

- 관리자

##### 선행 조건

- 관리자가 인증되어 있어야 한다.
- 등록할 유튜버 또는 채널의 정보를 관리자가 검증해야 한다.

##### 입력 조건

- YouTube 채널 링크

##### 처리 규칙

- YouTube 채널을 유튜버 정보의 고유한 관리 단위로 사용한다.

- YouTube API로 채널 존재와 현재 채널 정보를 조회하고 관리자가 확인한 결과를 저장한다.
- 자동 주기 동기화는 수행하지 않는다.
- 등록 외 수정, 삭제와 승인 상태 관리는 제공하지 않는다.

##### 결과

- 등록된 유튜버 정보
- 방문 관계와 사용자 조회에서 선택할 수 있는 유튜버

##### 예외 및 경계 조건

- 동일 채널 여부를 판단할 수 없으면 등록을 보류하고 관리자 확인이 필요함을 알린다.
- 동일한 YouTube 채널이 이미 등록되어 있으면 기존 유튜버 정보를 안내한다.

##### 인수 조건

- 필수 정보를 모두 갖춘 검증된 유튜버를 등록할 수 있다.
- 등록된 유튜버를 방문 관계 등록에 사용할 수 있다.
- 동일한 YouTube 채널을 다시 등록해도 유튜버가 중복 생성되지 않는다.
- 필수 정보가 누락되면 등록되지 않는다.

### 4.3 영상 정보 등록

### 4.4 방문 관계 등록

#### FR-VISIT-001 맛집·유튜버·영상 방문 관계 등록

##### 설명

관리자는 특정 유튜버가 특정 맛집을 실제로 방문했음을 확인한 영상을 근거로 방문 관계를 등록할 수 있어야 한다.

##### 사용자

- 관리자

##### 선행 조건

- 관리자가 인증되어 있어야 한다.
- 연결할 맛집, 유튜버와 영상 정보가 먼저 등록되어 있어야 한다.
- 관리자가 영상에서 해당 유튜버의 해당 맛집 실제 방문을 확인해야 한다.
- 선택한 영상은 선택한 유튜버와 연결된 영상이어야 한다.

##### 입력 조건

- 등록된 맛집 1개
- 등록된 유튜버 1명
- 방문 근거가 되는 등록된 영상 1개

##### 처리 규칙

- 하나의 방문 관계는 맛집 1개, 유튜버 1명과 근거 영상 1개를 연결한다.
- 하나의 맛집에는 여러 유튜버가 연결될 수 있다.
- 하나의 유튜버는 여러 맛집과 연결될 수 있다.
- 하나의 영상에는 하나 이상의 맛집이 연결될 수 있으며, 맛집마다 방문 관계를 구분해 등록한다.
- 동일한 맛집·유튜버·영상 조합은 중복 등록하지 않고 기존 관계를 사용한다.
- 영상이 없는 방문 관계 또는 추정에 근거한 방문 관계는 등록하지 않는다.
- MVP에서는 실제 방문 날짜를 별도로 관리하지 않고 영상 게시일을 방문 날짜로 사용하지 않는다.
- 관리자가 실제 방문 근거를 확인하고 등록을 완료한 관계를 검증된 관계로 취급하며 별도 검증 상태는 두지 않는다.
- 등록된 관계는 유튜버별 필터, 맛집의 방문 유튜버와 관련 영상 조회에 반영한다.
- 등록 외 수정, 삭제와 승인 상태 관리는 제공하지 않는다.

##### 결과

- 등록된 방문 관계
- 사용자 탐색과 맛집 상세에 반영된 유튜버 및 관련 영상 정보

##### 예외 및 경계 조건

- 맛집, 유튜버 또는 영상 중 하나라도 존재하지 않으면 관계를 등록하지 않는다.
- 선택한 영상의 게시 채널과 선택한 유튜버가 동일한 YouTube 채널이 아니면 관계를 등록하지 않는다.
- 영상에서 실제 방문을 확인할 수 없으면 관계를 등록하지 않는다.
- 동일한 조합이 이미 등록되어 있으면 중복 등록하지 않고 기존 관계를 안내한다.
- 동일 여부를 판단할 수 없으면 등록을 보류하고 관리자 확인이 필요함을 알린다.

##### 인수 조건

- 사전에 등록된 맛집, 유튜버와 근거 영상을 선택해 방문 관계를 등록할 수 있다.
- 등록된 관계의 맛집은 해당 유튜버 필터 결과에 나타난다.
- 등록된 관계의 유튜버와 영상은 해당 맛집 상세에서 확인할 수 있다.
- 하나의 영상에 여러 맛집이 등장하면 각 맛집에 대한 관계를 별도로 등록할 수 있다.
- 존재하지 않는 대상이나 근거 영상이 없는 관계는 등록되지 않는다.
- 동일한 맛집·유튜버·영상 조합을 다시 등록해도 관계가 중복 생성되지 않는다.

## 5. 공통 기능 규칙

### 5.1 사용자와 접근

- 일반 사용자 조회 기능은 회원가입과 로그인 없이 사용할 수 있어야 한다.
- MVP는 일반 사용자 계정과 사용자별 데이터를 관리하지 않는다.
- 일반 사용자는 맛집, 유튜버, 영상과 방문 관계를 등록하거나 수정할 수 없다.
- 관리자 등록 기능은 일반 사용자 기능과 분리하고 관리자 권한을 검증해야 한다.
- 관리자 전용 로그인은 일반 사용자 로그인 기능으로 보지 않는다.

### 5.2 조회 결과와 오류

- 목록 조회 조건에 맞는 데이터가 없으면 빈 목록을 정상 결과로 제공해야 한다.
- 존재하지 않거나 공개되지 않은 단일 맛집 조회는 찾을 수 없음으로 처리해야 한다.
- 유효하지 않은 페이지, 필터 값과 요청 조건은 잘못된 요청임을 구분할 수 있는 오류로 처리해야 한다.
- 삭제되거나 비공개 상태인 맛집, 유튜버, 영상과 방문 관계는 일반 사용자 조회 결과에 포함하지 않아야 한다.
- 같은 맛집, 유튜버 또는 영상은 한 조회 결과에 중복 표시하지 않아야 한다.
- 외부 YouTube 또는 카카오 링크가 유효하지 않더라도 맛집 기본 정보 조회는 가능해야 한다.
- 맛집 기본 정보 제공자가 실패하면 상세 전체를 실패 처리한다.
- 방문 관계·유튜버·영상 정보 제공자만 실패하면 맛집 기본 정보는 제공하고, 정상적인 콘텐츠 없음과 구분되는 일시적 콘텐츠 조회 실패로 처리한다.

### 5.3 검색과 필터

- 맛집 이름 검색어의 앞뒤 공백은 제거한다.
- 앞뒤 공백 제거 후 검색어가 비어 있으면 맛집 이름 조건을 적용하지 않는다.
- 영문 검색어는 대소문자를 구분하지 않는다.
- 검색어는 맛집 이름의 일부와 일치할 수 있다.
- 검색과 서로 다른 필터를 함께 사용하면 지정된 모든 조건을 만족하는 결과만 제공한다.
- 지역, 유튜버와 음식 카테고리 필터는 종류별로 한 번에 하나의 값만 선택할 수 있다.
- 지정하지 않은 검색 또는 필터 조건은 적용하지 않는다.
- 검색 또는 필터 조건이 변경되면 첫 페이지부터 결과를 제공한다.

### 5.4 등록과 검증

- 관리자가 출처와 사실 관계를 검증한 데이터만 등록해야 한다.
- 등록 요청의 필수 정보가 누락되거나 유효하지 않으면 등록하지 않아야 한다.
- 동일한 맛집, 유튜버, 영상과 방문 관계는 중복 등록하지 않아야 한다.
- 동일 대상에 대한 요청이 동시에 처리되어도 하나의 데이터 또는 관계만 등록해야 한다.
- 동일 여부를 판단할 수 없으면 임의로 병합하거나 새로 등록하지 않고 관리자 확인을 위해 등록을 보류해야 한다.
- 보류한 요청은 관리자가 재검증한 뒤 신규 등록, 기존 대상 사용 또는 등록 거부로 종결해야 한다.
- 등록이 완료된 공개 정보와 방문 관계는 관련 일반 사용자 조회 기능에 반영되어야 한다.
- MVP 관리자 등록은 YouTube API 조회 결과를 포함한 출처를 관리자가 확인한 뒤 등록하며, MVP 관리자 등록에는 관리자 확인 없는 자동 등록·자동 주기 동기화와 AI 판정을 포함하지 않는다. 3차 AI 등록은 `FR-AIEXTRACT-003`의 자동 검증 경계를 따른다.

| 방문 유튜버 정보 확인 | 등록된 유튜버와 유효한 방문 관계 | 맛집에 연결된 공개 유튜버만 제공한다. |
| 관련 영상 정보 확인 | 등록된 영상과 유효한 방문 관계 | 맛집에 근거 영상으로 연결된 공개 영상만 제공한다. |
| 맛집 정보 등록 | 관리자 인증, 검증된 카카오 장소 정보 | 방문 관계나 영상 없이 독립적으로 등록할 수 있다. |
| 유튜버 정보 등록 | 관리자 인증, 검증된 YouTube 채널 정보 | 등록 결과는 방문 관계에서 사용할 수 있다. |
| 영상 정보 등록 | 관리자 인증, 검증된 YouTube 영상 정보 | 영상 원본은 저장하지 않고 표시와 식별에 필요한 정보만 등록한다. |
| 방문 관계 등록 | 관리자 인증, 등록된 맛집·유튜버·영상 | 세 대상과 실제 방문 근거가 모두 존재해야 한다. |
| 일반 사용자 조회 반영 | 관리자 등록 결과 | 공개된 등록 정보와 관계는 관련 목록, 필터와 상세 조회에 반영되어야 한다. |
| 개인 컬렉션 | 회원 인증, 맛집 공개 상태 | 본인 컬렉션에 공개·활성 맛집만 새로 포함하고 탈퇴 시 회원 소유 관계를 정리한다. |
| 인기 맛집 | 찜, 맛집 공개 상태 | 현재 찜 관계 수만 실시간 집계하고 공개·활성 맛집 상위 20개를 제공한다. |
| 관리자 큐레이션 | 관리자 인증, 맛집 공개 상태 | 관리자가 공개 맛집을 직접 편집하고 게시 중인 큐레이션만 일반 사용자에게 노출한다. |
| 사용자 제보 | 회원 인증, 관리자 등록 검증 | 승인 뒤 기존 등록 검증을 통과한 신규 정보·관계만 공개 데이터로 반영한다. |
| 사용자 신고 | 회원 인증, 관리자 정정·공개 상태 처리 | 신고만으로 자동 비공개하지 않고 관리자가 근거 확인 뒤 수동 처리한다. |
| 사용자 알림 | 회원 식별, 제보·신고 상태 전이 | 승인된 상태 변경과 서비스 내 알림을 원자적으로 저장한다. |

- 특정 지역, 음식 카테고리, 유튜버 또는 영상 데이터가 없어도 의존하지 않는 다른 탐색 기능은 정상 동작해야 한다.
- 외부 영상 링크가 유효하지 않거나 관련 영상 정보가 없어도 맛집 목록과 기본 상세 조회는 정상 동작해야 한다.
- 방문 관계가 비공개 또는 삭제 상태가 되면 해당 관계를 사용하는 유튜버 필터와 관련 정보에서 노출하지 않아야 한다.

## 8. 1차 확장 기능

아래 요구사항은 확정된 1차 확장 범위다. 회원 식별자는 인증된 현재 회원만 사용하며, 공개 조회의 기본 접근성은 개인화 기능의 장애로 제한하지 않는다.

<a id="fr-member-001-이메일-회원가입"></a>

### FR-MEMBER-001 이메일 회원가입

- 사용자는 중복되지 않는 이메일과 비밀번호로 가입을 시작하고 이메일 인증 전에는 로그인할 수 없다.
- 인증 메일 발송 결과는 계정 존재 여부를 외부에 누설하지 않는다.

<a id="fr-member-002-이메일-인증"></a><a id="fr-member-002-가입-이메일-인증"></a>

### FR-MEMBER-002 가입 이메일 인증

- 사용자는 이메일로 받은 8자 1회용 인증 코드로 가입을 완료해 `ACTIVE` 상태가 된다.
- 인증 코드는 암호학적으로 안전한 난수 생성기로 만들고 사람이 혼동하기 쉬운 문자를 제외한 영문 대문자·숫자를 사용한다.
- 만료·사용·폐기 Token은 계정을 활성화하지 않는다.

<a id="fr-member-003-비밀번호-재설정"></a>

### FR-MEMBER-003 비밀번호 재설정

- 사용자는 이메일 기반 1회용 Token으로 비밀번호를 재설정할 수 있다.
- 요청·완료 응답은 계정 존재 여부를 누설하지 않고, 재설정 뒤 기존 세션을 폐기한다.

<a id="fr-member-004-회원-탈퇴"></a>

### FR-MEMBER-004 회원 탈퇴

- `ACTIVE` 회원은 본인 확인 뒤 탈퇴를 요청할 수 있고 즉시 인증·개인화 접근이 차단된다.
- 세션·인증 Token·찜·최근 기록을 정리한 뒤 회원 개인정보를 물리 삭제한다.

<a id="fr-member-005-현재-회원-정보"></a><a id="fr-member-005-현재-사용자-정보-조회"></a>

### FR-MEMBER-005 현재 사용자 정보 조회

- 인증된 회원은 자신의 불투명 식별자와 이메일만 조회할 수 있다.
- 다른 회원 식별자 입력이나 관리자 계정 정보 조회는 제공하지 않는다.

<a id="fr-auth-001-회원-로그인로그아웃"></a><a id="fr-auth-001-로그인과-활성-세션-발급"></a>

### FR-AUTH-001 로그인과 활성 세션 발급

- `ACTIVE` 회원은 이메일과 비밀번호로 로그인해 활성 세션을 발급받을 수 있다.
- 실패 제한을 초과한 로그인과 비활성·탈퇴 계정은 Token을 발급하지 않는다.

<a id="fr-auth-002-회원-token-재발급"></a><a id="fr-auth-002-access-token-재발급"></a>

### FR-AUTH-002 Access Token 재발급

- 회원은 유효한 Refresh Token으로 Access Token을 재발급받고 Refresh Token은 원자적으로 회전한다.
- 재사용·만료·폐기 Refresh Token과 Redis 장애는 fail-closed로 처리한다.

<a id="fr-auth-003-다중-로그인-세션-관리"></a><a id="fr-auth-003-로그아웃"></a>

### FR-AUTH-003 로그아웃과 다중 로그인 세션 관리

- 회원은 로그아웃으로 현재 세션을 폐기할 수 있다.
- 회원은 최대 3개의 활성 세션을 유지하며 새 세션이 한도를 넘으면 가장 오래된 세션을 폐기한다.
- 탈퇴·로그아웃·재사용 탐지로 폐기된 `sid`는 Access Token 만료까지 거부한다.

<a id="fr-favorite-001-맛집-찜-추가"></a>

### FR-FAVORITE-001 맛집 찜 추가

- 로그인 회원은 공개 맛집을 찜할 수 있고, 이미 찜한 경우에도 같은 성공 상태를 반환한다.

<a id="fr-favorite-002-맛집-찜-해제"></a>

### FR-FAVORITE-002 맛집 찜 해제

- 로그인 회원은 자신의 찜을 해제할 수 있고, 없는 관계의 반복 해제도 같은 성공 상태를 반환한다.

<a id="fr-favorite-003-맛집별-찜-상태-확인"></a><a id="fr-favorite-003-맛집별-현재-회원-찜-상태-확인"></a>

### FR-FAVORITE-003 맛집별 현재 회원 찜 상태 확인

- 로그인 회원은 공개 맛집 하나에 대한 자신의 찜 여부를 확인할 수 있다.

<a id="fr-favorite-004-찜-목록-조회"></a>

### FR-FAVORITE-004 찜 목록 조회

- 로그인 회원은 공개 상태인 자신의 찜을 최신순 페이지 목록으로 조회할 수 있다.
- 목록 조회는 데이터를 정리하지 않고 유효·공개 관계만 필터링한다.

<a id="fr-recent-001-최근-본-맛집-기록"></a>

### FR-RECENT-001 최근 본 맛집 기록

- 유효 회원이 공개 맛집 상세를 성공적으로 조회하면 최근 기록을 upsert하고 같은 맛집은 조회 시각만 갱신한다.
- 인증·개인화 저장소·기록 저장 실패는 공개 상세 성공 응답을 실패시키지 않으며 기록만 생략한다.

<a id="fr-recent-002-최근-본-맛집-목록-조회"></a>

### FR-RECENT-002 최근 본 맛집 목록 조회

- 로그인 회원은 유효·공개 최근 기록을 최신순 페이지 목록으로 조회할 수 있다.
- 목록 조회는 데이터를 삭제하지 않고 보존 기간과 공개 상태를 필터링한다.

<a id="fr-recent-003-최근-기록-개별-삭제"></a><a id="fr-recent-003-최근-본-맛집-개별-삭제"></a>

### FR-RECENT-003 최근 본 맛집 개별 삭제

- 로그인 회원은 자신의 최근 기록 하나를 멱등적으로 삭제할 수 있다.

<a id="fr-map-001-지도-기반-맛집-탐색"></a><a id="fr-map-001-kakao-지도와-맛집-마커-표시"></a>

### FR-MAP-001 Kakao 지도와 맛집 마커 표시

- 사용자는 이름·자치구·음식 카테고리·유튜버 탐색 조건에 맞는 공개 맛집 마커와 대체 목록을 조회할 수 있다.
- 좌표 없는 맛집은 지도에서만 제외하고 기존 목록·상세에서는 유지한다.

<a id="fr-map-002-지도-접근성장애-격리"></a><a id="fr-map-002-지도-영역과-탐색-조건-조합-조회"></a>

### FR-MAP-002 지도 이동과 탐색 결과 유지

- 사용자는 마커와 목록 선택을 동기화하고 키보드·스크린 리더·모바일에서도 대체 목록을 이용할 수 있다.
- 지도 이동·확대·축소는 서버 조회 조건을 변경하거나 이미 조회한 마커·대체 목록을 제거하지 않는다.
- 서버 조회는 URL의 이름·자치구·음식 카테고리·유튜버 조건이 변경될 때 수행한다.
- 지도 SDK·키·호출 제한 오류는 공개 탐색 자체를 실패시키지 않는다.

<a id="fr-creator-004-유튜버-상세-정보-조회"></a>

### FR-CREATOR-004 유튜버 상세 정보 조회

- 사용자는 공개 Creator의 저장된 채널 표시 정보를 조회할 수 있다.

<a id="fr-creator-005-유튜버-방문-맛집-목록-조회"></a><a id="fr-creator-005-유튜버의-방문-맛집-목록-조회"></a>

### FR-CREATOR-005 유튜버의 방문 맛집 목록 조회

- 사용자는 공개·유효 Visit에 연결된 Creator의 방문 맛집을 최신 등록순 페이지 목록으로 조회할 수 있다.

<a id="fr-creator-006-유튜버-근거-영상-목록-조회"></a><a id="fr-creator-006-유튜버의-근거-영상-목록-조회"></a>

### FR-CREATOR-006 유튜버의 근거 영상 목록 조회

- 사용자는 공개·유효 Visit에 연결된 Creator의 근거 영상을 최신 등록순 페이지 목록으로 조회할 수 있다.
- 사용자 조회 중 YouTube API를 실시간 호출하지 않는다.

## 9. 2차 확장 기능

아래 요구사항은 2026-08-03 승인된 2차 확장 초기 범위다. 개인 컬렉션·제보·신고·사용자 알림은 인증된 현재 회원만 본인 자원에 접근하며, 인기 맛집·게시 중인 관리자 큐레이션은 일반 사용자에게 공개한다.

### 9.1 개인 컬렉션

<a id="fr-collection-001-개인-컬렉션-생성"></a>

### FR-COLLECTION-001 개인 컬렉션 생성

- 로그인 회원은 이름을 지정해 본인만 접근하는 개인 컬렉션을 만들 수 있다.
- 회원별 컬렉션이 20개이면 새 컬렉션을 만들 수 없다.

<a id="fr-collection-002-개인-컬렉션-이름-변경"></a>

### FR-COLLECTION-002 개인 컬렉션 이름 변경

- 로그인 회원은 자신이 소유한 컬렉션의 이름을 변경할 수 있다.
- 이름 변경 성공 시 컬렉션의 최근 수정 시각을 갱신한다.

<a id="fr-collection-003-개인-컬렉션-삭제"></a>

### FR-COLLECTION-003 개인 컬렉션 삭제

- 로그인 회원은 자신이 소유한 컬렉션과 그 맛집 포함 관계를 삭제할 수 있다.
- 컬렉션 삭제는 맛집, 찜과 다른 컬렉션의 관계를 변경하지 않는다.

<a id="fr-collection-004-개인-컬렉션-조회"></a>

### FR-COLLECTION-004 개인 컬렉션 조회

- 로그인 회원은 자신의 컬렉션 목록을 최근 수정순으로 조회하고 컬렉션 하나의 공개·활성 맛집을 추가 최신순으로 조회할 수 있다.
- 다른 회원의 컬렉션은 존재 여부를 포함해 조회할 수 없다.

<a id="fr-collection-005-컬렉션-맛집-추가"></a>

### FR-COLLECTION-005 컬렉션 맛집 추가

- 로그인 회원은 공개·활성 맛집을 자신이 소유한 컬렉션에 추가할 수 있다.
- 같은 컬렉션의 같은 맛집을 반복 추가해도 중복 관계를 만들지 않으며, 한 맛집은 여러 컬렉션에 포함할 수 있다.
- 컬렉션에 맛집이 100개이면 새 맛집을 추가할 수 없다.

<a id="fr-collection-006-컬렉션-맛집-제거"></a>

### FR-COLLECTION-006 컬렉션 맛집 제거

- 로그인 회원은 자신이 소유한 컬렉션에서 맛집을 제거할 수 있다.
- 없는 관계를 반복 제거해도 다른 자원을 변경하지 않는다.

직접 순서 변경은 승인 범위가 아니다. 컬렉션과 항목은 각각 최근 수정순·추가 최신순으로만 제공한다.

## 10. 3차 확장 기능

아래 요구사항은 2026-08-10 승인된 3차 확장 초기 범위다. 자연어 검색은 기존 맛집 조건 해석, AI 영상 정보 추출은 자동 검증 통과 결과의 자동 등록·공개와 예외 보정, 동선 및 코스 추천은 사용자가 고른 맛집의 자동차 이동 순서 제안으로 제한한다.

### 10.1 자연어 검색

<a id="fr-nlsearch-001-자연어-검색-요청과-결과-조회"></a>

### FR-NLSEARCH-001 자연어 검색 요청과 결과 조회

- 사용자는 자연어 문장 하나를 제출하고 서버가 해석한 맛집 이름·서울 자치구·음식 카테고리·유튜버·관리자 확정 태그 조건 요약과 기존 공개 맛집 목록을 함께 조회할 수 있다.
- 결과는 기존 맛집 목록의 페이지·정렬·공개 상태 의미를 따르며 자연어 검색 전용 추천 순위, 생성 답변과 선정 이유를 만들지 않는다.

<a id="fr-nlsearch-002-자연어-조건과-직접-필터-조합"></a>

### FR-NLSEARCH-002 자연어 조건과 직접 필터 조합

- 사용자는 자연어 문장과 기존 구조화 필터를 한 요청에서 함께 지정할 수 있다.
- 같은 조건 종류가 충돌하면 사용자가 직접 지정한 필터를 적용하고, 자연어에서 해석했지만 적용하지 않은 조건을 해석 요약에서 구분한다.
- 서로 다른 조건 종류는 기존 목록 조회와 같은 AND 의미로 조합한다.

<a id="fr-nlsearch-003-빈-결과와-해석-실패"></a>

### FR-NLSEARCH-003 빈 결과와 해석 실패

- 유효한 조건을 해석했지만 일치하는 맛집이 없으면 정상 빈 목록과 적용 조건 요약을 반환한다.
- 지원 조건을 하나도 해석하지 못했거나 미지원 조건만 있으면 전체 맛집 목록으로 대체하지 않고 해석 실패·미지원 조건을 구분해 알린다.
- 사용자는 실패 뒤 기존 구조화 필터로 다시 검색할 수 있으며 기존 목록·상세 기능은 영향을 받지 않는다.

<a id="fr-nlsearch-004-확정-태그-조건과-결과-조회"></a>

### FR-NLSEARCH-004 확정 태그 조건과 결과 조회

- 사용자는 관리자 확정 태그를 자연어 조건 또는 직접 지정 조건으로 사용해 공개 맛집 목록을 조회할 수 있다.
- 태그가 여러 개 적용되면 하나의 유효한 방문 관계에 연결된 모든 태그를 만족하는 맛집만 반환한다.
- AI 추출 후보 또는 검수되지 않은 태그는 검색 조건과 결과에 사용하지 않는다.

### 10.2 AI 기반 영상 정보 추출

<a id="fr-aiextract-001-ai-영상-추출-작업-요청"></a>

### FR-AIEXTRACT-001 AI 영상 추출 작업 요청

- 인증된 관리자는 신규 영상 추가 화면에서 YouTube URL과 선택적 보완 텍스트로 비동기 추출 작업을 요청할 수 있다.
- 관리자가 활성화한 YouTube 채널에서 신규 영상 Webhook이 수신되면 시스템은 동일한 비동기 추출·검수 흐름으로 작업을 접수한다. Webhook 수신은 정식 `Restaurant`, `Creator`, `Video`, `Visit` 생성이나 공개를 뜻하지 않는다.
- Webhook 경로는 공개 YouTube URL을 Google Gemini API 영상 입력으로 전달해 분석할 수 있으며, 전체 영상·자막·전사를 애플리케이션에 자동 수집·저장하지 않는다.
- Gemini 영상 입력이 접근 불가·정책 제한·시간 초과·분석 실패이면 작업을 실패 또는 부분 추출로 기록하고, 관리자가 보완 텍스트를 추가해 재시도할 수 있어야 한다.
- 요청 성공은 추출 작업 접수를 뜻한다. 작업이 자동 검증을 통과하면 관리자 승인 없이 `Restaurant`, `Creator`, `Video`, `Visit` 생성과 공개까지 수행할 수 있다.
- 같은 영상·입력·모델·Prompt·결과 Schema 버전의 작업이 이미 존재하면 중복 작업을 만들지 않고 기존 작업을 안내한다.

<a id="fr-aiextract-002-추출-상태와-결과-조회"></a>

### FR-AIEXTRACT-002 추출 상태와 결과 조회

- 인증된 관리자는 본인이 접근 가능한 추출 작업의 `QUEUED`, `RUNNING`, `SUCCEEDED`, `FAILED` 상태와 생성·시작·종료 시각을 조회할 수 있다.
- 성공 결과에서는 맛집명·메뉴·주소 또는 위치 표현·방문 여부·통제 태그 후보와 필드별 신뢰도·출처 구간·모델·Prompt·Schema 버전을 확인할 수 있다.
- 실패 결과에서는 시간 초과·호출 제한·제공자 장애·응답 검증 실패 등 재시도 판단에 필요한 오류 범주를 확인할 수 있으며 비밀정보와 입력 원문은 노출하지 않는다.

<a id="fr-aiextract-003-자동-확정예외-보정폐기"></a>

### FR-AIEXTRACT-003 자동 확정·예외 보정·폐기

- 시스템은 성공한 후보를 등록 단위별로 자동 검증해 `AUTO_CONFIRMED`, `AUTO_BLOCKED` 또는 `AUTO_REJECTED`로 전환한다. 한 작업이 여러 등록 단위를 가질 수 있으며 판정은 단위별로 독립적이다.
- 장소 동일성은 시스템이 상호명·주소 후보로 Kakao 장소를 검색해 판정하고, 대표 음식 카테고리는 확정한 Kakao 장소 분류와 메뉴 후보로 결정한다. 두 판정 모두 관리자 선택을 요구하지 않는다.
- `AUTO_CONFIRMED`일 때 맛집 동일성·주소·영상 메타데이터·방문 근거를 확인하고 기존 Kakao 장소·YouTube·Visit 검증을 모두 통과한 결과를 관리자 승인 없이 정식 등록·공개한다.
- 인증된 관리자는 아직 등록되지 않은 등록 단위의 등록을 한 번의 요청으로 실행할 수 있고, 시스템은 맛집·유튜버·영상·방문 관계 4종을 이어서 등록하고 결과만 반환한다. 관리자는 장소 후보·주소 힌트·Kakao 장소 URL·음식 카테고리를 입력하지 않는다.
- 관리자 실행 경로는 Worker 자동 등록과 같은 판정 규칙을 사용하며, 정의된 예외 사유에 해당할 때만 보조 입력 경로로 전환한다.
- `AUTO_BLOCKED`·`AUTO_REJECTED` 등록 단위는 정식 Entity와 기존 공개 상태를 변경하지 않는다. 같은 작업의 다른 등록 단위가 통과했다면 그 단위의 등록은 그대로 유지한다. 관리자는 사후 보정·롤백할 수 있다.

<a id="fr-aiextract-007-ai-태그-후보-생성과-확정"></a>

### FR-AIEXTRACT-007 AI 태그 후보 생성과 확정

- 시스템은 영상 자막에서 태그 후보를 생성하고, 정규화·중복·금지 표현·근거 검사를 통과한 후보만 자동 태그로 등록한다.
- 태그 후보에는 자막 출처 구간과 신뢰도를 포함하며, 근거 없는 가격·품질·영업 상태 태그는 등록하지 않는다.
- 자동 태그 등록은 관리자 승인 없이 수행하고, 관리자는 사후 통합·폐기·롤백을 수행할 수 있다.
- 자동 검증을 통과한 `Visit`에만 태그를 연결하고 일반 사용자 검색에 공개한다.

<a id="fr-aiextract-004-신규-영상-webhook-감지와-작업-등록"></a>

### FR-AIEXTRACT-004 신규 영상 Webhook 감지와 작업 등록

- 관리자가 명시적으로 활성화한 YouTube 채널의 신규 영상 알림을 수신하면 채널·영상 식별자와 수신 시각을 검증하고 추출 작업을 등록한다.
- Webhook 수신 처리는 외부 AI 호출이나 정식 Entity 저장을 수행하지 않고 빠르게 작업 접수 결과만 확정한다.
- 동일 영상이 Webhook과 관리자 화면에서 각각 접수되거나 Webhook이 반복 전달되어도 동일한 영상·입력·모델·Prompt·Schema 조합의 작업으로 수렴한다.
- Webhook 누락 또는 제공자 장애에 대비한 보정 조회와 구독 상태 확인은 운영 계약에서 정한 주기로 수행하되, 기존 공개 탐색 기능과 격리한다.

<a id="fr-aiextract-005-관리자-신규-영상-추가"></a>

### FR-AIEXTRACT-005 관리자 신규 영상 추가

- 인증된 관리자는 신규 영상 추가 화면에서 YouTube URL과 보완 텍스트를 제출해 Webhook과 동일한 추출 작업 흐름을 시작할 수 있다.
- URL이 이미 Webhook 또는 다른 관리자 요청으로 접수된 경우 새 정식 영상을 중복 생성하지 않고 기존 작업·후보를 안내한다.
- 관리자 추가 작업은 초기 데이터 적립과 Webhook 누락 보완에 사용할 수 있으며, 실패 시 기존 수동 등록 흐름으로 전환할 수 있다.

<a id="fr-aiextract-006-webhook-감시-채널-관리"></a>

### FR-AIEXTRACT-006 Webhook 감시 채널 관리

- 인증된 관리자는 기존에 검증된 Creator의 YouTube 채널에 대해 신규 영상 Webhook 감시를 활성화하거나 중지할 수 있다.
- 채널 감시 상태와 마지막 구독 확인·갱신·오류 시각을 조회할 수 있어야 하며, Creator 등록만으로 감시를 자동 활성화하지 않는다.
- 감시를 중지해도 이미 접수된 추출 작업·후보·정식 데이터는 삭제하거나 되돌리지 않으며, 이후 신규 영상 작업만 접수하지 않는다.

### 10.3 동선 및 코스 추천

<a id="fr-course-001-코스-후보-입력"></a>

### FR-COURSE-001 코스 후보 입력

- 사용자는 공개·활성이고 유효한 좌표가 있는 맛집을 2개 이상 5개 이하로 직접 선택할 수 있다.
- 선택 목록의 첫 맛집을 출발지로 고정하고 별도 출발지·도착지, 현재 위치와 사용자가 고르지 않은 맛집은 입력으로 받지 않는다.

<a id="fr-course-002-이동-순서와-경로-조회"></a>

### FR-COURSE-002 이동 순서와 경로 조회

- 사용자는 첫 맛집을 고정한 상태에서 나머지 선택 맛집의 자동차 방문 순서, 구간별 실제 경로 거리·예상 소요 시간과 전체 이동 거리를 조회할 수 있다.
- 실제 경로 거리 합계가 30km를 초과하면 코스를 제공하지 않으며, 결과에는 생성 시각과 재조회가 필요한 만료 시각을 포함한다.
- 결과는 요청에 대한 일회성 응답이며 저장·공유·개인화 추천 이력으로 남기지 않는다.

<a id="fr-course-003-외부-경로-실패-대체-결과"></a>

### FR-COURSE-003 외부 경로 실패 시 대체 결과

- 좌표 누락, 외부 호출 제한·시간 초과·장애 또는 일부 구간 계산 실패 시 완전한 코스가 있는 것처럼 거리·시간을 추정하지 않는다.
- 실패 결과에는 사용자가 선택한 맛집과 입력 순서, 실패 범주와 재선택·재조회 안내만 제공할 수 있으며 계산되지 않은 구간을 정상 경로로 표시하지 않는다.
- 외부 경로 장애 중에도 기존 맛집 목록·필터·상세와 자연어 검색의 내부 조건 해석은 계속 사용할 수 있어야 한다.
