# 맛잇온 비기능 요구사항

## 1. 문서 목적

이 문서는 맛잇온 1차 MVP가 운영 환경에서 만족해야 할 성능, 보안, 데이터 정합성, 안정성, 가용성, 관측성, 호환성, 테스트, 배포, 복구 및 유지보수 품질 기준을 정의한다. 기능 범위와 비즈니스 규칙은 기존 요구사항 문서를 따르며, 이 문서는 특정 기술이나 제품을 선택하지 않고 이후 아키텍처와 ADR에서 구현 대안을 평가할 수 있는 검증 기준을 제공한다.

## 2. 비기능 요구사항 작성 원칙

- 각 요구사항은 고유 ID, 검증 가능한 기준, 검증 방법, 중요도와 결정 상태를 가진다.
- 기준 문서에서 확정된 범위와 정책은 `확정`, 합의되지 않은 합리적 수치는 `초기 제안`, 기술 구현 방식은 `후속 설계에서 결정`로 구분한다.
- 비즈니스 규칙과 기능 흐름을 반복하지 않고 그 기능이 만족해야 할 품질만 정의한다.
- 제품, 프레임워크, 저장소, 검색 엔진, 인증 방식과 배포 플랫폼을 고정하지 않는다.
- 4명의 백엔드 개발자가 구현하고 운영할 수 있는 MVP 복잡도를 기준으로 하며, 검증 이점이 없는 분산 구성이나 고가용성 구성을 요구하지 않는다.
- 성능 기준은 평균보다 95번째 백분위(p95)를 우선하며 외부 서비스 지연과 내부 처리 시간을 분리한다.

## 3. 성능

### NFR-PERFORMANCE-001 일반 조회 응답 시간

- 요구사항:
  - 정상 운영 조건에서 맛집 목록과 상세 기본 정보 조회는 목표 응답 시간 이내에 처리되어야 한다.
- 적용 대상:
  - 조건 없는 맛집 목록 조회
  - 맛집 상세 조회
- 목표 기준:
  - 애플리케이션 서버 내부 처리 시간 p95 500ms 이하(초기 제안)
- 측정 조건:
  - 외부 YouTube·카카오 서비스와 사용자 네트워크의 지연은 제외한다.
  - 데이터 규모와 동시 사용자 조건은 성능 테스트 계획 확정 후 기록한다.
- 검증 방법:
  - 대표 데이터셋을 사용한 부하 테스트 및 운영 응답 시간 메트릭 확인
- 중요도:
  - High
- 결정 상태:
  - 초기 제안

### NFR-PERFORMANCE-002 검색·필터 조합 응답 시간

- 요구사항:
  - 맛집 이름 검색과 지역·유튜버·음식 카테고리 필터를 모두 조합해도 조회 성능이 목표 범위를 벗어나지 않아야 한다.
- 적용 대상:
  - 이름 검색, 단일 필터 및 모든 허용 필터의 조합
- 목표 기준:
  - 애플리케이션 서버 내부 처리 시간 p95 800ms 이하(초기 제안)
  - 정상 부하에서 서버 오류 응답 비율 1% 미만(초기 제안)
- 측정 조건:
  - 빈 결과, 결과가 많은 조건, 유튜버 방문 관계가 많은 조건을 포함한다.
- 검증 방법:
  - 조건별 실행 비율을 반영한 부하 테스트와 느린 요청 분석
- 중요도:
  - High
- 결정 상태:
  - 초기 제안

### NFR-PERFORMANCE-003 관리자 등록 응답 시간

- 요구사항:
  - 외부 서비스의 실시간 응답을 기다리지 않는 관리자 등록 요청은 목표 시간 이내에 완료되어야 한다.
- 적용 대상:
  - 맛집, 유튜버, 영상 및 방문 관계 등록
- 목표 기준:
  - 애플리케이션 서버 내부 처리 시간 p95 1초 이하(초기 제안)
- 측정 조건:
  - 인증, 입력 검증, 중복 검증과 일관된 저장 처리를 포함하고 외부 서비스 지연은 별도로 측정한다.
- 검증 방법:
  - 등록 시나리오 부하 테스트 및 응답 시간 메트릭 확인
- 중요도:
  - High
- 결정 상태:
  - 초기 제안

### NFR-PERFORMANCE-004 페이지 크기 및 조회량 제한

- 요구사항:
  - 목록은 페이지 단위로 조회하고 과도한 응답 크기와 불필요한 중복 조회를 제한해야 한다.
- 적용 대상:
  - 맛집 목록, 검색 및 필터 조회
- 목표 기준:
  - 기본 페이지 크기 20개, 허용 크기 10개·20개·50개
  - 그 밖의 페이지 크기는 잘못된 요청으로 처리
  - 한 결과에서 동일 맛집을 한 번만 반환하고 화면에 필요하지 않은 대용량 원문이나 중복 관계 데이터를 반환하지 않음
- 검증 방법:
  - API 경계값 테스트, 응답 항목·크기 검사, 데이터 접근 프로파일 확인
- 중요도:
  - High
- 결정 상태:
  - 확정

## 4. 보안

### NFR-SECURITY-001 공개 조회와 관리자 접근 통제

- 요구사항:
  - 일반 조회는 로그인 없이 사용할 수 있어야 하며 모든 관리자 등록 요청은 인증과 관리자 권한 검증을 모두 통과해야 한다.
- 적용 대상:
  - 일반 사용자 조회 API와 관리자 등록 기능
- 목표 기준:
  - 인증되지 않은 일반 조회 요청은 허용
  - 인증 정보가 없거나 유효하지 않은 요청과 인증됐으나 권한이 없는 요청을 구분해 관리자 기능 접근을 100% 거부
- 검증 방법:
  - 인증 없음·실패·권한 실패·정상 관리자 시나리오의 자동화 보안 테스트
- 중요도:
  - Critical
- 결정 상태:
  - 확정

### NFR-SECURITY-002 입력 및 웹 공격 방어

- 요구사항:
  - 모든 외부 입력은 길이, 형식, 허용값과 URL 구조를 검증하고 SQL 삽입, 스크립트 삽입 등 일반적인 웹 공격이 실행되지 않도록 처리해야 한다.
- 적용 대상:
  - 검색어, 필터, 페이지, 관리자 등록값, 외부 URL
- 목표 기준:
  - 유효하지 않은 입력은 저장 또는 실행 전에 거부
  - 저장되거나 응답되는 사용자 입력이 실행 가능한 코드로 해석되지 않음
- 검증 방법:
  - 경계값·악성 입력 자동화 테스트 및 출시 전 보안 점검
- 중요도:
  - Critical
- 결정 상태:
  - 확정

### NFR-SECURITY-003 비밀정보와 오류 정보 보호

- 요구사항:
  - 관리자 인증 정보와 외부 서비스 키는 소스 코드 및 저장소와 분리하고, 운영 로그와 오류 응답은 비밀번호·토큰·비밀키·내부 스택 트레이스 및 시스템 구조를 노출하지 않아야 한다.
- 적용 대상:
  - 설정, 빌드 산출물, 로그, API 오류 응답
- 목표 기준:
  - 저장소 비밀정보 탐지 결과 0건
  - 표본 로그와 외부 오류 응답의 민감정보 및 내부 스택 노출 0건
- 검증 방법:
  - 저장소 비밀정보 검사, 로그 표본 검사, 오류 응답 계약 테스트
- 중요도:
  - Critical
- 결정 상태:
  - 확정

## 5. 데이터 정합성

### NFR-INTEGRITY-001 참조 및 필수값 정합성

- 요구사항:
  - 맛집, 유튜버·채널, 영상과 방문 관계는 필수 정보와 유효한 참조를 모두 만족할 때만 저장되어야 한다.
- 적용 대상:
  - 모든 관리자 등록 요청
- 목표 기준:
  - 필수값 누락 데이터 및 존재하지 않는 맛집·유튜버·영상을 참조하는 방문 관계 저장 0건
- 검증 방법:
  - 데이터 경계값 통합 테스트와 저장 데이터 정합성 검사
- 중요도:
  - Critical
- 결정 상태:
  - 확정

### NFR-INTEGRITY-002 중복 및 동시 등록 방지

- 요구사항:
  - 동일 영상과 동일 맛집·유튜버·영상 조합의 방문 관계는 중복 저장되지 않아야 하며, 동일 대상을 동시에 등록해도 하나만 생성되어야 한다.
- 적용 대상:
  - 맛집, 유튜버·채널, 영상 및 방문 관계 등록
- 목표 기준:
  - 정의된 동일성 기준을 위반한 데이터 0건
  - 동시 등록 테스트에서 성공적으로 생성되는 논리 대상 1개
- 측정 조건:
  - 동일성 식별값과 보장 구현은 후속 데이터 설계에서 결정한다.
- 검증 방법:
  - 반복·동시성 통합 테스트와 중복 데이터 검사
- 중요도:
  - Critical
- 결정 상태:
  - 확정

### NFR-INTEGRITY-003 등록 원자성과 공개 상태 일관성

- 요구사항:
  - 하나의 등록 요청이 실패하면 일부 데이터나 관계만 남아서는 안 되며, 공개 상태 기준은 목록·검색·필터·상세에 일관되게 반영되어야 한다.
- 적용 대상:
  - 복수 데이터·관계 등록 및 모든 일반 사용자 조회
- 목표 기준:
  - 의도적으로 실패시킨 등록 테스트의 부분 저장 0건
  - 동일 공개 상태에 대한 조회 유형별 노출 불일치 0건
- 검증 방법:
  - 실패 주입 통합 테스트 및 상태 전이 인수 테스트
- 중요도:
  - Critical
- 결정 상태:
  - 확정

### NFR-INTEGRITY-004 외부 링크와 내부 데이터 분리

- 요구사항:
  - 외부 영상 또는 장소 링크가 유효하지 않거나 이용 불가여도 내부 맛집 데이터의 유효성과 저장 상태가 자동으로 훼손되거나 삭제되지 않아야 한다.
- 적용 대상:
  - 외부 링크 상태 확인과 내부 맛집·관계 데이터
- 목표 기준:
  - 외부 링크 실패 시 내부 맛집 데이터 자동 변경·삭제 0건
- 검증 방법:
  - 외부 링크 실패 모의 통합 테스트와 데이터 변경 이력 확인
- 중요도:
  - Critical
- 결정 상태:
  - 확정

## 6. 안정성 및 장애 대응

### NFR-RELIABILITY-001 오류 격리와 공통 오류 정책

- 요구사항:
  - 단일 요청이나 특정 연계 기능의 실패가 전체 서비스 장애로 확대되지 않아야 하며, 예상 가능한 잘못된 요청·존재하지 않는 자원·서버 내부 오류를 구분해야 한다.
- 적용 대상:
  - 모든 API와 외부 연계 경로
- 목표 기준:
  - 처리되지 않은 예외는 내부 정보를 숨긴 공통 오류 응답으로 변환
  - 잘못된 입력과 존재하지 않는 자원을 서버 내부 오류로 집계하지 않음
  - 외부 링크 실패 중에도 맛집 목록과 상세 기본 정보 조회 성공
- 검증 방법:
  - 예외 유형별 계약 테스트와 장애 주입 테스트
- 중요도:
  - High
- 결정 상태:
  - 확정

### NFR-RELIABILITY-002 저장소 장애 및 재시도 통제

- 요구사항:
  - 데이터 저장소 연결 실패는 외부 서비스 오류와 구분 가능한 장애 로그를 남기고, 동일 실패 요청이 무한 재시도되지 않아야 한다.
- 적용 대상:
  - 데이터 접근과 재시도 가능한 외부 연계
- 목표 기준:
  - 장애 로그에 요청 식별 정보, 실패 대상과 오류 분류 포함
  - 모든 자동 재시도에 횟수 또는 시간 상한 존재
- 검증 방법:
  - 연결 실패·시간 초과 장애 주입 및 로그·재시도 횟수 검사
- 중요도:
  - High
- 결정 상태:
  - 후속 설계에서 결정

### NFR-RELIABILITY-003 사용자 오류 메시지와 기능 분리

- 요구사항:
  - 복구 불가능한 내부 오류는 일반화된 메시지로 제공하고, 장애가 난 관련 영상 영역과 정상 동작 가능한 맛집 기본 조회 영역을 분리해야 한다.
- 적용 대상:
  - 맛집 상세, 관련 영상 및 관리자 등록
- 목표 기준:
  - 외부 영상 장애 시 기본 정보 조회 성공률이 정상 내부 조회와 같은 기준을 만족
  - 오류 응답의 내부 구현 정보 노출 0건
- 검증 방법:
  - 외부 장애 인수 테스트와 오류 응답 검사
- 중요도:
  - High
- 결정 상태:
  - 확정

## 7. 가용성

### NFR-AVAILABILITY-001 상태 확인과 장애 구분

- 요구사항:
  - 애플리케이션의 실행 상태와 핵심 의존성 사용 가능 여부를 확인할 수 있어야 하며 애플리케이션 장애와 데이터 저장소 장애를 구분해야 한다.
- 적용 대상:
  - 운영 상태 확인 경로

- 검증 방법:

- 중요도:
  - High
