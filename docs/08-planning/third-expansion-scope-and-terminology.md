# 맛잇온 3차 확장 범위와 용어 결정

## 1. 목적과 결정 상태

이 문서는 [3차 확장 선행 상태 검토](third-expansion-baseline-review.md) 다음 단계로 자연어 검색, AI 기반 영상 정보 추출, 동선 및 코스 추천의 초기 의미와 제공 경계를 확정한다. 이 문서는 세 기능의 **범위와 용어**를 결정하지만, 세부 요구사항·PRD·API·데이터 계약·ADR·구현 Task를 대신하지 않는다.

결정 상태는 다음과 같이 구분한다.

- **결정**: 3차 확장 세부 계약을 작성할 때 지켜야 하는 승인된 초기 범위다.
- **초기 제외**: 같은 단계에서 제공하지 않기로 승인한 범위다.
- **후속 검증**: 결정된 계약을 구현·운영 환경에서 확인하는 항목이다. 정책을 미결정 상태로 되돌리는 의미가 아니다.

3차 확장 기능은 모두 기존 공개·활성 맛집과 자동 검증 경계를 우선한다. AI 결과는 정해진 자동 검증을 통과한 경우에만 공개하며, 관리자는 예외 보정·롤백을 담당한다.

## 2. 범위 요약

## 3. 공통 범위 경계

### 3.1. 기존 데이터와 공개 상태

- 일반 사용자가 검색하거나 코스를 구성할 수 있는 대상은 기존 공개·활성 맛집이다.
- 비공개·삭제 맛집은 자연어 검색 결과와 코스 후보에서 제외한다.
- 좌표가 없는 맛집은 기존 목록·상세에는 남지만 동선·코스 추천 후보에서는 제외한다.
- 3차 확장 기능은 기존 맛집·유튜버·영상·방문 관계의 공개 상태와 생명주기를 우회하지 않는다.

### 3.2. AI의 역할

- AI는 검색 조건 해석 또는 자동 등록을 위한 후보 생성에 사용한다.
- AI가 만든 문장이나 추정만으로 공개 사실, 방문 관계, 예약 가능 여부 또는 영업 상태를 확정하지 않는다.
- AI 결과를 공개 Entity로 반영하는 기능은 자동 필수값·근거·정규화·중복·Kakao·YouTube·Visit 검증을 모두 통과한 뒤에만 허용한다. 관리자의 사전 확인은 요구하지 않는다.
- 신규 AI 영상 후보에는 Google Gemini API Free Tier의 `gemini-3.5-flash-lite` global endpoint, Prompt `P6`, Schema `S1`만 사용한다. 기존 Prompt `P1`·`P2`·`P3`·`P4`·`P5` 작업과 Snapshot은 역사적 이력으로 보존한다. 유료 호출·자동 모델 전환은 하지 않는다. 모델이 무료 tier에서 제공되지 않거나 결제 연결을 요구하면 수동 등록 fallback으로 전환한다.
- Webhook은 신규 영상의 채널·영상 식별과 작업 접수에 사용하며, Webhook 수신만으로 정식 `Video`·`Visit`를 생성하거나 공개하지 않는다.
- 관리자는 신규 영상 추가 화면에서 URL과 보완 텍스트를 제출할 수 있다. Webhook 경로는 공개 YouTube URL의 Gemini 직접 영상 입력을 우선 사용하고, 접근 불가·분석 실패·부분 추출 시 관리자 보완 텍스트를 fallback으로 사용한다.

### 3.3. 거래·개인정보·위치

- 예약·결제·상업적 거래 연결은 3차 확장에 포함하지 않는다.
- 현재 위치, 이동 이력, 기기 식별자와 같은 위치·행동 데이터를 수집하지 않는다.
- 개인 컬렉션·찜·최근 본 기록을 추천 입력으로 사용하는 기능은 초기 범위에 포함하지 않는다.
- 코스 결과는 초기에는 저장·공유하지 않으며 요청 처리 결과로만 제공한다.

## 4. 자연어 검색

### 4.1. 용어

**자연어 검색**은 사용자가 입력한 문장을 서비스가 지원하는 맛집 검색 조건으로 해석해 기존 맛집 목록을 조회하는 기능이다.

**검색 조건 해석**은 자연어 문장에서 맛집 이름, 지역, 음식 카테고리, 유튜버에 해당하는 값을 추출하고 기존 필터 값으로 정규화하는 처리다.

**해석 결과 요약**은 서버가 실제 목록 조회에 적용한 구조화 조건을 사용자에게 보여주는 정보다. AI가 새로 작성한 맛집 설명이나 검색 결과에 대한 자유 형식 답변이 아니다.

### 4.2. 초기 범위

2026-08-10 다음 범위를 승인했다.

- 일반 사용자가 자연어 문장 하나를 입력한다.
- 서비스는 문장에서 기존 검색 조건인 맛집 이름, 서울 자치구, 음식 카테고리, 유튜버를 해석한다.
- 자연어에서 해석한 서로 다른 조건 종류는 기존 맛집 목록 조회의 AND 조건과 같은 의미로 적용한다.
- 자연어 조건과 사용자가 직접 지정한 필터가 같은 조건 종류에서 충돌하면 직접 지정 필터를 우선하고, 적용하지 않은 자연어 조건을 해석 결과 요약에서 구분한다.
- 결과는 기존 맛집 목록 응답과 같은 공개 맛집 목록이며, 자연어 검색 전용의 새로운 추천 순위를 만들지 않는다.
- 화면 또는 API는 실제 적용된 구조화 조건을 요약해 보여줄 수 있다. 이 요약은 결과 선정 이유를 생성하는 답변이 아니라 해석된 필터의 확인 수단이다.
- 지원하지 않는 메뉴·분위기·가격대·감정·예약 가능 여부가 문장에 포함되면 이를 기존 조건으로 추정해 조용히 적용하지 않는다. 미지원 조건의 표시·오류 방식은 API 계약에서 결정한다.
- 검색 조건으로 해석할 수 없는 문장은 전체 맛집 목록으로 대체하지 않고, 사용자가 조건을 다시 입력할 수 있는 실패 상태로 처리한다. 구체적인 오류 코드와 화면 문구는 후속 계약에서 정한다.

### 4.3. 초기 제외

- 임베딩 유사도나 벡터 검색을 이용해 의미가 비슷한 맛집을 별도 순위로 찾는 기능
- 검색 결과를 근거로 새로운 사실이나 설명을 생성하는 RAG 답변
- 대화 맥락을 유지하는 자유 형식 챗봇
- AI 추출 결과인 메뉴·분위기·가격대·맛 표현을 검색 조건으로 사용하는 기능
- 검색 결과에서 예약·주문·결제 화면으로 연결하는 기능
- 오타 자동 교정, 검색 자동 완성, 검색 기록 저장과 개인화 검색

### 4.4. 확정 계약과 검증 항목

- P1은 규칙·사전 기반으로 구현하며 `parserVersion: P1`을 사용한다. LLM 도입은 별도 범위·ADR·비용·개인정보 승인 없이는 하지 않는다.
- 자치구·카테고리·유튜버 이름의 동의어는 P1 사전에 두고, 복수 값은 같은 차원 안에서 OR·차원 간 AND로 적용한다.
- 같은 문장에 상충 조건이 있거나 별칭이 하나로 정규화되지 않으면 `UNRESOLVED`로 반환하고 추측하지 않는다.
- 미지원 조건·낮은 신뢰도·복수 후보는 API의 `PARTIAL_UNSUPPORTED`·`UNRESOLVED` 상태로 반환한다.
- 기존 목록 API 조회 계약을 재사용하고, 입력 원문은 저장하지 않으며 해시·상태·집계 지표만 운영에 남긴다.

## 5. AI 기반 영상 정보 추출

### 5.1. 용어

**AI 추출 후보**는 YouTube 영상과 관리자가 제공한 텍스트에서 AI가 추출해 자동 검증 대상으로 보관하는 맛집 관련 제안이다. 자동 검증을 통과하면 정식 Entity 생성·공개 결과로 전환된다.

**자동 확정 등록**은 AI 추출 후보가 필수값·근거·중복·기존 Kakao 장소·YouTube 메타데이터·Visit 검증을 통과해 관리자 승인 없이 정식 Entity와 `VisitTag`로 저장·공개되는 절차다. 관리자의 사후 보정·롤백은 별도 감사 이력으로 남긴다.

AI 추출 후보와 `Restaurant`, `Creator`, `Video`, `Visit`는 같은 의미로 사용하지 않는다. 후보는 자동 검증 전 임시 결과이고 정식 Entity는 검증 후 저장된 공개 데이터다.

### 5.2. 입력과 추출 대상

2026-08-10 다음 범위를 승인했다.

- 관리자가 기존 관리자 흐름에서 확인할 YouTube URL을 제출한다.
- 기본 입력은 공개 YouTube URL의 Gemini 영상 입력이며, 관리자가 최대 20,000자의 보완 텍스트를 추가할 수 있다.
- 초기 범위에서는 시스템이 YouTube 원본 영상이나 자막을 자동으로 내려받아 저장하지 않는다. URL 접근 실패·부분 추출 시 보완 텍스트 fallback을 사용한다.
- AI는 다음 후보 필드를 추출할 수 있다.
  - 영상에서 언급된 맛집명
  - 메뉴·음식 표현
  - 주소 또는 위치 표현
  - 해당 맛집을 실제 방문했다는 후보 여부와 근거 문장
- Creator 식별과 Video 메타데이터의 정식 값은 기존 YouTube 검증 흐름을 사용한다. AI가 채널 식별자나 영상 식별자를 사실로 확정하지 않는다.
- 추출 결과에는 필드별 신뢰도와 입력 텍스트 안의 출처 구간을 검수 보조 정보로 남긴다. 신뢰도는 확률로 사용자에게 약속하지 않으며, 근거 구간이 없으면 `UNKNOWN`으로 처리한다.

### 5.3. 자동 검증과 공개 경계

- AI 추출 결과는 자동 검증 전에는 후보 상태로 저장한다.
- 자동 검증을 통과하면 `Restaurant`, `Creator`, `Video`, `Visit`와 `VisitTag`를 생성하고 공개 목록·상세에 반영한다.
- 관리자는 정상 결과를 승인하지 않으며, 자동 차단 결과의 보완·사후 보정 또는 이미 공개된 결과의 롤백만 수행한다.
- 후보가 기존 등록 데이터와 중복이면 새 Entity를 만들지 않고 기존 관리자 등록·정정 흐름에서 처리한다.
- 자동 확정 후보는 기존 Kakao 장소 검증과 YouTube 검증을 통과해야 정식 등록할 수 있다.
- AI가 추출한 메뉴·분위기·요약 문장을 사용자에게 공개하는 기능은 초기 범위에 포함하지 않는다.

### 5.4. 실패·중복·모델 변경

- 같은 YouTube 영상 식별자, 입력 텍스트 해시, 추출 모델·Prompt·결과 Schema 버전 조합은 중복 작업으로 식별한다.
- 외부 AI 실패·시간 초과·quota 초과는 제한된 재시도 후 실패 상태로 남기며 무제한 재시도하지 않는다.
- 실패 결과를 기존 정식 Entity의 공개 상태 변경으로 연결하지 않는다.
- 모델 또는 프롬프트가 바뀌면 기존 후보를 조용히 덮어쓰지 않고 새 버전 결과를 만든다.
- 기존 결과와 새 결과를 비교할 수 있게 원래 모델 버전·추출 시각·검수 상태를 보존한다.
- 전체 데이터 자동 재처리는 초기 범위에 포함하지 않으며, 관리자 또는 명시적으로 승인된 작업만 재처리한다.

### 5.5. 초기 제외

- YouTube 원본 영상·자막의 저장 또는 재배포
- 자동 검증 없이 AI 결과만으로 정식 맛집·유튜버·영상·방문 관계를 생성하는 기능
- 자동 검증 전 공개와 자동 주기 동기화
- 영상 전체를 자동 요약해 공개하는 기능
- AI가 영업시간, 폐업 여부, 예약 가능 여부, 가격을 사실로 확정하는 기능
- 무제한 대량 재처리, 모델 변경 시 자동 전체 재계산, 외부 AI 제공자 간 자동 failover

### 5.6. 확정 계약과 검증 항목

- 기존 모델의 Google Gemini API Free Tier global endpoint 모델·영상 입력·구조화 출력 smoke test는 통과했지만, `gemini-3.5-flash-lite`로 전환한 새 모델의 smoke test와 운영 billing·quota 확인은 별도 실행이 필요하다. 새 모델은 유료 전환·자동 failover 없이 고정하고, 검증 전에는 호출하지 않는다.
- 신규 후보 Snapshot은 P6/S1·18개 통제 태그·근거 유형(`TIMESTAMP`, `TEXT_RANGE`, `UNKNOWN`)·입력 해시를 저장하고, 기존 P1/S1·P2/S1·P3/S1·P4/S1·P5/S1 Snapshot은 생성 당시 계약 이력으로 보존한다. 원본·전체 자막·전체 응답은 저장하지 않는다.
- Gemini timeout은 5초/90초/120초, 최대 2회 재시도·5초/30초 backoff이며 정책·입력·Schema 오류는 즉시 실패한다.
- 관리자 후보 검수 후 Kakao 장소·YouTube 메타데이터·Visit 검증을 순서대로 수행하고, 실패 시 정식 Entity 0건으로 보류한다.
- 동일 영상·입력 해시·모델·Prompt·Schema 조합은 멱등 처리하고, 버전 변경은 새 후보·평가 후 명시적 재처리만 허용한다.

## 6. 동선 및 코스 추천

### 6.1. 용어

**동선**은 사용자가 선택한 맛집들을 방문할 순서와 각 장소 사이의 이동 구간이다.

**코스**는 선택한 맛집 2~5개, 출발점으로 사용할 첫 장소, 제안된 방문 순서와 이동 요약을 묶은 일회성 결과다.

**코스 추천**에서 `추천`은 시스템이 맛집을 고르는 의미가 아니라, 사용자가 고른 맛집의 이동 순서를 제안하는 의미로만 사용한다.

### 6.2. 초기 범위

2026-08-10 다음 범위를 승인했다.

- 사용자가 공개·활성이고 좌표가 있는 맛집을 2~5개 직접 선택한다.
- 선택 목록의 첫 맛집을 출발지로 고정하고, 나머지 맛집의 방문 순서를 계산해 제안한다.
- 제안된 마지막 맛집을 도착점으로 사용하며 별도 도착지 입력은 받지 않는다.
- 초기 이동 수단은 자동차 1종으로 제한한다.
- 경로 정보는 각 구간의 거리·예상 소요 시간과 전체 순서 요약을 제공한다. 구체 응답 필드와 외부 제공자 형식은 API 계약에서 정한다.
- 코스의 총 이동 거리는 초기 30km 이하로 제한한다. 상한을 초과하거나 경로를 계산할 수 없으면 코스를 제안하지 않고 재선택·재시도를 안내한다.
- 경로 계산은 요청 시점의 외부 경로 결과를 사용하며, 실시간 교통을 서비스가 별도 판단하거나 도착 가능 시간을 보장하지 않는다.
- 코스 결과는 요청 처리 결과로만 제공하고 초기에는 저장하거나 다른 사용자와 공유하지 않는다.

### 6.3. 초기 제외

- 시스템이 사용자가 선택하지 않은 맛집을 자동으로 고르는 기능
- 현재 위치, 위치 권한, 이동 이력 또는 기기 위치의 수집
- 별도 출발지·도착지 주소 입력
- 도보·대중교통·자전거 등 자동차 외 이동 수단
- 실시간 교통량, 사고, 혼잡도와 영업시간을 이용한 방문 가능 여부 판단
- 예약 시간, 대기 시간, 주차 가능 여부와 결제 연결
- 코스 저장, 공유, 공동 편집, 회원별 추천 이력
- 사용자의 찜·최근 본 기록·개인 컬렉션을 이용한 자동 맛집 선정

### 6.4. 확정 계약과 검증 항목

- Kakao Mobility 자동차 길찾기 `/v1/directions`와 REST API Key를 사용한다. 유료 비용은 0원·앱 월 1,000건이며 운영 계정 quota 연결을 활성화 전 확인한다.
- 첫 장소를 출발지로 고정하고 좌표 직선거리 최근접 이웃 순서, 동률 Restaurant ID 오름차순을 적용한다.
- 30km 상한은 실제 경로 거리 기준으로 판정하며, 실제 경로 거리 응답이 없으면 코스를 제공하지 않는다.
- 코스당 외부 호출은 최대 1회, 서버 캐시는 사용하지 않고 결과 TTL은 5분이다.
- 외부 429·시간 초과·부분 경로 실패 시 재시도하지 않고 추정값 없는 실패 상태를 반환한다.
- 코스 결과는 저장하지 않으며 로그에는 맛집 ID와 추적 ID만 남기고 좌표 원문은 남기지 않는다.

## 7. 공통 초기 제외

다음 항목은 세 기능 어느 쪽에도 초기 범위로 포함하지 않는다.

- 자유 형식 AI 챗봇, RAG 답변, 사실 근거 없는 생성 답변
- 자동 검증 전 공개 데이터 생성과 자동 주기 동기화
- 예약·주문·결제·상업적 거래
- 현재 위치와 개인 이동 이력 수집
- 개인화 추천, 회원 행동 기반 자동 맛집 선정
- 저장·공유·공동 편집 기능
- 외부 API quota를 초과하는 무제한 재시도와 비용 상한 없는 처리

## 8. 범위 변경과 상세 계약 게이트

다음 항목은 이 문서의 초기 범위를 넓히므로 별도 범위 변경 승인과 관련 계약 갱신이 필요하다.

| 변경 후보 | 필요한 추가 결정 |
|---|---|
| 임베딩 의미 검색 | 임베딩 모델·벡터 저장소·재색인·검색 품질·비용·개인정보 |
| RAG·챗봇 | 답변 근거·환각 방지·대화 상태·모델 비용·운영 책임 |
| 자동 검증 없는 AI 공개 | 자동 검증 조건 우회, 정확도 기준, 롤백·감사·오류 책임 |
| 영상·자막 자동 수집 | YouTube 호출·저작권·보존·전사 품질·외부 비용 |
| 자동 맛집 선정 | 추천 신호·개인정보·설명 가능성·편향·결과 책임 |
| 현재 위치·대중교통 | 위치 동의·보존·실시간 교통 제공자·호출 비용 |
| 코스 저장·공유 | 소유권·공개 범위·탈퇴 정리·신고·수정·저장 데이터 수명주기 |

세부 요구사항·PRD·API·데이터·ADR을 작성할 때는 [3차 확장 선행 상태 검토](third-expansion-baseline-review.md)의 G3-01~G3-07 게이트를 다시 확인한다. 특히 2차 확장의 정상 부하 50명·20 RPS와 최대 부하 200명·80 RPS 측정은 3차 확장 최종 완료 게이트로 승계한다.

## 9. 다음 문서화 순서

1. 3차 확장 도메인 경계에서 기존 도메인·AI 후보·조회 책임을 분리한다.
2. 자연어 해석, AI 자동 등록·예외 보정, 동선·코스의 PRD와 Workstream 소유권을 경계에 연결한다.
3. AI 후보 Snapshot·자동 판단·사후 보정·재처리와 경로 호출·캐시·quota의 데이터·ADR 결정을 확정한다.
4. 승인된 경계를 API·데이터 계약과 제품·평가 추적표에 연결한다.
5. 2차 성능 측정과 좌표 보강률 결과를 3차 최종 완료 증거에 연결한다.

## 10. 결론

3차 확장의 초기 범위는 다음과 같이 확정한다.

- 자연어 검색은 자연어를 기존 맛집 조건으로 해석해 기존 목록을 반환한다.
- AI 영상 정보 추출은 자동 검증용 등록 후보를 만들고, 기존 검증을 포함한 자동 게이트를 통과하면 관리자 승인 없이 정식 데이터를 생성·공개한다.
- 동선 및 코스 추천은 사용자가 고른 2~5개 맛집의 자동차 이동 순서를 제안하며, 자동 맛집 선정과 현재 위치를 사용하지 않는다.

임베딩 검색, 챗봇, 자동 검증 없는 공개, 현재 위치, 대중교통, 저장·공유는 후속 범위 변경 없이는 3차 확장에 추가하지 않는다.
