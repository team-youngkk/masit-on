# 이슈 231 맛집 추천 코스 지도 표시 문서화 초안

## 1. 목적과 상태

이 문서는 이슈 [#231](https://github.com/team-youngkk/masit-on/issues/231)의 제품·API·외부 연동 계약을 변경하기 전에 현재 공백, 결정할 사항과 문서 갱신 순서를 정리한다. 아직 승인된 계약이 아니며, `WS-16` 소유자와 지도 프론트엔드 리뷰어가 아래 결정을 승인하기 전에는 요구사항·API·ADR의 확정값으로 사용하지 않는다.

목표는 코스 계산 성공 결과에 추천 순서 마커와 실제 자동차 이동 경로 선을 표시해 사용자가 이동 흐름을 공간적으로 이해하게 하는 것이다. 현재 위치를 수집하거나 지도 조작을 서버 재계산 조건으로 사용하지 않는다.

## 2. 현재 기준선

| 영역 | 현재 계약·구현 | 지도 표시를 위해 필요한 변화 |
|---|---|---|
| 제품 | `PRD-DISCOVERY-006`은 방문 순서, 구간 거리·시간과 전체 거리를 결과로 정의한다. | 정상·만료·SDK 실패·경로 형상 누락 상태의 지도 동작을 추가로 정의해야 한다. |
| API | `restaurants`에는 순서·식별자·이름·역할, `segments`에는 출발/도착 식별자·거리·시간만 있다. | 방문지 좌표와 경로 형상의 응답 위치·타입·상한을 합의해야 한다. |
| 백엔드 | Mobility Adapter는 `summary=true`로 호출하고 `sections[].distance`와 `duration`만 정규화한다. 성공 Response는 좌표와 Kakao 원문을 제외한다고 명시한다. | 요약 전용 호출을 유지할 수 있는지 확인하고, 제공자 형상을 내부 Port의 중립 타입으로 정규화해야 한다. |
| 프론트엔드 | `/course`는 순서·거리·시간 목록만 렌더링한다. `/map`에는 별도 Kakao SDK loader와 마커·대체 목록이 있다. | 지도 공통 기반의 재사용 경계, 순서 마커·경로 선·영역 맞춤과 목록 선택 동기화를 정해야 한다. |
| 개인정보·비용 | 현재 위치·선택 이력·경로 결과를 저장하지 않고, 코스당 외부 호출 1회·TTL 5분·30km 상한을 적용한다. | 지도 도입 뒤에도 같은 경계를 유지하고 좌표·경로·뷰포트를 로그에서 제외해야 한다. |

새 테이블이나 Flyway migration은 필요하지 않은 것으로 예상한다. 이 판단은 코스 결과를 요청 단위 응답으로만 유지한다는 기존 계약을 전제로 하며, 저장·공유 범위가 추가되면 다시 검토한다.

## 3. 제안 범위

### 3.1 포함 제안

- 코스 계산 성공 뒤에만 결과 지도를 표시한다.
- 방문 순서 번호가 있는 2~5개 마커를 표시하고 출발·경유·도착 역할을 구분한다.
- 제공자가 반환한 실제 자동차 경로 형상을 순서대로 연결한다.
- 최초 표시와 새 경로 조회 때 전체 경로가 보이도록 지도 영역을 맞춘다.
- 마커와 텍스트 순서 목록의 선택을 양방향으로 동기화한다.
- 키보드·스크린 리더·SDK 실패 환경에서는 기존 순서·거리·시간 목록을 완전한 대체 수단으로 유지한다.
- 후보 변경, 요청 실패와 결과 만료 때 이전 지도 경로가 최신 결과처럼 남지 않게 한다.

### 3.2 제외 유지

- 현재 위치·위치 권한·기기 이동 이력
- 지도 이동·확대·축소에 따른 서버 재조회 또는 코스 재계산
- 도보·대중교통·자전거와 실시간 교통 도착 보장
- 코스·경로 형상의 영속 저장, 공유와 공동 편집
- 브라우저에서 Kakao Mobility REST API 직접 호출

## 4. 계약 결정이 필요한 항목

Kakao 제공자 원문 필드명을 공개 API와 Domain에 그대로 노출하지 않는다. 외부 응답 구조가 바뀌어도 Application과 프론트 계약이 제공자 SDK·Schema에 종속되지 않도록 Adapter에서 WGS84 좌표 목록으로 정규화한다.

## 5. API 변경 초안

아래 JSON은 논의를 위한 형태이며 확정 계약이 아니다. 필드 이름, 좌표 정밀도와 배열 상한은 `D-231-02`~`04` 승인 뒤 API 문서에 반영한다.

```json
{
  "restaurants": [
    {
      "sequence": 1,
      "restaurantId": "restaurant-id-1",
      "name": "출발 맛집",
      "role": "START",
      "coordinate": {
        "latitude": 37.5665,
        "longitude": 126.9780
      }
    }
  ],
  "segments": [
    {
      "fromRestaurantId": "restaurant-id-1",
      "toRestaurantId": "restaurant-id-2",
      "distanceMeters": 4200,
      "durationSeconds": 780,
      "path": [
        { "latitude": 37.5665, "longitude": 126.9780 },
        { "latitude": 37.5651, "longitude": 126.9812 }
      ]
    }
  ]
}
```

기존 `status`, 전체 거리·시간, 생성·만료 시각과 오류 계약은 유지한다. 공개 응답에는 API Key, Kakao 원문 응답, 현재 위치, 지도 뷰포트와 내부 제공자 식별자를 포함하지 않는다.

## 6. 상태와 접근성 초안

| 상태 | 지도 | 텍스트 결과 | 사용자 행동 |
|---|---|---|---|
| 계산 전·계산 중 | 표시하지 않음 | 선택 목록과 진행 상태 유지 | 중복 제출 방지 |
| 정상 | 순서 마커·실제 경로 선·전체 영역 | 순서·구간·전체 거리와 시간 | 마커/목록 선택, 상세 이동, 새 경로 조회 |
| 만료 | 오래된 결과임을 식별하고 조작 상태 해제 | 거리·시간 만료 안내 | 새 경로 조회 |
| Maps SDK·키 실패 | 오류·재시도 안내 | 기존 결과 완전 유지 | 목록·상세 사용, SDK 재시도 |
| 경로 형상 누락 | `D-231-03` 결정 전 미확정 | 추정 직선은 표시하지 않음 | 재조회 또는 목록 사용 |
| 코스 API 실패 | 표시하지 않음 | 기존 실패 범주와 선택 목록 유지 | 재선택·허용된 재시도 |

지도 캔버스만으로 순서와 거리를 전달하지 않는다. 각 마커에는 순서와 맛집 이름을 연결하고, 포커스 가능한 목록을 항상 제공한다. 360·390·768·1280·1440px에서 지도와 목록 순서, 높이와 터치 조작을 검증한다.

## 7. 문서 갱신 순서

1. `D-231-01`~`06`을 소유자와 리뷰어가 확정한다.
2. `FR-COURSE-*`와 관련 NFR에 지도 표시·장애 격리·응답 크기 기준을 추가하거나 기존 항목 확장 여부를 결정한다.
3. `PRD-DISCOVERY-006`, 3차 사용자 흐름과 와이어프레임에 정상·만료·SDK 실패·형상 누락 상태를 반영한다.
4. 코스 API와 공통 좌표 계약에 좌표·경로 형상 Schema, 상한과 오류 의미를 반영한다.
5. `ADR-ROUTE-001`에 Mobility 요약 모드·형상 정규화·Port 경계를, 필요하면 `ADR-MAP-001`에 SDK 공통화 경계를 반영한다.
6. 아키텍처 외부 연동·패키지 경계와 3차 확장 테스트 추적표를 동기화한다.
7. 구현 Task와 브라우저·성능·보안 검증 항목을 `third-expansion-task-breakdown.md`에 추가한다.

요구사항과 API 계약을 바꾸는 2~5단계는 소유자 합의 뒤 같은 변경 범위에서 수행한다. 문서 간 결정이 충돌하면 구현을 시작하지 않고 충돌 지점과 영향 범위를 다시 기록한다.

## 8. 구현·검증 예상 범위

### 백엔드

- Course Route Port 결과에 제공자 중립 경로 형상 추가
- Mobility 요청 옵션과 `sections` 형상 Schema 검증
- 방문지 좌표·구간 경로를 Application 결과와 API DTO로 매핑
- 부분 형상·잘못된 좌표·점 수 상한·응답 크기 경계 테스트
- 기존 외부 호출 1회, quota, 30km, TTL, 비저장과 로그 금지 회귀

### 프론트엔드

- Maps SDK loader·최소 타입의 공유 가능한 경계 분리
- 코스 결과 전용 지도, 순서 마커, Polyline과 전체 영역 맞춤
- 마커/목록 선택 동기화와 후보 변경·만료 시 정리
- SDK 실패·키 누락·형상 누락 대체 상태
- 순수 상태 테스트, 컴포넌트 테스트와 다섯 화면 폭 브라우저 검증

### 완료 증거

- 계약 테스트: 기존 소비자 호환성, 좌표 순서와 경로 구간 순서
- 외부 Adapter: WireMock 정상·형상 누락·부분 실패·과대 응답
- 보안·개인정보: API Key·원문·현재 위치·뷰포트·경로 로그 0건
- 성능: 최대 5개 맛집 경로의 응답 크기와 렌더링 비용 측정
- 접근성: 지도 없이도 동일한 방문 순서·거리·시간과 다음 행동 제공
