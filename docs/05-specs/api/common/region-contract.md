# 전국 지역 계층 계약 — 이슈 #394

## 1. 적용 범위와 검토 상태

사용자의 #394 구현 요청에 따라 맛집 목록·자연어 직접 필터·관리자 등록의 지역 범위를 전국으로 확장한다. 최초 MVP의 서울 한정 범위는 당시 기록으로 보존한다. 이 변경의 API·DB·등록 경계에 대한 소유자 리뷰는 PR에서 요청하며, 팀 승인을 이미 받았다는 의미는 아니다. 지도 기능과 지도 API의 지역 계약 확대는 포함하지 않는다.

## 2. 지역과 식별자

- 지역은 시·도 → 시·군·구의 최대 2단계다. 같은 `중구`라도 소속 시·도가 다르면 다른 지역이다.
- 수원시 장안구 같은 비자치구는 별도 3단계나 시·도 직속 구로 만들지 않고 `경기도 → 수원시`에 귀속한다. 전체 도로명주소의 구 이름은 보존한다.
- 세종특별자치시는 `3611000000`인 최상위 지역에 직접 맛집을 연결한다. `3600000000`이나 가상의 하위 시·군·구를 만들지 않는다.
- 제주특별자치도 아래에는 제주시·서귀포시를 둔다.
- `Region.id`는 내부 UUID, `Region.code`는 기존 애플리케이션 코드다. 서울 25개 행의 UUID·code 및 기존 `restaurant.region_id` FK를 보존한다.
- 새 `Region.administrativeCode`는 행정안전부 법정동 코드의 10자리 숫자 **문자열**이며, `parentId`는 상위 Region UUID다. 최상위의 `parentId`는 `null`이다. API의 지역 `code`와 검색 `regionCode`는 이 `administrativeCode`를 뜻하며 기존 `SEOUL_*` code나 UUID가 아니다.
- 원천은 [행정표준코드관리시스템](https://www.code.go.kr/)의 법정동 코드이며, 이 변경의 기준은 [2026-09-30 검증 스냅샷](../../../../src/main/resources/db/reference/regions-2026-09-30.json)이다. 스냅샷의 현존 코드 집합은 상위 16개·하위 229개, 총 245개다. `전남광주통합특별시(1200000000)`를 포함하고 폐지된 광주광역시·전라남도의 별도 상위 행은 제외한다. 선택 목록에 폐지 코드가 섞일 수 있으므로 개별 현존 조회로 확인한 집합을 사용하며 시·도 수를 17개로 고정하지 않는다.

## 3. 공개 지역 목록

`GET /api/regions`는 무인증이며 쿼리 파라미터를 받지 않는다. 파라미터가 있으면 `400 INVALID_REQUEST`다. 성공은 `200`과 다음 구조이며 페이지 정보는 없다.

```json
{
  "items": [
    {
      "code": "1100000000",
      "name": "서울특별시",
      "children": [{ "code": "1144000000", "name": "마포구" }]
    },
    { "code": "3611000000", "name": "세종특별자치시", "children": [] }
  ]
}
```

위 예시는 구조 설명용 일부 지역이다. 실제 응답은 활성 시·도와 그 아래 활성 시·군·구의 **전체 마스터**이며, 등록 맛집이 0건인 지역도 포함한다. 비활성 부모 아래 자식은 공개 트리에 포함하지 않는다. 하위가 없으면 `children: []`, 활성 마스터 자체가 없으면 `items: []`다. 지역 마스터의 표시 순서로 반환한다.

## 4. 일반 목록과 호환성

- `GET /api/restaurants`의 선택 파라미터 `regionCode`는 활성 마스터에 존재하는 10자리 코드 하나다. 형식 오류·미등록·비활성 코드·복수 값은 `400 INVALID_FIELD_VALUE`다.
- 시·도 선택은 해당 지역 ID **자체와 활성 자식 ID**를 포함한다. 시·군·구 선택은 해당 ID만 포함한다. 유효한 지역의 맛집이 없으면 `200`과 빈 결과다.
- 기존 `district`는 서울 자치구 이름만 받는다. 전국 동명 구를 이름만으로 조회하지 않는다. `regionCode`와 `district`의 동시 지정은 `400 INVALID_FIELD_VALUE`다.
- 응답의 기존 `district` 필드명은 유지하며 값은 맛집에 연결된 지역의 표시명이다. 따라서 `수원시`, `제주시`, `세종특별자치시`도 가능하다. 이 표시명을 레거시 `district` 요청값으로 재사용하지 않는다.
- `/api/restaurants/filter-options`의 `districts`는 기존 서울 자치구 문자열 계약을 유지한다. `categories`는 전국의 공개·활성 맛집이 사용하는 기존 카테고리 계약을 유지한다. 전국 지역 선택지는 `/api/regions`를 사용한다.
- UI는 시·도 선택을 바꾸면 이전 하위 선택과 페이지를 초기화한다. 지역을 지우면 지역 조건만 해제하고 나머지 필터는 유지한다. 세종은 하위 선택 없이 검색할 수 있다.

## 5. 자연어 검색

`POST /api/restaurants/natural-language-search`는 `filters.regionCode`를 받으며 일반 목록과 같은 검증·범위·`filters.district`와의 상호 배제를 적용한다. 파서의 기존 서울 지명 해석 범위는 유지한다.

직접 `regionCode`가 있으면 자연어에서 해석한 `district` 대신 적용한다. `interpretation.appliedConditions.regionCode`에 적용 코드를 반환하고, 대체된 `district`는 `null`이다. 실제 불일치 또는 지역 해석의 미해결 상태는 기존 `district` 필드와 `DIRECT_FILTER_WON`으로 설명한다. 직접 코드가 자연어에서 해석한 서울 자치구와 같으면 충돌로 표시하지 않는다. 직접 코드가 없거나 의심 입력으로 적용 조건을 비운 응답의 `regionCode`는 `null`이다.

의심 입력 등으로 조회하지 않는 실패 경로에서도 직접 지역·기타 필터의 유효성을 검증한다. 유효한 직접 필터가 있어도 의심 입력은 결과를 반환하지 않으며 전체 목록으로 대체하지 않는다.

## 6. 등록·저장과 검증

수동 등록, AI 후보의 물리 참조 해석과 장소 후보는 같은 주소 정규화·지역 마스터 판정을 사용한다. 시·도와 시·군·구를 함께 확인하고 비자치구는 시로 귀속한다. 세종은 최상위에 직접 연결한다. 등록 가능한 활성 지역을 찾지 못하면 임의 생성·서울 폴백 없이 등록을 거부한다.

장소 재검증은 같은 주소 정규화를 사용하지만 지역 마스터를 조회하거나 `regionId`를 재배정하지 않는다. 기존 주소와 관측 주소에서 추출한 시·도·시·군·구를 비교하고, 추출 불가 또는 변경이면 `REVIEW_REQUIRED`로 보내며 기존 감사 사유 `DISTRICT_CHANGED`를 유지한다. 같은 지역 안의 자동 보정도 기존 `regionId`, 공개·생명주기 플래그와 기존 감사 계약을 보존한다.

주소의 시·도 별칭과 기존 광주·전남 표기는 현행 `전남광주통합특별시`로 정규화한 뒤 그 아래 활성 시·군·구를 확인한다. 예를 들어 `광주광역시 동구`는 현행 통합 지역의 `동구`에 연결되며 `경기도 광주시`와 혼동하지 않는다. 이는 주소 호환 규칙이며 폐지 행정코드를 검색 입력으로 허용하는 규칙이 아니다. 현행 귀속을 확인할 수 없는 폐지 이름은 추정하지 않고 거부한다. 장소 검색 후보는 매핑 불가 시 `district: null`로 남을 수 있지만 등록 성공을 의미하지 않는다.

지역 변경 후에도 이름·음식 종류·유튜버·태그의 AND 조건과 불투명 자원 ID 계약을 유지한다. URL의 직접 지역 필터 변경은 자연어 입력·태그 선택·이전 결과 초기화에 포함하고, 페이지 이동만으로는 초기화하지 않는다. [PR #169](../../../troubleshooting/pr-169-natural-language-search-review.md)와 [PR #213](../../../troubleshooting/pr-213-natural-language-filter-reset-review.md)의 검증·필터 상태 회귀 제약을 유지한다.

외부 Kakao·YouTube 호출은 DB 트랜잭션 밖에서 수행한다. 외부 검증 또는 지역 매핑 실패 시 핵심 Entity를 0건 저장하며, 성공한 검증 이후 짧은 저장 트랜잭션에서 기존 원자성을 유지한다.

V20은 새 전진 마이그레이션으로 컬럼·전국 시드·계층 제약을 추가한다. V1~V19는 수정하지 않는다. 서울 ID·code·FK 보존, 같은 이름의 다른 시·도 지역, 수원·세종·제주, 빈 마스터 지역, 잘못된 코드·동시 필터, 자연어 실패 경로를 회귀 검증한다. 모든 최신 Flyway 버전 기대값을 V20으로 맞추되 과거 특정 버전 전환 검증은 보존한다.

## 9. 지도 적용 범위 — 이슈 #399 결정

전국 지역 계층화는 맛집 목록·자연어 직접 필터·관리자 등록에 적용하지만, 현재 지도 기능과 지도 API에는 적용하지 않는다. 지도는 기존 서울 자치구 기반 탐색 범위로 유지한다.

- `GET /api/restaurants/map-points`는 `regionCode`를 받지 않으며, `query`·서울 자치구 `district`·`category`·`creatorId`만 사용한다.
- 맛집 목록에서 `regionCode`가 선택된 동안 지도 메뉴는 링크를 만들지 않는다. 지역 코드를 조용히 제거한 뒤 전국 또는 전체 맛집 지도로 이동하지 않는다.
- `/map?regionCode=...`를 직접 열어도 지도 조회를 실행하지 않고 같은 미지원 안내와 지역 필터 해제 행동을 표시한다.
- 화면은 지도 미지원 범위와 `regionCode`를 해제하면 지도를 이용할 수 있다는 안내를 제공하고, 지역 목록 탐색은 계속 사용할 수 있게 한다.
- 전국 지역을 지도에서 지원하려면 별도의 제품 결정과 지도 API·조회·초기 화면·회귀 검증 계약을 함께 갱신한다.
