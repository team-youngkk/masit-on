# 응답 계약

## 1. 권장 방식

성공 응답은 `data`·`meta` 공통 래퍼 없이 데이터 자체를 반환한다. MVP 규모에서 래퍼는 단일 자원과 목록을 불필요하게 중첩하고 프론트엔드 접근 경로를 늘린다. 페이지 메타데이터는 목록 본문의 `page`로 충분하며 오류는 별도 공통 구조로 일관되게 표현한다.

## 2. 성공 응답

- 단일 자원: 자원 객체를 본문으로 반환한다.
- 목록: `{ "items": [], "page": {...} }`를 반환한다. 페이지가 필요 없는 최소 선택 목록은 `{ "items": [] }`를 반환한다.
- 생성: `201 Created`와 생성된 자원의 외부 표시 객체를 반환한다.
- 본문 없는 성공: 현재 MVP에는 수정·삭제 API가 없어 사용하지 않는다.

## 3. 값과 필드 규칙

- 계약에서 필수인 필드는 값이 없더라도 생략하지 않는다.
- 목록은 항목이 없으면 `[]`이며 `null`이나 필드 생략을 사용하지 않는다.
- 선택 문자열에서 `null`은 값이 등록되지 않았음을 뜻한다. 빈 문자열 `""`은 유효한 값으로 사용하지 않는다.
- 선택 객체는 계약에서 명시한 경우에만 `null`을 사용한다.
- 존재하지 않는 단일 자원은 빈 객체나 `null`이 아니라 공통 `404` 오류다.
- JSON 필드는 lower camel case를 사용한다.
- 응답 문자열은 UTF-8로 손실 없이 왕복돼야 한다.
- 클라이언트는 호환 가능한 선택 필드 추가를 허용하되, 문서에 없는 필드의 존재를 전제로 동작하지 않는다.

## 4. 목록 예시

```json
{
  "items": [],
  "page": {
    "number": 1,
    "size": 20,
    "totalElements": 0,
    "totalPages": 0,
    "hasNext": false
  }
}
```
