## 3. 문제 현상

### 3.1 비계약 문서를 계약보다 높은 제약으로 승격

- 재현 조건: PR #128이 추가한 `implement-review-workflow/SKILL.md`의 "트러블슈팅 기록 선행 확인" 항목과 `AGENTS.md` 2절(또는 `CLAUDE.md` 2절)의 권위 순서를 나란히 읽는다.
- 실제 결과: 추가한 규칙은 트러블슈팅 기록의 "재발 방지" 항목을 조건 없이 이번 구현의 제약(`binding constraints`)으로 삼고, 그 제약을 서브에이전트 위임 프롬프트에까지 전달하도록 지시했다. 그러나 권위 순서에 열거된 것은 확정 요구사항·Accepted ADR·API/데이터 계약·아키텍처·구현 컨벤션·외부 컨벤션 여섯 항목뿐이며 트러블슈팅 기록은 없다.
- 기대 결과: 트러블슈팅 기록은 회귀 위험을 상기시키는 검토 자료로 쓰고, 현재 계약과 충돌할 때는 계약이 이긴다.
- 영향 범위: 이후 구현·위임·리뷰의 판단 기준. 요구사항이나 ADR이 갱신된 뒤 낡은 기록이 최신 계약을 밀어내면, 구현이 잘못된 제약을 따르거나 불필요하게 중단될 수 있다.

### 3.2 이번 라운드의 기록이 인덱스에 없음

- 재현 조건: PR #128 리뷰 스레드를 처리한 뒤 `docs/troubleshooting/README.md`의 목록을 확인한다.
- 실제 결과: PR #128의 앞선 변경은 PR #125의 후속 대응이라 `pr-125-develop-to-main-sync-policy-review.md`에 함께 기록했고, 그 문서와 `pr-127-*.md`는 이미 인덱스에 있었다. 하지만 PR #128 자체에 달린 이번 리뷰 스레드를 다루는 기록은 존재하지 않아 인덱스에도 없었다.
- 기대 결과: 리뷰 라운드마다 그 PR의 기록이 있고, 인덱스에서 찾을 수 있어야 한다. 특히 이번 PR이 추가한 규칙(구현 전 트러블슈팅 기록 조회)은 인덱스가 완전하다는 전제에 의존한다.
- 영향 범위: 문서 발견성. 인덱스에 없으면 다음 작업에서 이 기록을 찾지 못해 새 규칙이 무력해진다.

## 4. 근본 원인

3.1은 스킬 규칙을 쓸 때 "이 문서를 반드시 읽어라"와 "이 문서를 제약으로 삼아라"를 구분하지 않은 것이 원인이다. 의도는 과거 실수 반복 방지였는데, 문장이 트러블슈팅 기록에 계약과 같은 강제력을 부여해 저장소가 이미 정한 문서 권위 순서와 모순됐다. 권위 순서를 다시 확인하지 않고 규칙을 추가한 절차상 누락이다.

3.2는 기록 파일을 PR 단위가 아니라 "이슈 계보" 단위로 묶은 판단에서 비롯됐다. PR #128을 PR #125의 후속으로 보아 #125 기록에 이어 썼고, 그 결과 PR #128 자체에 달린 새 리뷰 라운드가 어느 기록에도 대응되지 않는 공백이 생겼다.

## 5. 해결

- 변경 내용:
  - `.claude/skills/implement-review-workflow/SKILL.md`와 `.codex/skills/implement-review-workflow/SKILL.md`의 트러블슈팅 선행 확인 항목을 수정했다. "제약으로 삼는다" → "회귀 위험 점검 목록으로 사용한다"로 바꾸고, 트러블슈팅 기록이 권위 순서에 없는 비계약 문서임을 명시했다. 각 재발 방지 항목을 현재 요구사항·ADR·계약·아키텍처와 대조해 유효한 항목만 제약·위임 프롬프트로 전달하고, 충돌 시 권위 순서를 따르며 기록을 버리도록 했다. 낡은 기록 때문에 구현을 멈추지는 않되 문서 충돌로 보고하도록 구분했다(3.1).
  - 이 문서를 작성하고 `docs/troubleshooting/README.md` 인덱스 최상단에 등록했다(3.2).
- 선택 이유: 3.1은 규칙의 의도(회귀 방지)를 유지하면서 강제력만 계약 아래로 낮추는 최소 수정이다. 규칙 자체를 되돌리면 이번 PR의 목적이 사라지고, 그대로 두면 문서 권위 정책과 모순이 남는다.
- 변경 파일: `.claude/skills/implement-review-workflow/SKILL.md`, `.codex/skills/implement-review-workflow/SKILL.md`, `docs/troubleshooting/pr-128-skill-troubleshooting-authority-review.md`(이 문서), `docs/troubleshooting/README.md`
- 고려한 대안: 트러블슈팅 기록을 권위 순서에 정식 항목으로 추가하는 방안을 검토했으나, `AGENTS.md`·`CLAUDE.md` 2절은 팀이 합의한 계약 문서이고 이번 PR 범위(스킬 규칙 보완)를 넘는 정책 변경이라 채택하지 않았다.

## 7. 재발 방지

- 스킬·지침에 "이 문서를 따르라"는 규칙을 추가할 때는 그 문서가 `AGENTS.md`·`CLAUDE.md` 2절 권위 순서의 어디에 해당하는지 먼저 확인하고, 순서에 없는 문서에는 계약과 같은 강제력을 부여하지 않는다.
- 트러블슈팅 기록은 PR 단위로 만든다. 앞선 PR의 후속 작업이라도, 새 PR에 자체 리뷰 스레드가 달리면 그 PR 번호의 기록을 만들고 인덱스에 등록한다.

## 8. 남은 사항

- 인덱스 등록 요청 스레드는 `[P2]` 제목만 있고 `문제 상황`·`영향`·`개선 제안` 항목이 없어, "이번 기록"이 무엇을 가리키는지 3.2와 같이 해석해 처리했다. 해석이 요청과 다르면 해당 스레드를 다시 열어 알려주기를 요청한다.
