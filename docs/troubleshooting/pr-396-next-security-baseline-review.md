## 3. 문제 현상과 발생 조건

- 오류 메시지: 없음. 코드 실행 오류가 아니라 승인되지 않은 기준선의 문서 전파 문제다.
- 발생 환경: PR #396, `codex/next-security-patch`, 최초 커밋 `de66803d`.
- 재현 조건: 보안 패치 ADR-WEB-007을 Proposed로 추가하면서 Accepted ADR-WEB-001 요약·검증 방법 및 파생 표에는 16.3.8을 기록했다.
- 실제 결과: 같은 Accepted 문서의 요약·검증은 16.3.8, 선택지·결정·과거 검증은 16.3.4였다.
- 기대 결과: 승인된 계약, 검토 중 변경안, PR의 검증 형상을 구별하고 승인 전 기존 결정을 대체하지 않는다.
- 영향 범위: ADR·정책·작업 지침·계획의 버전 해석. 이번 리뷰 반영은 애플리케이션 코드·의존성·API·DB를 바꾸지 않는다.

## 4. 근본 원인

패키지와 잠금 파일에 반영해 CI가 통과한 사실을 승인 기준 갱신과 동일하게 취급했다. ADR-WEB-007의 Proposed 표기만 남기면 충분하다고 보아 기존 Accepted 요약·파생 문서에도 새 버전을 전파했다. 그러나 [ADR README](../07-adr/README.md)의 3절은 Proposed를 구현 기준에서 제외하고, 9절은 Accepted 결론의 덮어쓰기를 금지한다.

## 5. 확인 및 시도

| 확인하거나 시도한 방법 | 결과 | 판단과 다음 단계 |
|---|---|---|
| GitHub 미해결 스레드·승인·변경 요청 확인 | 인라인 1건, 일반 승인 1건, 변경 요청 1건 | 일반 승인을 프론트 소유자의 기준선 채택 합의로 확대 해석하지 않음 |
| 기존 트러블슈팅 검색 | #210은 결정 소유권, #257은 파생 기준선 정합성 문제 | 점검 방식만 재사용 |
| ADR-WEB-001·007과 파생 표 대조 | 승인 상태와 버전이 혼재 | 리뷰어의 첫 번째 대안 적용 |
| 모든 16.3.8 표기를 16.3.4로 되돌리는 대안 검토 | 검증 대상 의존성까지 되돌리면 기존 보안 감사 실패를 재도입 | 기각. 승인된 문서 기준만 복원하고 패치 검증 형상은 유지 |
| ADR-WEB-007 즉시 Accepted 전환 검토 | 소유자 합의 근거가 없음 | 기각. 병합 전 담당자 결정으로 남김 |

## 6. 최종 해결

- ADR-WEB-001의 2·13절을 기존 승인 기준으로 복원했다. 5·6·10.1절의 선택·결정·검증 이력은 수정하지 않았다.
- ADR 인덱스의 WEB-001과 추적표의 Accepted 행, 기술 정책 고정 표, AGENTS.md·CLAUDE.md·성능 ADR·MVP 계획의 승인 버전을 정합화했다.
- 추적표의 별도 Proposed 행, 기술 정책 3.1절, ADR-WEB-007 승인 절차에서 16.3.8을 PR 검증 변경안으로 명시했다.
- 패키지·잠금 파일은 변경하지 않았다. 기존 결정을 보존하는 것은 취약 버전으로 되돌리거나 배포하라는 뜻이 아니다.
- 이 기록을 [트러블슈팅 목록](README.md)에 등록했다.

## 9. 도입 전후 비교 지표

해당 없음 — 런타임 동작·성능을 바꾸지 않는 승인 상태 문서 정정이다. 배포 전후 성능 수치를 만들지 않는다. 효과는 동일 문서의 승인 버전 및 변경안 구분을 정적으로 대조한다.

## 10. 남은 사항

문서 불일치 수정과 별개로 ADR-WEB-007의 채택 결정은 남아 있다. CI 통과나 인라인 스레드 해결을 소유자 승인으로 보지 않으며, 승인 전 병합·배포하지 않는다. 실제 브라우저 인수·운영 적용은 수행하지 않았다.
