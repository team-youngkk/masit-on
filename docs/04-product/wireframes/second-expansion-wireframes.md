# 2차 확장 와이어프레임

## 1. 목적과 사용법

이 문서는 2차 확장 화면의 정보 구조, 주요 제어와 상태를 정의한다. 화면 ID는 제품 문서 간 참조용이며 URL, API, 컴포넌트 이름을 확정하지 않는다. 시각 언어와 반응형 기준은 [와이어프레임 적용 기준](README.md)을 따른다.

## 2. 공통 레이아웃

- 공개 헤더: 로고, 탐색, 인기, 큐레이션, 로그인 상태에 따른 개인 메뉴
- 회원 헤더: 컬렉션, 내 요청, 알림 진입점과 미읽음 배지
- 관리자 내비게이션: 데이터 관리, 큐레이션, 제보·신고 검토
- 콘텐츠 폭: 데스크톱은 기존 카드 그리드, 모바일은 단일 열과 하단 고정 주요 동작을 우선한다.
- 카드에는 확정된 맛집 정보만 표시하며 평점·리뷰·임의 대표 이미지를 추가하지 않는다.

## 3. 개인 컬렉션

### COL-LIST — 컬렉션 목록

```text
+------------------------------------------------------+
| 개인 컬렉션                              [새 컬렉션] |
| 나만 볼 수 있는 목록 · 12/20                         |
+------------------------------------------------------+
| 제주 여행 (8)        최근 수정 08.03       [⋯]      |
| 회식 후보 (0)        최근 수정 07.29       [⋯]      |
+------------------------------------------------------+
| 빈 상태: 목적에 맞는 첫 컬렉션을 만들어 보세요.     |
+------------------------------------------------------+
```

- `⋯`: 이름 변경, 삭제. 삭제 전 구성 관계가 함께 제거됨을 확인한다.
- 20개 도달 시 생성 버튼을 비활성화하고 상한을 설명한다.

### COL-CREATE / COL-RENAME — 입력 대화상자

- 제목, 이름 입력, 글자 수/검증 안내, 취소, 저장
- 서버 오류 시 대화상자를 닫지 않고 입력을 유지한다.

### COL-DETAIL — 컬렉션 상세

- 이름, 포함 개수 `n/100`, 이름 변경·삭제, 맛집 추가 진입
- 최근 추가순 맛집 목록과 각 항목의 제거 제어
- 숨겨진 맛집 수를 회원에게 공개할지는 개인정보가 아닌 제품 정책이므로 후속 UI 리뷰에서 확정한다. 숨겨진 항목의 상세 정보는 표시하지 않는다.

### COL-ADD — 맛집을 컬렉션에 추가

- 본인 컬렉션 목록, 현재 포함 상태, 각 컬렉션 개수, 저장
- 이미 포함된 항목은 선택 상태로 표시하고 중복 요청을 만들지 않는다.
- 비공개 전환 또는 상한 충돌 시 서버 최신 상태와 해결 방법을 표시한다.

## 4. 인기와 큐레이션

### POPULAR-LIST — 인기 맛집

```text
+------------------------------------------------------+
| 인기 맛집                                             |
| 현재 가장 많이 찜한 공개 맛집                         |
+------------------------------------------------------+
| 1  맛집 카드 · 찜 142                                |
| 2  맛집 카드 · 찜 131                                |
| ... 최대 20                                           |
+------------------------------------------------------+
```

- 기간 선택, 페이지 이동, 조회수·추천 점수는 노출하지 않는다.
- 찜 수를 표시할지는 개인정보 문제는 없으나 공개 응답 계약과 함께 확정한다. 정렬 기준 설명은 항상 제공한다.

### CUR-PUBLIC-LIST / CUR-PUBLIC-DETAIL — 공개 큐레이션

- 메인: 게시 큐레이션 최대 5개, 제목·설명 요약·구성 맛집 미리보기
- 상세: 제목, 설명, 관리자 순서의 공개 맛집 최대 20개
- 게시 종료 시 일반적인 찾을 수 없음 화면과 탐색 복귀 동작을 제공한다.

### CUR-ADMIN-LIST — 관리자 큐레이션 목록

- 상태 필터 `전체 / DRAFT / PUBLISHED`, 제목, 구성 수, 최근 수정, 공개 상태, 편집
- 비공개·삭제 구성 맛집이 있으면 경고 배지와 개수를 표시한다.

### CUR-ADMIN-EDIT — 관리자 편집

```text
+------------------------------------------------------+
| 큐레이션 편집                    [저장] [게시/비게시] |
+------------------------------------------------------+
| 제목 [............................................]   |
| 설명 [............................................]   |
| 구성 맛집 12/20                                      |
| [≡] 1. 맛집 A                              [제거]    |
| [≡] 2. 맛집 B  [비공개 경고]                [제거]    |
|                                      [맛집 추가]      |
+------------------------------------------------------+
```

- 드래그 외에도 키보드로 순서를 바꿀 수 있는 위/아래 제어를 제공한다.
- 게시·비게시와 게시 중 저장은 영향 확인 후 실행한다.

## 5. 제보와 신고

### REQ-TYPE / REQ-CREATE — 요청 유형과 등록

- 첫 단계에서 `제보: 새 정보 제안`과 `신고: 기존 정보 문제`를 설명과 함께 분리한다.
- 공통: 대상 유형, 설명, 선택적 근거 URL, 개인정보 입력 주의, 남은 일일 요청 수
- 제보: 신규 후보 정보 입력
- 신고: 기존 대상 선택과 오류·폐업·잘못된 영상·부적절 콘텐츠 유형
- 파일 첨부와 익명 제출 제어는 두지 않는다.

### REQ-MEMBER-LIST / REQ-MEMBER-DETAIL — 내 요청

- 제보/신고 탭, 상태 필터, 접수일, 제목/대상 요약, 현재 상태
- 상세 타임라인: 접수 → 검토 중 → 승인 → 처리 완료 또는 반려
- `ACCEPTED`에는 “승인됨, 실제 반영 대기”를 명시해 완료로 오인하지 않게 한다.
- `REJECTED`와 `COMPLETED`에는 관리자 사유·결과 요약을 표시한다.

### REQ-ADMIN-QUEUE / REQ-ADMIN-DETAIL — 관리자 검토

- 유형, 상태, 대상 유형, 접수일 필터와 오래된 순/최신 순 정렬
- 원문과 근거 URL은 안전하게 렌더링하고 외부 링크임을 표시한다.
- 현재 허용되는 다음 상태만 주요 버튼으로 제공한다.
- `ACCEPTED → COMPLETED`에는 실제 데이터 조치 확인 체크와 결과 요약을 요구한다.
- 신고 상세의 수동 숨김은 기존 공개 상태 관리로 이동하며 자동 실행하지 않는다.

## 6. 사용자 알림

### NOTI-ENTRY — 헤더 진입점

- 미읽음 0은 배지를 숨기고, 1~99는 정확한 수, 100 이상은 `99+`로 표시한다.
- 알림 아이콘만으로 의미를 전달하지 않고 접근성 이름을 제공한다.

### NOTI-LIST — 알림 목록

```text
+------------------------------------------------------+
| 알림                                      [모두 읽음] |
+------------------------------------------------------+
| ● 신고 검토를 시작했습니다.                 방금 전   |
|   요청 요약 · 검토 중                                |
| ○ 제보가 반려되었습니다.                    2일 전    |
|   반려 사유 요약                                      |
+------------------------------------------------------+
| 외부 알림 설정 없음 · 서비스 처리 결과 알림          |
+------------------------------------------------------+
```

- 미읽음은 색상뿐 아니라 기호와 텍스트 의미로 구분한다.
- 선택 시 읽음 처리 후 요청 상세로 이동한다.
- 전체 읽음 실패는 일부 성공처럼 보이지 않게 원래 상태를 다시 조회한다.
- 빈 상태에서는 제보·신고 처리 상태가 바뀌면 이곳에서 알린다는 설명을 제공한다.

## 7. 반응형·접근성 기준

- 360px, 390px, 768px, 1280px, 1440px에서 핵심 동작이 가려지지 않는다.
- 상태는 색상만으로 구분하지 않고 텍스트를 함께 사용한다.
- 드래그 정렬에는 키보드 대체 동작과 순서 변경 결과 안내가 있다.
- 확인 대화상자는 초점 이동·복귀와 Escape 취소를 지원한다.
- 입력 오류는 필드 근처 설명과 상단 요약을 함께 제공한다.

## 8. 화면 검수 체크리스트

- [ ] 개인 컬렉션에 공개·공유·메모·태그·수동 순서 제어가 없다.
- [ ] 인기 화면에 기간·조회수·추천 알고리즘 표현이 없다.
- [ ] 큐레이션 공개 흐름과 관리자 편집 권한이 분리된다.
- [ ] 제보와 신고가 첫 단계부터 구분되고 승인과 처리 완료가 다르게 보인다.
- [ ] 신고 접수 또는 승인만으로 자동 숨김되는 UI가 없다.
- [ ] 알림에 이메일·푸시·수신 해지·실시간 연결 설정이 없다.
- [ ] 모든 화면에 로딩·빈 상태·오류·권한·인증 만료 상태가 있다.
