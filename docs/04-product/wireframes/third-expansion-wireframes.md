# 3차 확장 와이어프레임

## 1. 목적과 사용법

이 문서는 3차 확장 화면의 정보 구조, 주요 제어와 정상·빈 상태·오류·복구 상태를 정의한다. 화면 ID는 제품 문서 간 참조용이며 URL, API 경로, 컴포넌트 이름을 확정하지 않는다. 시각 언어와 반응형 기준은 [와이어프레임 적용 기준](README.md)을 따른다.

AI 영상 추출은 일반 사용자 화면을 만들지 않고 관리자 작업 목록·상세·예외 보정 화면에 집중한다. 정상 결과는 자동 공개되며, 관리자는 신뢰도 숫자만으로 승인하지 않고 출처 근거·누락·외부 검증 상태를 확인해 오류 신고·롤백을 수행한다.

## 2. 공통 레이아웃과 상태 표현

- 공개 헤더: 기존 탐색 메뉴와 코스 후보 진입점. 챗봇·예약·결제 메뉴는 두지 않는다.
- 관리자 내비게이션: 기존 데이터 등록 아래 `AI 추출 작업`을 독립 메뉴로 둔다.
- 상태 Badge는 색상뿐 아니라 텍스트·아이콘을 함께 사용한다.
- 외부 장애는 제공자 이름·비밀정보·응답 본문 대신 사용자가 취할 행동을 표시한다.
- 작업·경로 요청 중 입력과 선택 목록을 유지하고 중복 제출을 막는다.

## 3. 자연어 맛집 탐색

### NLS-SEARCH — 자연어 입력과 결과

```text
+------------------------------------------------------------------+
| 맛잇온                                                [코스 0/5] |
+------------------------------------------------------------------+
| 어떤 맛집을 찾으세요?                                             |
| [ 성수에서 백종원이 방문한 한식집________________ ] [검색]       |
| 예: 마포의 중식집 / 쯔양이 방문한 강남 맛집                      |
+------------------------------------------------------------------+
| 직접 필터  지역 [성동구 v]  음식 [전체 v]  유튜버 [전체 v]      |
| 직접 태그(최대 5개)  [x] 냉면 [ ] 국밥 [ ] 매운맛 [ ] 혼밥 ...  |
+------------------------------------------------------------------+
| 적용 조건  [성동구] [한식] [백종원] [냉면] [혼밥]                 |
| 직접 필터 우선: 자연어의 '마포구'는 적용하지 않았습니다.          |
| 미지원 표현: '조용한 분위기'                                      |
+------------------------------------------------------------------+
| 결과 12개                                                         |
| [맛집 카드] [코스에 추가]  [맛집 카드] [코스에 추가]             |
+------------------------------------------------------------------+
```

- 적용 조건, 제외된 충돌 조건과 미지원 표현을 서로 다른 줄·Badge로 표시한다.
- 기존 맛집 카드·정렬·페이지를 재사용한다.
- 직접 태그는 여러 개를 AND로 조합하므로 목록 API의 단일 `tag` 필터가 아니라 자연어 요청의 `filters.tags`로 보낸다. 그래서 구조화 필터 줄이 아니라 자연어 검색 영역이 태그 선택을 갖는다. 선택은 다음 문장 검색에 적용되고 문장에서 해석한 태그를 대체한다.
- 적용 조건은 표시 전용이다. 조건 Badge에는 개별 제거 제어를 붙이지 않고, 조건 변경은 문장 수정과 직접 필터·태그 선택으로 한다.
- 오류 안내는 오류 코드별 문구와 잘못된 조건 필드·사유를 함께 보여준다.
- 입력 원문 저장·최근 검색 UI를 제공하지 않는다.

## 4. AI 영상 추출 자동 등록·예외 보정

### AI-EXTRACT-LIST — 작업 목록

```text
+--------------------------------------------------------------------------------+
| AI 추출 작업                                                    [새 추출 요청] |
+--------------------------------------------------------------------------------+
| 상태 [전체 v]  자동 등록 [전체 v]  영상 URL/작업 ID [____________] [조회]     |
+--------------------------------------------------------------------------------+
| 작업 ID | 영상 | 유입 경로 | 실행 상태 | 결과 완전성 | 자동 등록 상태 | 버전 | 생성/종료 |
| A-1042  | ...   | WEBHOOK   | SUCCEEDED | PARTIAL     | AUTO_BLOCKED | M3/P7/S2 | 10:31/10:33 |
| A-1041  | ...   | ADMIN     | FAILED    | -           | -         | M3/P7/S2 | 10:20/10:21 |
+--------------------------------------------------------------------------------+
```

- 실행 상태와 자동 등록 상태를 별도 열로 둔다.
- `PARTIAL`은 `SUCCEEDED`의 결과 완전성이고 별도 실행 실패 상태가 아니다.
- 대기·실행 시간이 긴 작업, 재시도 상한과 quota 차단을 행 단위로 구분한다.

### AI-EXTRACT-CREATE — 신규 영상 추가·추출 요청

```text
+------------------------------------------------------------------+
| 새 AI 추출 작업·영상 추가                                         |
+------------------------------------------------------------------+
| YouTube URL * [_______________________________________________]   |
| 보완 텍스트(선택)                                                  |
| 자막·전사·메모를 보완 입력할 수 있습니다.                         |
| [______________________________________________________________] |
| 12,480 / 최대 글자 수                                             |
+------------------------------------------------------------------+
| 원본 영상·전체 자막은 저장하지 않습니다.                          |
| 외부 AI 전송 범위와 보존 정책: [확인]                             |
+------------------------------------------------------------------+
| [취소]                                      [신규 영상 추가·추출 요청] |
+------------------------------------------------------------------+
```

- 입력 오류는 필드 바로 아래에 표시하고 대화상자·화면을 닫지 않는다.
- 중복이면 새 작업 생성 대신 기존 작업 ID·상태와 “기존 작업 보기”를 표시한다.
- 비용·quota 차단 중에는 요청 버튼을 비활성화하고 기존 수동 등록을 연결한다.
- Webhook으로 이미 접수된 영상이면 기존 작업 ID·상태·유입 경로를 표시하고 새 작업을 만들지 않는다.


실패 상태는 오류 범주, 마지막 실패 시각, 시도 횟수와 다음 행동만 표시한다.


### AI-EXTRACT-DETAIL — 자동 등록 결과

```text
+--------------------------------------------------------------------------------+
| 작업 A-1040  SUCCEEDED · COMPLETE     자동 등록 AUTO_CONFIRMED                |
| 영상 [YouTube에서 확인]  모델 gemini-3.5-flash-lite / Prompt P7 / Schema S1 |
+--------------------------------------------------------------------------------+
| 필드       | AI 후보                 | 신뢰도 | 출처 구간          | 판정       |
| 맛집명 *   | 을지로 골목식당          | 높음   | 02:14 문장 보기     | 자동 확정   |
| 주소 *     | 서울 중구 ...            | 중간   | 02:21 문장 보기     | 자동 확정   |
| 메뉴       | 제육볶음, 된장찌개        | 중간   | 03:05 문장 보기     | 자동 통과   |
| 방문 근거* | 방문함                    | 높음   | 01:58~03:40 보기    | 자동 통과   |
| 태그       | MENU_NAENGMYEON          | 높음   | 03:05 문장 보기     | 자동 등록   |
+--------------------------------------------------------------------------------+
| 채택한 장소: 을지로 골목식당 (상호명·시구 일치 1건)                            |
| 선정한 카테고리: 한식 (근거 Kakao 분류)                                        |
| 등록 결과: 맛집 R-2201 · 유튜버 C-118(재사용) · 영상 V-905(재사용) · 방문 T-77 |
+--------------------------------------------------------------------------------+
| 관리자 메모 [______________________________________________________________] |
| [감사 이력]       [오류 신고·롤백]       [자동 등록 결과 확인]                |
+--------------------------------------------------------------------------------+
```

- 자동 등록 결과 화면은 사전 승인용이 아니다. 필수값·근거·외부 검증이 모두 통과한 경우에만 `AUTO_CONFIRMED`가 된다.
- 한 영상에 맛집이 여러 곳이면 등록 단위별로 결과 블록을 반복해 표시하고, 단위마다 상태·차단 사유·채택한 Kakao 장소·선정한 카테고리와 그 근거 순위를 함께 보여준다.
- 화면에는 후보 선택 버튼과 카테고리 선택 입력을 두지 않는다. 장소와 카테고리는 시스템이 판정하며 관리자는 결과 확인과 사후 보정만 한다.
- 정상 결과 목업에는 `Kakao 확인` 같은 관리자 검증 동작과 유사 장소 후보 비교를 두지 않는다. 시스템이 채택한 장소·카테고리와 그 근거, 등록 결과만 표시한다. 장소 후보 비교는 `PLACE_NOT_FOUND`·`PLACE_AMBIGUOUS` 예외 화면에서만 제공한다.
- 아직 등록되지 않은 등록 단위에는 실행 동작을 **하나만** 둔다. 누르면 맛집·유튜버·영상·방문 관계 4종이 한 번에 등록되고 결과만 표시한다. 주소 힌트 선택, Kakao 장소 검색, Kakao 장소 URL 직접 입력, 카테고리 선택, 단계별 진행 표시를 정상 경로 화면에 두지 않는다.
- 실행 중에는 진행 상태만 알리고, 완료되면 맛집·유튜버·영상·방문 관계 식별자와 재사용한 자원을 함께 표시한다.
- 후보 절삭이 일어난 작업은 등록 단위 목록 위에 경고 배너를 둔다. "후보 수 상한(300)을 넘어 일부 장소가 누락됐습니다"처럼 원인과 상한 값을 함께 적고, 등록 결과가 영상의 모든 맛집을 덮지 않는다는 점을 명시한다. 누락된 맛집 목록은 알 수 없으므로 추측해 표시하지 않는다.
- 보조 입력 화면은 `BR-AIEXTRACT-011`의 예외 사유에서만 연다. 이때도 예외가 요구하는 항목만 묻고 나머지는 그대로 자동 판정한다.
- 출처 구간은 필요한 최소 문맥만 관리자에게 표시한다.
- 신뢰도는 확정 버튼의 유일한 기준이 아니며 낮음·`UNKNOWN`도 텍스트로 표시한다.

### AI-EXTRACT-EXCEPTION — 부분 추출·자동 차단

```text
+--------------------------------------------------------------------------------+
| 작업 A-1042  SUCCEEDED · PARTIAL      자동 등록 AUTO_BLOCKED                  |
| ! 4개 필드 중 2개를 추출하지 못했습니다.                                      |
+--------------------------------------------------------------------------------+
| 맛집명 *   | 을지로 골목식당 | 중간 | 근거 보기 | 검증 전                    |
| 주소 *     | UNKNOWN          | -    | 위치 표현 없음 | 보완 필요              |
| 메뉴       | 제육볶음          | 낮음 | 근거 보기 | 선택 사항                 |
| 방문 근거* | UNKNOWN          | -    | 직접 방문 근거 없음 | 보완 필요            |
+--------------------------------------------------------------------------------+
| 확정 불가: 주소와 방문 근거를 확인해야 합니다.                                 |
| [폐기] [허용된 값 보완] [새 버전으로 재처리] [사후 보정] [수동 등록]          |
+--------------------------------------------------------------------------------+
```

- 누락과 낮은 신뢰도를 같은 상태로 합치지 않는다.
- 차단 사유는 코드로 구분해 표시한다. 장소를 찾지 못하면 `PLACE_NOT_FOUND`, 조건을 만족하는 장소가 여러 건이면 `PLACE_AMBIGUOUS`, 카테고리 근거를 찾지 못하면 `CATEGORY_UNRESOLVED`, 같은 맛집·방문 관계가 이미 있으면 `DUPLICATE_CONFLICT`다.
- `DUPLICATE_CONFLICT`는 종결이 아니라 보류다. 새 작업을 안내하지 않고 이미 등록된 맛집·방문 관계로 이동할 수 있는 경로를 제공한다.
- 보조 입력을 요구하는 예외는 장소·카테고리 두 가지뿐이다. 나머지 예외 화면에는 입력란을 두지 않고 재추출·수동 등록·기존 등록 확인 중 해당하는 경로만 안내한다.
- 같은 작업에서 이미 자동 등록된 등록 단위가 있으면 그 결과를 함께 표시해 전체 작업이 실패한 것으로 오인되지 않게 한다.
- 보완값도 Kakao·YouTube·Visit 검증을 거쳐야 한다.
- 부분 추출은 작업 실패로 오인되지 않도록 실행 성공과 완전성을 함께 표시한다.

### AI-EXTRACT-VERIFY-CONFLICT — 외부 검증 충돌

```text
+------------------------------------------------------------------+
| 정식 등록을 완료하지 못했습니다.                                  |
| Kakao 장소 후보 2건이 일치하거나 YouTube 채널이 기존 후보와 다릅니다.|
| 정식 데이터 저장: 0건                                             |
| [후보 비교] [예외 보정 화면으로] [비공개·롤백]                    |
+------------------------------------------------------------------+
```

- 충돌 화면에서 후보·기존 데이터 차이를 비교할 수 있어야 한다. 장소 후보 비교와 Kakao 장소 확인은 정상 결과 화면이 아니라 이 예외 화면에서만 제공한다.
- `PLACE_NOT_FOUND`·`PLACE_AMBIGUOUS`는 Kakao 장소 URL, `CATEGORY_UNRESOLVED`는 카테고리 하나만 요구한다. 예외가 요구하지 않은 입력은 화면에 두지 않는다.
- 자동 검증 충돌은 `AUTO_BLOCKED`로 유지하며 `AUTO_CONFIRMED` 또는 공개 상태로 표시하지 않는다.

```text
| 3        잠실 식당 C       좌표 확인        [위로] [아래로] [삭제]|
+------------------------------------------------------------------+
| 첫 맛집을 출발점으로 자동차 이동 순서를 제안합니다.               |
| 현재 위치·영업시간·실시간 교통은 사용하지 않습니다.               |
| [맛집 더 찾기]                                      [코스 계산] |
+------------------------------------------------------------------+
```

- 1개 이하는 계산 버튼을 비활성화하고 최소 2개를 안내한다.
- 5개에서는 추가를 막고 제거 방법을 표시한다.
- 좌표 없는 항목은 문제 Badge와 교체 제어를 표시하고 전체 계산을 막는다.

### COURSE-RESULT — 정상 경로

```text
+------------------------------------------------------------------+
| 추천 이동 순서                 생성 [시각] · 만료 [정책 확정값] |
+------------------------------------------------------------------+
| 1 성수 식당 A                                                    |
|   └ 자동차 4.2km · 약 13분                                       |
| 2 건대 식당 B                                                    |
|   └ 자동차 8.5km · 약 24분                                       |
| 3 잠실 식당 C                                                    |
+------------------------------------------------------------------+
| 전체 12.7km · 약 37분                                            |
| [선택 수정] [새 경로 조회]                                      |
+------------------------------------------------------------------+
```

- 거리·시간은 외부 경로 결과임을 밝히고 도착 보장으로 표현하지 않는다.
- 만료 뒤에는 거리·시간을 흐리게 최신처럼 유지하지 않고 `새 경로 조회`를 우선한다.

### COURSE-INVALID / COURSE-FAILURE

```text
+------------------------------------------------------------------+
| 경로를 만들 수 없습니다.                                         |
| [좌표 없음] 잠실 식당 C — 다른 맛집으로 교체해 주세요.            |
| [30km 초과] 선택한 경로는 초기 범위를 초과합니다.                 |
| [외부 장애] 거리·시간을 추정해 표시하지 않았습니다.               |
| [부분 실패] 일부 구간만 계산되어 전체 결과를 제공하지 않습니다.   |
| [선택 수정] [허용 시 다시 시도] [기존 맛집 탐색]                 |
+------------------------------------------------------------------+
```

## 6. 반응형·접근성 기준

- 360px·390px에서는 자연어 입력, 적용 조건, 결과 목록 순으로 세로 배치한다.
- 관리자 예외 보정 표는 모바일에서 필드별 카드로 전환하되 후보·근거·검증 상태를 같은 카드 안에 유지한다.
- AI 상태·신뢰도·누락·충돌은 색상만으로 구분하지 않는다.
- 긴 URL·근거 텍스트·오류 메시지는 레이아웃을 넘지 않고 전문 복사·확장은 관리자 권한에서만 제공한다.
- 코스 순서는 번호와 텍스트로 표시하고 키보드·터치로 순서 변경이 가능해야 한다.
- 비활성 확정·계산 버튼에는 비활성 이유를 인접 설명으로 제공한다.

## 7. 화면 검수 체크리스트

- [ ] 자연어 적용 조건·직접 필터 충돌·미지원 표현이 구분된다.
- [ ] 해석 실패에서 전체 목록을 대신 표시하지 않는다.
- [ ] AI 실행 상태·결과 완전성·자동 등록 상태가 서로 다른 필드로 보인다.
- [ ] AI 정상·부분·실패·검증 충돌·확정·폐기 화면에 다음 행동이 있다.
- [ ] 부분 추출 필수값 누락 시 확정이 차단되고 이유가 보인다.
- [ ] 입력 원문·AI 응답 본문·외부 비밀정보가 오류 화면에 노출되지 않는다.
- [ ] 코스 2~5개·첫 출발점·좌표·30km·만료가 표시된다.
- [ ] 외부·부분 경로 실패에서 추정 거리·시간을 표시하지 않는다.
- [ ] 360px, 390px, 768px, 1280px와 1440px에서 핵심 검수·탐색 흐름을 사용할 수 있다.
