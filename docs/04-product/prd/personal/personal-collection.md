# 개인 컬렉션 PRD

## 1. 문서 정보

- 상태: 초안. WS-09 박진영이 소유하고 김인안이 기본 리뷰한다.
- 목적: 회원이 공개 맛집을 목적별 비공개 목록으로 묶어 다시 찾는 비용을 줄인다.
- 선행 조건: 1차 확장의 회원 인증과 맛집 공개 상태 계약이 구현되어야 한다.

## 2. 사용자와 문제

로그인 회원은 찜 목록 하나만으로는 방문 목적이나 상황별 맛집을 구분하기 어렵다. 회원은 자신의 컬렉션을 만들고 공개 맛집을 여러 컬렉션에 중복해 담을 수 있어야 하며, 다른 회원에게 내용이 노출되어서는 안 된다.

## 3. 목표와 성공 기준

- 회원이 컬렉션 생성·이름 변경·삭제·목록 및 상세 조회를 완료한다.
- 맛집 상세 또는 컬렉션 상세에서 맛집을 추가·제거하고 결과를 즉시 확인한다.
- 소유권, 개수 상한과 맛집 공개 상태가 모든 진입점에서 동일하게 적용된다.
- 성공 지표 후보: 컬렉션 생성 완료율, 추가 성공률, 소유권 위반 0건. 수치 목표는 운영 계측 계약에서 정한다.

## 4. 범위

### 포함

- 회원당 최대 20개인 비공개 개인 컬렉션
- 이름 기반 생성·변경·삭제와 목록·상세 조회
- 컬렉션당 공개 맛집 최대 100개 추가·제거
- 한 맛집의 여러 컬렉션 포함
- 컬렉션 목록 최근 수정순, 컬렉션 내부 최근 추가순

### 제외

- 공개·공유, 공동 편집
- 수동 순서 변경, 메모, 태그, 대표 이미지
- 관리자 큐레이션과 데이터 모델 또는 관리 화면 공유를 전제로 하는 설계

## 5. 핵심 사용자 흐름

1. 회원이 개인 컬렉션 목록에 진입한다.
2. 이름을 입력해 컬렉션을 만들고 최근 수정순 목록에서 확인한다.
3. 공개 맛집을 선택해 하나 이상의 자신의 컬렉션에 추가한다.
4. 컬렉션 상세에서 최근 추가순으로 맛집을 보고 제거한다.
5. 컬렉션 이름 변경 또는 삭제 전에 영향을 확인하고 확정한다.

세부 정상·실패 흐름은 [2차 확장 사용자 흐름](../../user-flows/second-expansion-user-flows.md)을 따른다.

| PR-COLLECTION-002 | 회원은 자신의 컬렉션 목록과 컬렉션별 맛집 구성을 조회한다. | FR-COLLECTION-004 |

## 7. 정책과 예외

- 같은 컬렉션에 같은 맛집을 두 번 저장할 수 없다. 다른 컬렉션에는 저장할 수 있다.
- 비공개·삭제된 맛집은 새로 추가할 수 없다. 기존 구성에서는 자동으로 노출하지 않는다.
- 컬렉션 삭제는 구성 관계를 함께 제거하지만 맛집 원본에는 영향을 주지 않는다.
- 회원 탈퇴 시 컬렉션과 구성 관계는 회원 생명주기 정책에 따라 삭제한다.
- 이름의 길이·공백·중복 정책은 API 및 데이터 계약에서 확정하되 UI와 서버가 동일한 규칙을 사용한다.

## 8. 화면과 상태

- 컬렉션 목록: 로딩, 정상, 빈 상태, 20개 상한, 오류
- 컬렉션 생성·이름 변경: 입력 전, 검증 오류, 저장 중, 성공, 충돌
- 컬렉션 상세: 정상, 빈 상태, 비공개·삭제 맛집 제외 후 빈 상태, 권한 오류
- 맛집 추가 선택: 선택 가능, 이미 포함, 100개 상한, 맛집 비공개 전환, 저장 실패
- 삭제 확인: 영향 설명, 취소, 확정, 처리 실패

## 9. 개인정보와 운영 영향

- 컬렉션과 구성은 회원 식별자에 연결된 개인 행동 데이터이며 공개 API에 포함하지 않는다.
- 회원 탈퇴 및 보존 정책 검증이 필요하다. 운영자의 일상 편집 업무는 없다.
- 외부 연동은 없고 저장소·인증 범위의 개발 및 테스트 비용이 발생한다.

## 10. 완료 조건

- [ ] 회원당 20개, 컬렉션당 100개, 동일 컬렉션 중복 제한이 동시 요청에서도 지켜진다.
- [ ] 비공개·삭제 맛집과 회원 탈퇴 처리 결과가 정책과 일치한다.
- [ ] 모바일·데스크톱의 빈 상태, 오류와 확인 흐름이 검수된다.
- [ ] WS-09 박진영 구현과 김인안 기본 리뷰가 완료된다.
- [ ] 일정과 API·데이터 계약이 승인된다.
