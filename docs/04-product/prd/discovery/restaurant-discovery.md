# 맛집 탐색 PRD

## 1. 문서 정보

공개 맛집의 최종 목록·검색·필터·정렬·페이지 흐름을 정의한다. 주 Workstream은 WS-01이며 유튜버 조건의 관계 판정은 [유튜버 기반 탐색 PRD](creator-discovery.md)에 의존한다.

## 2. 기능 개요

사용자는 맛집 목록을 열고 이름, 서울특별시 자치구, 대표 음식 카테고리와 유튜버 조건을 단독 또는 조합해 원하는 공개 맛집을 찾는다.

## 3. 문제 및 사용자 요구

사용자는 흩어진 맛집 후보를 직접 정리하지 않고도 익숙한 이름이나 방문하려는 지역·음식 종류를 기준으로 비교하고 싶다. 특정 유튜버 조건도 같은 탐색 결과 안에서 함께 적용할 수 있어야 한다.

## 4. 목표

- 사용자가 공개 맛집을 안정된 순서와 페이지로 탐색한다.
- 이름·지역·카테고리·유튜버 조건을 조합해 결과를 좁힌다.
- 조건에 맞는 항목이 없어도 다음 행동을 이해할 수 있는 정상 빈 결과를 받는다.

## 5. 비목표

자연어·초성·유사어·오타 교정 검색, 자동 완성, 복수 값 필터, 지도·거리 탐색, 인기·개인화 정렬, 무한 스크롤과 유튜버 상세는 이 기능의 목표가 아니다.

## 6. 대상 사용자

- 로그인하지 않은 일반 사용자

## 7. 전제 조건

- 맛집은 서울특별시 자치구와 대표 음식 카테고리 1개를 가진다.
- 공개 맛집과 공개·유효 방문 관계만 사용자 결과에 포함된다.
- 유튜버 조건은 WS-03이 제공하는 유효 맛집 판정 결과를 사용한다.

## 8. 핵심 사용자 흐름

### 기본 목록 탐색

- 시작 조건: 사용자가 맛집 탐색 화면에 접근한다.
- 사용자 행동: 별도 조건 없이 목록을 요청하고 페이지를 이동한다.
- 시스템 동작: 공개 맛집을 이름, 전체 도로명주소 오름차순으로 정렬해 기본 20개 단위로 제공한다.
- 성공 결과: 사용자는 맛집 요약과 방문 채널 표시 정보를 확인한다.
- 빈 결과 또는 실패 처리: 결과나 요청 페이지가 비면 빈 목록을 제공하고 잘못된 페이지 값은 잘못된 요청으로 처리한다.

### 검색·필터 조합

- 시작 조건: 기본 목록 또는 기존 탐색 결과가 표시돼 있다.
- 사용자 행동: 검색어와 지역·음식 카테고리·유튜버 조건 중 하나 이상을 지정한다.
- 시스템 동작: 검색어를 정규화하고 모든 지정 조건을 AND로 적용한 뒤 고유 맛집을 정렬·페이지 처리한다. 조건 변경 시 첫 페이지부터 제공한다.
- 성공 결과: 모든 조건을 만족하는 공개 맛집만 확인한다.
- 빈 결과 또는 실패 처리: 일치 항목이 없으면 빈 결과를 제공한다. 공백 검색어는 이름 조건을 적용하지 않으며 허용되지 않은 값은 잘못된 요청으로 처리한다.

## 9. 기능 범위

### 포함 범위

- 공개 맛집 목록과 목록용 방문 YouTube 채널명
- 맛집 이름 부분 일치, 앞뒤 공백 제거와 영문 대소문자 무시
- 서울 자치구 1개, 대표 음식 카테고리 1개 필터
- WS-03 결과를 이용한 유튜버 1명 조건과 모든 조건의 AND 조합
- 10·20·50개 페이지 크기, 기본 20개, 안정된 기본 정렬과 빈 결과

### 제외 범위

- 복수 값 필터, 지도·추천·개인화·통합 검색과 유튜버 상세
- Visit 관계의 내부 유효성 재판정

### 후속 확장

- 자연어 검색, 지도 기반 탐색, 개인화·추천 기능은 범위 변경 후 검토한다.

## 11. 비즈니스 규칙

- 검색 대상·공백·필터·AND 조합·고유성·빈 결과·페이지·정렬은 `BR-SEARCH-001`~`006`, `008`, `009`를 따른다.
- 유튜버 조건의 방문 근거는 `BR-SEARCH-007`과 [유튜버 기반 탐색 PRD](creator-discovery.md)가 소유한다.
- 영상 연결이 없는 맛집 포함과 공개 범위는 `BR-RESTAURANT-002`, `008`, `BR-PUBLICATION-001`, `003`~`006`을 따른다.

## 12. 예외 및 경계 상황

| 상황 | 기대 결과 |
|---|---|
| 결과 없음 또는 범위 밖 페이지 | 오류가 아닌 빈 목록을 제공한다. |
| 앞뒤 공백 또는 공백뿐인 검색어 | 공백을 제거하며 비면 이름 조건을 적용하지 않는다. |
| 서울 자치구·카테고리·페이지 값이 유효하지 않음 | 잘못된 요청으로 처리한다. |
| 동일 맛집에 여러 유효 관계가 있음 | 맛집은 한 번만 표시한다. |
| 비공개·삭제 맛집 또는 무효 관계 | 결과에서 제외한다. |
| 영상 연결이 없는 공개 맛집 | 기본 목록에 포함한다. |

## 13. 품질 요구사항

일반 조회와 조건 조합 성능, 페이지 제한은 `NFR-PERFORMANCE-001`, `002`, `004`를 따른다. 입력·오류 보호, 공통 오류, 문자·응답 크기와 자동화 검증은 메타데이터의 관련 NFR을 적용한다. 목표 성능 수치는 팀 결정 전까지 확정값으로 간주하지 않는다.

## 14. 의존성

- 선행 정책: 공개 상태와 페이지·오류 계약
- 데이터 의존성: WS-04가 등록한 공개 맛집과 관계
- 다른 기능 PRD: 유튜버 조건 판정을 제공하는 PRD-DISCOVERY-002
- 다른 Workstream: WS-03 관계 판정, WS-04 등록 데이터
- 공통 API 계약: 식별자, 응답·오류와 페이지네이션 계약

WS-03 구현 전에는 계약 Stub으로 나머지 탐색 범위를 독립 검증할 수 있으며 순환 선행 의존을 만들지 않는다.

## 15. Workstream 및 책임자

- 주 Workstream: WS-01 맛집 탐색
- 최종 책임자: 양성훈
- 기본 리뷰어: 이우람
- 협업: 박진영(목록·상세 식별자), 김인안(등록 데이터 반영)

## 16. 성공 기준

- 사용자가 각 조건을 단독·조합해 예상한 공개 맛집을 중복 없이 찾는다.
- 조건 변경과 페이지 이동에도 결과 누락·중복 없이 안정된 순서를 유지한다.
- 빈 결과와 영상 없는 맛집에서도 탐색 흐름이 정상 유지된다.

## 17. 완료 기준

- 7개 관련 요구사항과 비즈니스 규칙이 검토되고 구현·자동화 테스트가 완료된다.
- WS-03 관계 판정과 WS-04 등록 결과가 실제 탐색에 통합된다.
- API 계약, 오류·페이지 계약, 문서와 추적성이 실제 동작과 일치한다.
- PC·모바일 핵심 탐색 인수 흐름이 통과한다.

## 18. 리스크

- 관계 조건 조합이 조회 비용과 중복 제거 복잡도를 높일 수 있다.
- 목록 채널 표시 인원과 축약 방식, 목표 성능 수치가 미확정이다.
- 유튜버 선택 데이터를 제공하는 방식이 확정되지 않았다.
